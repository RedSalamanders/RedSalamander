# Shared-transfer validation scenarios

This file records the fixture and limits of the local validation. The authoritative contracts are in `Specs/FileSystem/FileSystem_FileOperations.md`, `Specs/UI/UI_FileOperationsPopup.md`, `Specs/UI/UI_PreferencesDialog.md`, and `Specs/Core/Core_SettingsStore.md`.

Builds, tests and changes use that checkout. Raw evidence remains under the previously initialized and marked `Z:\RedSalamander.Perf` sandbox.

`FileOps_IdentityInterlockWaiting` covers:

- Shared permit limits 1, 2, 4 and 16; waiting for N+1; release; cancellation; live increases/decreases; exclusive fairness; and zero holders/waiters at teardown.
- Admission controls for distinct missing sibling names, identical names, differing parents/roots/path contracts, retained physical source aliases, existing destinations, unsupported/nonqualified scopes, and stale concurrent consent. Read/Read source sharing remains permitted.
- Indexed overlap checks for 64 and 4,096 selected files, compared with pairwise policy controls. The gate is at most 100 indexed probes per selected file. Namespace keys are scheduling facts, never publication or deletion authority.
- An unrelated native-only Move rename admitted while four data jobs occupy the root admission budget. Its provider options retain a metadata budget of eight under a data limit of four.
- Actual local I/O through canonical admission, `EnterOperation`, `ExecuteOperation`, typed result reduction, and owned MTA workers. The six scenarios are four one-file Copy jobs with limit one; the same four jobs with limit four; five one-file Copy jobs with the waiting fifth canceled; two four-file Copy jobs sharing four permits; and four one-file managed Moves in each of the two identity-injection modes below. Files contain 4 MiB plus the file index, with exact destination/source-content checks and no surviving permit owners.

The real-I/O sandbox is one physical local volume. The fixture explicitly selects Managed Move instead of a Native rename to exercise pump, publication and source cleanup without exposing another volume or a live NAS. The directory-only injection makes destination directory `BindObject` identity unsupported while retaining real file identity. The all-path injection makes destination `BindObject` identity unsupported, but does not remove the Local provider's valid operation-owned publication authority. Success and source removal are correct when that authority proves publication. No fictitious verification capability is injected. The separate `R3_3_PublicationFaultMatrix` checks actual proof failures and source-retention invariants.

The setting-one/setting-four Copy pair is a same-candidate scheduling control with identical four-file payloads. It includes deliberately held transactions to observe occupied slots. Its wall times are observations, not an old-source/new-source A/B or a throughput speedup. Eligible local new-file Copy now uses the host bridge so each file owns a shared permit; native offload, ReFS/block-clone behavior, physical NAS throughput and production Release performance are not established by this fixture. `FileOps_SmallFileCopyCost` separately checks ordinary recursive provider and bridge routes with exact post-timing output validation.

`R4A02_RunConcurrentSameDestinationStaysSafe` keeps its historical filter name, but checks the new serialization behavior: no concurrent Run action for overlapping transfers, the second task waits, both result sets survive, and a third task asks independently. `FileOps_ReviewRemediationContracts` retains generic consent-key/replacement coverage with an explicitly non-transfer Rename requester.

The Preferences journey uses real UIA and keyboard input. It checks a unique accessible combo, draft-only changes, dirty/Apply state, restoring the baseline, persisted Apply, the runtime limit, preservation of unrelated values, Cancel and reopening. Separate cases exercise forward/reverse tab traversal, returning to the DxUi page, settings round-trip and default pruning. Standalone schema tests cover range/type normalization and serialized values 1, 2, 4 and 16.

The Waiting gallery covers English/French, Copy/Move, 480/960 DIP at 144 DPI, and identity/capacity/exclusive waits: 24 scenarios and 12 measured redraws per scenario. It checks Waiting text/accessibility, no stale counters or counting controls, no Start now bypass, and clearing the reason when running resumes. Captures use harness-owned windows with synthetic Studio/Moonrise paths and hostnames, without desktop takeover. Only inspected capacity/exclusive images are promoted here. All 24 original captures and their scenario manifest remain in the exact raw run; identity-wait frames retain the pre-existing intermittent missing-path painting observation documented in the earlier archive. No path-painter fix is claimed.

The data cap is independent of bandwidth, Delete concurrency and metadata-only native rename budgets. Conflicting names, replacements, trees and ambiguous aliases keep serialized admission. Lowering the cap drains current holders; it does not cancel them.
