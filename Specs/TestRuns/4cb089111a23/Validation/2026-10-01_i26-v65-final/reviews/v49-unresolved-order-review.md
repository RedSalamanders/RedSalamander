## S3 entry disappears before remote inspection

**Established:** The passing delayed MTP picker case explicitly calls `FileSystemPluginManager::Refresh(g_settings)` and then requires `builtin/file-system-s3` to be present, loadable and not deferred before it returns (`RedSalamander/SelfTest/Commands/Commands.SelfTest.Connections.cpp:2579–2590`). The remote inspection fixture later obtains a null S3 entry before trying to enable or load it (`Commands.SelfTest.FileOps.cpp:14491` and following). A disabled setting alone cannot explain a null entry: `FindPluginById` searches the manager's `_plugins`, while `Refresh` calls `Discover`, which unloads and clears `_plugins` before rediscovery (`FileSystemPluginManager.cpp:466–470, 1059–1075, 1100–1104`). The optional DLL is enumerated from `<exe>/Plugins` (`:1050–1057, 1160–1176`); an optional candidate with `E_NOINTERFACE` or missing export is skipped without an entry (`:1288–1315`). Other discovery failures can leave an unloadable entry, so the observed null specifically needs a boundary or candidate-path explanation. No Commands case directly calls manager Shutdown/Discover/Clear; the only explicit Commands Refresh calls are the two in the MTP picker.

**Credible routes, not yet proven causes:** Preferences save can post `WndMsg::kPluginsChanged` (`Preferences.Dialog.cpp:2764–2791`), and a settings hot reload can also call `RefreshRunningPluginsFromSettings` (`RedSalamander.cpp:9391, 9502`). That runtime function releases pane plugins and calls manager `Refresh(g_settings)` while discarding its HRESULT (`:9206–9238`). Main-window per-case isolation pumps posted messages (`Commands.SelfTest.Settings.cpp:9118–9143, 9174–9188`), so a queued refresh could land between the MTP assertion and S3 inspection. Nothing in the current evidence shows that it did. A directory-iteration error, transient optional-binary visibility/export failure, or a different refresh trigger likewise remains unproven. Do not refresh at the failing fixture entrance; that would mask the shared-order state loss.

**Decisive next witness already in primary:** `Commands.SelfTest.cpp:617–672` records inventory changes before isolation, before each case and after each case, including count, S3 presence/loadability/disabled/deferred/path/error. The first change boundary can separate a case mutation from isolation-pumped work. If the boundary is a runtime Refresh, retain its HRESULT and candidate enumeration/optional-directory error around that specific event; do not infer this from a later null lookup.
