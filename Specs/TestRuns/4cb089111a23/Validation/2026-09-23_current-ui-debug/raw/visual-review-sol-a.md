# Debug file-operations visual review (read-only)

Reviewed Debug contact sheets `01.jpg`–`24.jpg` (96 captures) and opened original PNGs for the clipped speed-limit control, short confirmation before/after scrolling, and Issues scenes 125, 129, 131, and 132. The remaining sheets were not individually re-reviewed after the paired pixel comparison established unchanged UI bodies across all 424 Debug/Release captures.

`capture-comparison.json` reports 100 byte-identical pairs and 324 pairs differing only inside the titlebar application icon: 162 within `(13,10,37,34)` at 144 DPI and 162 within `(9,7,25,23)` at 96 DPI; no other pixel difference is reported. I independently recomputed the full RGBA difference bounds for representative empty, speed-limited, and Issues captures using `System.Drawing.Bitmap`; each matched the manifest. Thus the Debug UI body/geometry is pixel-identical to the reviewed Release capture for every paired scene, including the confirmation scroll and Issues facts.

The compact waiting cards reviewed in scenes 04, 05, 107, and 120–122 keep status, source/destination paths, and action rows visible without overlap at both widths and DPIs. Representative short confirmation originals retain pinned Copy/Cancel actions while the body scrolls; the scrolled variants expose the option rows. Representative Issues originals distinguish original problem, accepted decision, failure result, selected-row removal, and history eviction/reintroduction without visible role confusion. Long-path and Unicode scenes retain readable leaf names and extensions. Partial rows at the bottom of Issues/expanded lists are within scrollable viewports, rather than painted over the footer.

Existing visual issue, **not a Debug regression**: the per-task speed-limit button in `11-speed-limited__dark__480dip__fr-FR__display1__144dpi.png` and `display2__96dpi.png` visibly clips its label on both sides (`Limite` loses its initial letters and `MB/s` loses the final character). The paired Release originals have exactly the same pixels outside the app icon, so this is a pre-existing action-label readability defect. The known scene-107 destination flyout clipping is also not newly introduced by Debug; this review did not resolve it.

Limits: Contact sheets are analysis composites; all cited observations about controls were checked against original PNGs where necessary. Static captures and pixel equality do not replace live keyboard, pointer, UIA, or focus validation. No application input, build, repository edit, or test run was performed in this review.
