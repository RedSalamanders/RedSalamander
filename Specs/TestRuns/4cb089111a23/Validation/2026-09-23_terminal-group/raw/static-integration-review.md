# Terminal result body: integration review (read-only)

The strengthened witness in `inputs/` now requires a complete `ResultSummary` semantic region for single-task expanded terminal cards, including canceled and indeterminate outcomes. The current popup renders `resultSummary` only through `StatusTextForTask` in the one-line header (`Popup.cpp:1363-1369`, `1502-1514`, `7919`, `8133-8141`); canceled does not even take the summary branch. Keep `StatusTextForTask` unchanged because failure-surface text, status announcements, and other callers use it (`Popup.cpp:6304`, `6501`, `11080`). For a finished file-operation card with a nonempty summary, build a short visual header from the operation and a localized terminal status (`Done`, `Partial`, `Indeterminate`, `Failed`, `Canceled`), and make its status chip short as well: `StatusChipTextForTask` currently returns the full summary for `Done` (`Popup.cpp:1399-1421`). Leave the full summary in a separate body row. The semantic descriptor must carry exactly `task.resultSummary`, with automation ID `FileOperations.Task.<id>.ResultSummary` and the actual painted bounds. The existing descriptor-to-DxUi Label path (`Popup.cpp:6195-6204`, `6358+`) supplies the accessible name/help/tooltip and the body scroll parent.

Prepare each nonempty finished summary before card-height calculation in `Render` (`Popup.cpp:6661-6850`). Reuse the footer summary cache pattern (`Popup.cpp:4949-4995`): one bounded slot per current snapshot item, keyed by task ID, text, exact pixel width, and `_bodyFormat` identity; retain one `IDWriteTextLayout` plus successful metrics. The speed-width vector (`Popup.cpp:6677`, `Popup.h:1111-1118`) shows the per-snapshot slot lifetime, but its caption-only key is insufficient for row reorder or width changes. Resize slots to `snapshot.size()`, clear/retry failed measurements, and release entries when tasks disappear. Explicitly clear on DPI/format recreation (`Popup.cpp:11299-11320`) and teardown (`11216-11255`); device-target loss alone need not invalidate a DirectWrite layout if factory/format persist. Do not allocate the text layout inside the per-row paint path. `EnsureTextFormats` sets `_bodyFormat` to no-wrap (`Popup.cpp:3662-3755`), so the retained layout itself must call `SetWordWrapping(WRAP)` and use its `GetMetrics` result.

Insert measured summary height plus a small gap into the finished-card height target (`Popup.cpp:6750-6774`) before `ResolveAnimatedTaskHeight` (`6847-6853`). Paint the retained layout after terminal axis badges and before diagnostic/path rows (`Popup.cpp:8150-8230`), increment `textY` by the same reserved height, then append the descriptor with those exact bounds. The existing dismiss/progress placement uses `textY` and `cardRect.bottom` (`Popup.cpp:8305-8361`); reserve enough total height for summary **and** existing optional HRESULT, paths, and last-note rows so the `max(textY, card-bottom...)` action placement does not exceed the card. The current fixed terminal 178/202-DIP heights do not guarantee that. Expansion/content-height changes already snap to the new target in `ResolveAnimatedTaskHeight` (`3464-3480`), preventing a new summary from overlapping actions during card-height animation.

Measure against the effective card content width with scrollbar gutter reserved. Height is determined before `AutoResizeWindow` and the scrollbar two-pass layout (`Popup.cpp:6864-6950`), while drawing uses the resulting client width (`7100-7112`). If a scrollbar narrows the client after measurement, remeasure and recompute height in that frame, or reserve the gutter up front as conflict actions do (`6664-6670`); relying on a later paint risks a clipped transition. The outer list viewport and card clips (`7100-7120`) may still reveal only part of a long card until the user scrolls; that is acceptable if the native scroll range is derived from the full measured `_contentHeight`. Completed-group reveal multiplies terminal card heights by `completedGroupVisibility` (`6849-6853`) and intentionally clips intermediate animation frames, whereas the witness uses reduced motion. Do not expose a semantic region as fully visible while that intermediate clip hides its text. No native build or runtime validation was performed for this review.
