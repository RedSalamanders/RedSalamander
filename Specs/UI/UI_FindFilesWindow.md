# Find Files Window Specification

`FindFilesWindow` is the modeless DirectX Find Files and Directories surface. It owns the search form, result grid, result action commands, and the Find split-button action menu.

## Window Lifetime And Initial Scope

- `cmd/pane/find` opens a new independent modeless Find window each time it is invoked.
- The initial root comes from the focused pane when focus is inside a pane; otherwise it comes from the active pane.
- A non-empty pane root takes precedence over the persisted `search.lastRoot` setting when a new Find window is created.
- The `Look in:` row is an embedded shared `NavigationView` address bar, not a visible edit/combo field. It must expose the same breadcrumb/full-path editing, autosuggest, validation behavior, and history dropdown as the FolderView/Pane navigation bar, while syncing its path to the Find search root and recent-root history.
- The hidden root combo/history bridge, if present for compatibility, is non-visual plumbing only. It must not be visible or counted as a fallback control on the live Find UI path.

## Split-Button Menu

- The `Find Now` split-button primary action starts the normal find command.
- The drop-down side opens the action menu from a private posted window message, not synchronously from the button mouse-up/dropdown callback.
- The action menu uses `DxUi::ContextMenu::Show(...)` and therefore shares the common DxUI menu input contract:
  - moving the pointer over an enabled row highlights that row immediately
  - clicking an enabled row invokes immediately without a later activation or title-bar click
  - visible hover/pressed/menu-close feedback must not depend on moving the pointer over the title bar or another owner-window region
  - clicking outside the popup dismisses it immediately
  - `Up`, `Down`, `Home`, `End`, `Enter`, `Space`, `Escape`, mnemonics, and applicable submenu/navigation keys are live while the popup is open
  - hover, invocation, dismissal, and keyboard state are driven by delivered popup/menu messages, with only the shared bounded DxUI input resync allowed as an idle or owner-message-flood starvation fallback
- Command enablement must remain coherent across idle, running, and selected-result states. Disabled actions stay visible but cannot be selected or invoked.

## Live Diagnostics

- In builds compiled with `ENABLE_DXUI_MENU_DIAGNOSTICS`, or debug/test builds where `NDEBUG` is not defined, `REDSALAMANDER_DXUI_MENU_TRACE=1` records the Find split-button handoff alongside the shared DxUI menu trace. Retail builds compile this file tracer out.
- Find-specific events include the split-button drop-down callback, posted `kFindShowActionMenu` delivery, `ShowFindActionMenu(...)` entry/result, command dispatch, `BeginSearch(...)` start/block decisions, destination `NavigationView` creation, and destination history refreshes.
- Find delayed-input repro logs must also include `app.message-loop.find` queue/dequeue records, `find.wndproc.raw` owner-window message entries/after-Dx dispatch records, and `dxui.windowhost.raw` / `dxui.windowhost.pointer-*` records from the shared DxUi host. These records are diagnostic only and identify whether a pointer message reached the application queue, reached the Find owner window, was handled by the root DxUi host, hit the embedded destination `NavigationView` child, or never reached those layers. High-volume diagnostics may be enabled only under the shared support trace switch and must stay out of retail builds unless an explicit support diagnostics define is used.
- The embedded destination `NavigationView` also emits `navigation.*` menu diagnostics for mouse-down, resolved branch (`menu`, `history`, `disk`, `segment`, `siblings`, or ignored), dropdown entry/show/result, and skip decisions under the same trace switch. Destination repro logs must also include `navigation.wndproc.raw` boundary records for low-level child-window activation/pointer routing, input-state snapshots, edit-host mouse/focus messages, hover candidates/changes/renders, hover-timer start/tick/cursor state, cancel/capture/menu-loop transitions, and NavigationView paint/present decisions. These events are required when investigating delayed dropdown opening, missing hover feedback, or dropdown close/action delivery that waits for unrelated owner-window movement.
- Result/progress queue diagnostics include `find.ui.results-handler-enter`, `find.ui.results-handler-exit`, `find.ui.progress-handler-enter`, `find.ui.progress-handler-exit`, and `find.ui.*-drain-stop`. A `queue-head` drain stop means a nonmatching or child-window message is ahead of the next Find result/progress message and must be returned to the normal message pump before more search UI coalescing happens.
- Use `REDSALAMANDER_DXUI_MENU_TRACE_FILE=<absolute path>` when a stable repro log path is needed; otherwise the shared DxUI default `%TEMP%\RedSalamander-DxUiMenuTrace-<pid>.log` is used.

## Search Result Ingestion

- Find result and progress handlers may coalesce only messages that are already consecutive at the head of the current UI thread queue. Before removing an extra `kFindSearchResults` or `kFindSearchProgress` message, the handler must inspect the unfiltered thread-queue head; it must not use parent-HWND-filtered peeks that skip older child-window messages from the destination `NavigationView`, DxUi popup/input hosts, or other Find child windows.
- If a queued child input, popup input, paint, activation, or any nonmatching message is ahead of the next result/progress payload, the result/progress handler must stop draining and return to the message pump so hover, click, close, and keyboard feedback are not delayed until unrelated pointer movement.
- Result application and visible refresh costs must remain instrumented (`find.ui.results_handler_ms`, `find.ui.results_apply_records_us`, `find.ui.progress_handler_ms`, deferred-refresh metrics, and visible-work counters) so future responsiveness regressions can be diagnosed from archived selftest or support logs.

## Result Actions

- `Open` activates the selected result. Directory results navigate into the directory. Local file results open directly with the file's default/proper application and MUST NOT navigate the active pane to the containing folder.
- `Go to folder` on a directory result navigates to the parent folder and keeps the directory entry focused.
- `Go to folder` must not block the UI thread with redundant enumeration or message-pump starvation; the action path must stay responsive enough for the Find dialog to keep repainting and routing input.
- When the results grid has focus, keyboard actions MUST resolve through `settings.shortcuts` and `ShortcutManager` to stable `cmd/*` command IDs before any result action runs. The Find window MUST NOT hardcode private key chords for copy, cut, viewer/editor, delete, or permanent delete.
- When the results grid has focus and no search is running, `WM_COMMAND` dispatch for the corresponding pane command IDs must reach the same result-action handler before generic DxUI message handling can consume the message. This keeps menu/accelerator and selftest command dispatch equivalent to shortcut dispatch for copy, cut, view/edit, copy/move to other pane, delete, and permanent delete.
- `cmd/pane/clipboardCopy` copies the selected result paths as `CF_HDROP` plus Preferred DropEffect `DROPEFFECT_COPY`, and also publishes Unicode text matching the visible grid selection. The default chords include `Ctrl+C` and `Ctrl+Insert`.
- `cmd/pane/clipboardCut` copies the selected result paths as `CF_HDROP` plus Preferred DropEffect `DROPEFFECT_MOVE`; this marks a shell cut but does not move or delete anything immediately. Its Unicode text fallback is the selected full paths, one per line, so multi-subfolder cuts do not depend on visible grid text formatting. The default chord includes `Ctrl+X`.
- `cmd/pane/copyToOtherPane` and `cmd/pane/moveToOtherPane` operate on the selected result paths through the shared File Operations pipeline, using the result plugin/context/path identity to infer the source pane. Their destination defaults to the opposite pane, but the bottom destination navigation bar may override it. When accepted, the Find action-row status must name the resolved destination folder so F5/F6 are not ambiguous.
- Accepted `cmd/pane/moveToOtherPane`, `cmd/pane/delete`, `cmd/pane/moveToRecycleBin`, and `cmd/pane/permanentDelete` operations remove the affected rows from the current result set. Canceled permanent delete must keep the rows.
- `cmd/pane/view`, `cmd/pane/alternateView`, `cmd/pane/edit`, and `cmd/pane/alternateEdit` dispatch the selected file through the configured primary viewer, alternate viewer, primary editor, and alternate editor respectively. Directory results keep Enter/Open-style navigation behavior. File viewer/editor dispatch from Find must use the Find window as the action owner and must not route through a focus-stealing folder-view command post. After a configured action launch, Find MUST NOT schedule foreground/focus restoration or otherwise bring itself to the top; the launched viewer/editor must keep its natural foreground and Z-order, and Find may regain focus only through normal owner/OS focus return or explicit user action.
- `cmd/pane/delete` / `cmd/pane/moveToRecycleBin` and `cmd/pane/permanentDelete` operate on the selected result paths through the shared File Operations pipeline. Permanent delete MUST request the existing warning confirmation before removing items without the Recycle Bin.
- Right-clicking a result row opens a DxUI context menu that dispatches through the same result-action handlers as keyboard shortcuts, toolbar buttons, and `WM_COMMAND` command IDs. The menu must not implement a second action path.
- Result context-menu shortcut labels must be resolved from the effective `settings.shortcuts` via `ShortcutManager` and stable `cmd/*` command IDs. Menu text may use localized resource strings, but shortcut display must not be hard-coded from private Find key tables.
- When multiple result rows are selected and the right-clicked row is part of that selection, the result context menu has two visible sections: one for actions on the clicked item, and one for actions on the whole selection. The clicked-item section includes item-only actions such as `Open` and `Go to folder`; the selection section offers bulk-capable actions such as view/edit, clipboard copy/cut, copy/move to Destination, delete, and permanent delete.
- Right-clicking an unselected row makes that row the context target and shows the single-item menu.
- A compact `?` help button is right-aligned in the action row. It opens a window-scoped modal alert overlay that takes keyboard focus, prepares its close/button hit geometry synchronously before first paint, renders a fully visible first frame without waiting for mouse movement or another input nudge, applies a real dimming scrim over the captured owner image, preserves a dimmed view of the Find/main window instead of rendering the owner area black, refreshes that captured backdrop when the owner size or placement changes while the modal overlay is visible, and closes with `Escape` or a real pointer click on the close glyph without requiring title-bar movement or another activation change. The close glyph must also dismiss from the first delivered mouse-up over the glyph if window activation consumed or reordered the corresponding mouse-down.
- The `?` help text summarizes the result-list actions: Enter/Open, Go to folder, `Ctrl+C`, `Ctrl+X`, `F3`/`F4`, `F5`/`F6`, `Del`, and `Shift+Del`. It must include the current resolved destination folder, or an unavailable placeholder when no destination can be resolved.
- The action row lays out primary result actions from the left (`Find Now`, `Open`, `Go to folder`), then a right-aligned inline status section that paints only text over the row background, uses leading ellipsis when space is tight, and stays blank while idle instead of showing a `Ready` placeholder. The `?` help button is right-aligned. `Cancel` appears immediately to the left of `?` only while a running search can be canceled.
- The bottom row is a persistent destination editor: `Destination:` plus the shared `NavigationView` address bar. It must provide the same breadcrumb/full-path editing, autosuggest, validation behavior, and history dropdown as the FolderView/Pane navigation bar. This destination is the visible F5/F6 target and becomes the explicit destination when the user edits it.
- The destination `NavigationView` uses embedded destination presentation, not pane presentation: it paints into the Find window footer background, suppresses the active-pane bottom border/current-segment accent/rainbow underline, and must not look permanently focused when the results grid or another Find control has focus.
- The destination `NavigationView` child HWND owns its client hit-test and activation contract: it returns `HTCLIENT` for its client area and `MA_ACTIVATE` for mouse activation so Windows does not route footer clicks through transparent popup margins, the parent DirectX host, or another owner window before the breadcrumb/history/menu branch is known.
- Destination status/control-state refreshes must not repeatedly reapply the same destination path or history while results are changing. If the resolved destination text/path/history is unchanged, the Find window and embedded NavigationView leave the existing model and paint state alone; hover feedback must keep following delivered pointer messages and must not unlock/relock only because an unrelated status refresh repainted the footer.
- The embedded destination `NavigationView` follows the shared NavigationView pointer contract: delivered `WM_MOUSEMOVE`, `WM_LBUTTONDOWN`, `WM_LBUTTONDBLCLK`, and related client points drive hover and activation from the delivered message point. Production routing MUST NOT call `GetCursorPos()` or substitute the later live cursor for stale classification, hover, click activation, popup opening, popup dismissal, or repaint state. Stale activation residue must be rejected from delivered-message metadata such as target HWND, message time/order, capture/menu ownership, destination NavigationView input generation, and explicit edit-host/layout teardown tokens. Paint and cursor handling must not mutate hover state.
- The destination `NavigationView` seeds its history from the shared `FolderWindow` folder history with the current destination first. A pointer click on its history arrow must hit-test to the `RedSalamander.NavigationView` child and open a non-empty DxUI history menu immediately, without waiting for pointer movement outside the Find window or title-bar movement. A pointer click on a breadcrumb separator must dispatch the sibling menu directly after hit testing, not rely on a later posted message that can be starved until another mouse message arrives.
- The embedded destination bar must remain usable if a stale `RedSalamander.NavigationView.DxHost` edit child is visible above it. Inactive destination edit hosts hide during layout; if one still receives real pointer hit-testing, it must retire/forward so history, menu, disk, and breadcrumb clicks are processed by the embedded `NavigationView` immediately.
- Destination `NavigationView` dropdowns, including breadcrumb sibling menus, must use embedded dropdown placement: root popup visible surfaces anchor to the footer control's top edge, open upward from the footer, cap their visible height to a scrollable compact surface, and must not create a monitor-height capture window that makes outside clicks or hover feedback appear delayed. The first opened menu state must expose a rendered initial frame, and transparent popup shadow margins must not own hit testing over the footer.

## Results Grid

- The Name column shows a shell file/folder icon for every visible result. Local results resolve system image-list icon indices through `IconCache` and render bitmap icons in the shared grid, with text glyphs only as a fallback.
- The results grid uses the shared `DxUi::Grid` folder-view visual mode. Idle rows stay visually quiet over the folder-view background, hover and selection use folder-pane-like rounded highlights, and Rainbow mode must not tint every idle row. Selected Rainbow-mode result rows MUST derive their color from the same containing-folder plus display-name stable hash and HSV selection recipe that `FolderView` uses for the item in its real folder.
- Result cell text tooltips are shown only when the visible cell text is clipped by the current column width, or when explicit non-duplicate help text is supplied. Fully visible names, paths, and other cell text must not show redundant tooltips just because the text is long.
- Local recursive searches must enumerate all matching files in nested subfolders when `Search subdirectories` is enabled and the local scan backend is used.
- Recursive traversal MUST descend into subdirectories independently of whether each directory name itself matches the name mask; a non-matching folder may contain matching files or folders below it.
- The Path column shows the containing folder relative to the searched root. Nested subfolders must be visible in this column; files directly in the searched root may show the current empty/placeholder path presentation.
- Header clicks cycle result sorting without changing explicit or persisted column widths.
- Resized columns must survive sort changes, repeated search refreshes, and result-grid rebuilds.

## Backend Options

- `Prefer indexed backend` is enabled only when the current root is an absolute local path that the index repository reports as indexable.
- When the indexed backend is unavailable for the current root, `Prefer indexed backend` is disabled and unchecked, and search request construction must not set `FILESYSTEM_SEARCH_PREFER_INDEX`.
- For an explicit built-in local search context, an unchecked `Prefer indexed backend` MUST set `FILESYSTEM_SEARCH_FORCE_SCAN` so the plugin does not select `service` or `local-index` through its `auto` backend policy.

## Regression Coverage

- `cmd_pane_find_dialog_command_enablement_matches_idle_running_and_selection_states` covers action enablement and the split-button menu pointer route.
- `cmd_pane_find_dialog_result_drains_respect_child_input_queue_order` covers the queue-order guard that prevents Find result/progress coalescing from skipping older child-window input messages.
- `cmd_pane_find_dialog_resized_columns_survive_sort_cycles` covers resized-column stability across header sort cycles.
- `cmd_pane_find_dialog_header_drag_reorders_columns_without_sort` covers header drag behavior without accidental sort changes.
- `cmd_pane_find_dialog_opens_from_focused_pane_and_allows_multiple_instances` covers focused-pane initial scope and multiple modeless instances.
- `cmd_pane_find_dialog_recursive_local_search_and_index_availability` covers local recursive subfolder results, Path column subfolder text, shell icon indices, forced scan when the indexed preference is unchecked, and disabled indexed-backend preference state.
- `cmd_pane_find_dialog_destination_navigation_stale_edit_host_hit_testing` covers stale queued destination hover, click, and double-click rejection after the live pointer leaves the embedded `NavigationView` for a far/different-window target, accepts queued history clicks when the live pointer only drifted into the same-owner edge fringe, verifies stale double-clicks do not enter edit mode, keeps history hover/click routing live while the path editor is active, and verifies inactive stale destination edit hosts retire as transparent/hidden before the history menu opens.
- `cmd_pane_find_dialog_action_buttons_activate_expected_commands` covers live UIA Find/Cancel/split-menu action buttons, directory-result Open navigation, Go to folder parent navigation, and the file-result Open disposition that must default-open without pane navigation.
- `cmd_pane_find_dialog_result_shortcuts_use_shell_clipboard_and_file_actions` covers settings-backed result-grid command resolution for shell clipboard formats, multi-subfolder `Ctrl+X`, the embedded `Look in` NavigationView presentation/history path, the result context menu's clicked-item and selection sections, context-menu shortcut labels resolved through `ShortcutManager`, clicked-item vs whole-selection dispatch, the compact right-aligned result-action help button, synchronous help-overlay close hit geometry before paint, captured owner backdrop for the modal help scrim, nonzero applied scrim opacity, backdrop refresh after owner resize while the help overlay is visible, visible first-frame modal help paint without mouse movement, release-only close-glyph dismissal for first-activation routing, delivered close-glyph press/release dismissal without title-bar movement, modal help focus and `Escape` dismissal, blended action-row status feedback, bottom destination `NavigationView` visibility/text/embedded presentation/history seeding, stale destination hover/click rejection when the live pointer has left the embedded control, live history-arrow open/close behavior, rendered first-frame destination popup state, footer-top anchored compact scroll-capped embedded destination dropdowns, explicit destination override for F5/F6, configured viewer/editor actions without scheduled Find foreground/focus restoration, move-to-recycle delete, row removal after accepted move/delete, canceled permanent-delete row preservation, and permanent-delete confirmation.
- `cmd_pane_find_dialog_theme_cycle_keeps_grid_legible` covers the Find results grid staying in the shared folder-view visual mode while dark, light, rainbow, and high-contrast theme updates keep the selected row legible and, in Rainbow mode, deriving the selected-row color from the same containing-folder/display-name stable hash recipe used by `FolderView`.
