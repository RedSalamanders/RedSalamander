# Scenario inventory and capture coverage

**124 named scenarios, 437 native PNGs, three revised French concept images.** Open the [gallery](gallery.html), [proposal](proposal.md), or [manifest](capture-manifest.json).

## Meaning of coverage

The original 128 English captures remain traceable to their Debug receipt. The revised set adds 300 French static images from the final Debug run and 9 French interaction images from Debug. Each current static scenario is captured on both actual monitors. Representative themes and widths supplement the dark catalog; this is a finite semantic inventory, not every combinatorial permutation.

The renderer, French satellite resources, conflict policy, menus, confirmation windows, speed prompt and Issues pane are real. Paths, timestamps, progress, rates, errors and task outcomes are controlled fixtures. Captures do not operate on user files. French fixture sentences include long names and parent paths. Numeric localization alone is not counted as French UI coverage.

## Coverage gaps

The earlier review blockers are **closed for the requested scope**:

| Earlier gap | New captured evidence | Boundary |
|---|---|---|
| Destination choices | 107: real destination-history flyout with seeded choices, both displays | Choices are presentation fixtures; no destination change/provider operation is executed |
| Issues and recovery | 103–106: empty, 28 typed issues, selected row and scroll; 114–115: known/unknown source recovery menus | The pane has no grouping mode to capture; no recovery action executes |
| Live entry confirmations | 102 variants 0–9: Copy, Move, Delete, verification availability, queue/parallel and clipboard consequences | Real dialogs are cancelled safely; some equivalent option combinations intentionally look alike |
| DPI and monitor transition | Every static scenario at native 144/96 DPI; 109–113 on the same HWND across displays and back | 200% requires a future native display configuration; images were never rescaled as evidence |
| French text | Real fr-FR resources and long French fixture text throughout; built-in theme representatives | Japanese/RTL/custom themes remain later qualification, not missing capture infrastructure |
| Interaction | 109 Tab, 110 Shift+Tab, 111 verified hover, 112 real press with owned mouse capture, 113 monitor return; checked/disabled fixture states elsewhere | This sequence does not establish all tooltip timings, every action transition, UIA or assistive-technology conformance |

No claim is made about real provider I/O, animation timing, every menu selection, taskbar overlays, all capability combinations or performance. Those belong to behavioral qualification. Native clipping is retained as evidence, never edited out.

## Fixture interpretation

- Counts, graph histories and provider messages are synthetic. Similar terminal notes are not evidence of an engine defect.
- An English OS error description can appear inside the French Issues pane; the French resource load is asserted independently.
- Static menu captures do not establish that a missing ordinary task action is currently user-reachable.
- Dialog width is `0` in the scenario TSV when the dialog chooses it. Actual PNG dimensions are in the manifest.
- Window size is bounded by the selected monitor work area. The short secondary monitor is an actual constrained-height case.
- Menus are separately captured process-owned windows. Dark transparent margins belong to capture framing.
- Pointer screenshots omit the cursor image; the input and hovered/owned-capture assertions establish the state.
- All three original English concepts are superseded. The horizontal comparison is explicitly rejected.
