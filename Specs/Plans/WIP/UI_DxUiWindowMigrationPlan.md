## Living Implementation Checklist

This checklist is the execution control list for broader `DxUi` migration beyond the first shared-grid pilots:

- mark completed work with `[x]`
- keep pending or active work as `[ ]`
- mark blockers as `[blocked]` and capture the missing dependency or decision
- add newly discovered required work under the relevant phase before continuing
- do not mark a phase complete until its validation items have passed

## Cleanup Milestone Checklist

- [x] Collapse the live high-fanout Preferences-, Connection Manager-, and Manage Plugins-class DX breadth by rolling the unstable multi-host page/dialog slices back to the proven legacy path.
- [x] Keep the live Preferences DX shell limited to the category tree, the one-host shell header/description/footer chrome, and the shared page-host background/card surface while broader page re-land work remains deferred.
- [x] Stop building heavy hidden-page child-control trees during Preferences open; non-active pages now create their real page-local child controls lazily on first activation instead of being built during initial dialog creation.
- [x] Stop pre-creating inactive Preferences pane containers during initial open; the dialog now creates only the active page container up front, and the page-host self-test explicitly locks that invariant.
- [x] Stop keeping inactive note-page pane containers alive after first activation; `Preferences.Editors` and `Preferences.Mouse` now destroy their pane container and DX note host when leaving the page and recreate them on demand when revisited.
- [x] Stop creating visible legacy note placeholders on the direct-host note pages; `Preferences.Editors` and `Preferences.Mouse` now create their note content DX-first on the reset path.
- [x] Stop relying on visible legacy backing toggles on `Preferences.General`; the direct-host reset path now creates the General toggle-card surface DX-first and applies setting changes directly from DX toggle callbacks.
- [x] Update Preferences debug snapshot accounting so direct-host pages measure the shared page host itself as the active DX page surface instead of assuming every active page still owns a child DX host window.
- [x] Reuse shared graphics-device resources across remaining child `DxUi::WindowHost` surfaces so migrated shells stop multiplying D3D11/D2D device stacks.
- [x] Keep the shared `DxUi::WindowHost` graphics-resource pool single-UI-thread-owned; mixed-thread access now logs and fails fast instead of sharing unsynchronized D3D11/D2D/DXGI/DirectWrite state.
- [x] Keep hidden or redraw-suppressed child DX hosts from creating or resizing swap chains until they are visible again.
- [x] Remove immediate swap-chain recreate loops from resize-failure paths before resuming broader migration breadth.
- [x] Gate child-host invalidation, swap-chain resize, and present work on effective visibility so hidden or minimized DX child hosts stop spamming resize failures during shell/layout churn.
- [x] Keep Preferences redraw-suppression helpers non-allocating in teardown/re-enable paths so cleanup-era batched transitions cannot terminate from destructor allocations.
- [x] Keep Preferences category/page redraw scoped to the shell/page DX hosts instead of dialog-wide erase plus forced category-tree invalidation so page switches stop flashing white and repainting the tree; post-batch redraw now invalidates only the shell/page hosts instead of forcing immediate dialog-wide redraw passes.
- [x] Keep Preferences shell/page/active-pane layout refreshes from repositioning unchanged HWNDs so category switches and page-host relayout do not churn gratuitous repaint work.
- [x] Detach Preferences-owned `DxUi::WindowHost` instances before destroying their owned child HWNDs so nested page/editor teardown cannot reenter stale child-host callbacks during pane switches, and resolve child-host subclass callbacks from the live window property instead of stale subclass `refData`.
- [x] Keep Connection Manager editor-load combo updates from reentering commit/layout work so switching connections leaves the visible DX form surface populated after the selection settles.
- [x] Keep Connection Manager protocol switches from leaving stale S3/SSH section headers visible after switching back to FTP-class protocols; the visible DX section-header set now has explicit selection-switch acceptance coverage.
- [x] Keep runtime sweeps and new migration breadth paused until validation restarts on the cleaned-up narrow DX state.

Cleanup milestone status: complete. Remaining work now shifts to validation and later one-host re-landings, not further broad rollback cleanup.

## Goal

Use the shared `DxUi` stack as the default UI path for remaining app and plugin windows that still rely on visible Win32 common controls or owner-drawn Win32 dialog chrome.

The target look and feel is not "custom skinned Win32." It is a DirectX UI family that stays visually coherent with the current app theme while behaving closer to modern WinUI/XAML controls for focus, hover, keyboard, popup, and command semantics.

## Frozen Acceptance Matrix

- Stand-alone search/form shells pass when all visible controls are DX-hosted, `Tab` / `Shift+Tab` traversal is stable, default/cancel routing is correct, access keys focus the intended fields, popups dismiss predictably, and no visible child-control fallback remains.

- Grouped/checkable/icon-rich list windows pass when shared grid or tree primitives preserve grouping, checkbox/state-image interaction, icon/badge layout, infotips, selection/copy behavior, context menus, persisted layout where applicable, and bounded visible-work behavior.

- Existing DX viewer shells with remaining Win32 chrome pass when visible combo/dialog chrome is removed or explicitly accepted, shared DX popup/keyboard behavior matches the rest of the DXUI family, and the viewer no longer mixes a DX content surface with visible legacy controls.
