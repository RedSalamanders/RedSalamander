## Adoption sequence

1. **Select and record the producer pin.** Review the producer capabilities, compatibility changes and published evidence at one API 6 commit. Record the existing consumer and lock as the rollback pair, plus the selected producer SHA and revision. Update the lock and compatible adapters together. [DxUi capability manifest](https://github.com/RedSalamanders/DxUi/blob/main/capabilities.json)
2. **Adapt the consumer boundaries.** Cover H-01 and H-02 by installing the application failure host before entering DxUi and reviewing the exception boundaries, including the fatal allocation policy. Use the public logging and posted-payload interfaces for the applicable H-05 and H-14 call sites. Keep RedSalamander's ETW and plugin contracts, window message forwarding, token ownership and teardown covered by consumer tests.
3. **Adopt the pinned build and restore interface.** Use the public restore tooling, provenance and triplet settings and import the native build policy in its supported order. Preserve the existing public command arguments and exit outcomes. Prove clean source restore, an exact restore in a relocated checkout, and rejection of the wrong revision, dirty source, or mismatched compiler, CRT and sanitizer inputs. Verify any optional qualified SDK path against the product contract. [SDK input schema](../../Build/Build_DxUiSdkInput.schema.json)
4. **Qualify the exact consumer.** The build and test maintainer owns the native runs. Bind six zero-warning builds and required PR checks to the reviewed RedSalamander source and exact DxUi lock. Run the applicable ProductUiTests, RedConfigure and hosted Release regressions, covering dispatch, focus, DPI, text input, accessibility and teardown. Record clean portable-package smoke results on x64 and native ARM64. Keep scoped, interactive, paired performance and unavailable capabilities in the owning validation records. Record any D21 deferral with source, scope, outcome, owner and replay.
5. **Reconcile and close.** Update the affected consumer contracts, pin and publication evidence. Verify rollback restores the compatible consumer adapters, tools and lock together. When the consumer obligations close, archive this plan through the protected Done admission process and update both indexes.
