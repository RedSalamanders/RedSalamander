## Findings considered and rejected (do not re-audit)

False positives, killed during advisor vetting against source:

- **curl CURLOPT_URL string lifetime** (FileSystemCurl.Shared.cpp:2909): the `url` local outlives `curl_easy_perform` in the same scope, and libcurl copies string setopt arguments since 7.17.0. Not a bug.
- **Navigation-menu callback not cleared by plugin destructor** (FileSystemCurl.h:776): host-clears-callback before unload is the documented plugin lifecycle contract (AGENTS.md unload quiet-point). By design.
- **7z listing buffer overflow** (FileSystem7z.cpp:289-349): overflow check per accumulation and bounds check before each write are present. Not a bug.
- **ViewerWeb find-query script injection** (ViewerWeb.cpp:1977): the query passes through `EscapeJavaScriptString` at :1976. Already mitigated.
- **`ignoreSslTrust` disables TLS verification** (FileSystemCurl.Shared.cpp:2275-2281): explicit per-connection opt-in; by-design convention (a UI warning when enabling it would be a nice-to-have, not a finding).
- **Crash marker file tampering** (CrashQuarantine.cpp): the marker lives in the user's own %LOCALAPPDATA%, protected by profile ACLs. Threat model doesn't hold.
- **OAuth loopback accepts non-loopback traffic** (FileSystemMicrosoftDrive.cpp:1578): bound to 127.0.0.1/::1; OS enforces loopback isolation; state validated. Defense-in-depth at best.
- **OAuth state validation weakness** (FileSystemMicrosoftDrive.cpp:1631): length-checked ordinal comparison; safe as written.
- **WIC factory recreated per thumbnail batch** (FolderView.Icons.cpp:869): the factory is cached via a caller-owned `wil::com_ptr&` and creation is counted (`wicFactoryCreate` stat). Already cached.
- **Case-insensitive extension hash cost** (FolderView.Enumeration.cpp:14-31): towlower per char on ≤5-char extensions, once per item per enumeration — measured-in-microseconds territory. Not worth doing.

Real but deliberately NOT planned (with rationale):

- **ColorTextView vs ViewerText D2D text-rendering duplication** (5,536 + 8,561 lines): real duplication, but the two have different rendering philosophies (streaming monitor vs static viewer) and a unification is L-effort/HIGH-risk with no current forcing function. Revisit if a third text renderer appears.
- **FolderWindow / Preferences.Dialog.cpp god-files** (Preferences.Dialog.cpp = 6,932 lines verified): true debt, but a safe decomposition needs the owners' architectural intent; a mechanical split by an executor would churn 100+ call sites for unclear gain. Candidate for a future maintainer-led design spike.
- **Resource.h manual ID management** (191 commits/6 months): codegen would help, but build-system surgery on .rc tooling is high-blast-radius; revisit if ID collisions actually start happening.
- **Plugin DLL loading with LOAD_WITH_ALTERED_SEARCH_PATH** (FileSystemPluginManager.cpp:154): standard for plugin systems that carry their own dependencies; installing a plugin is already code execution. Optional hardening (`LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`) noted for whenever third-party plugin distribution becomes real.
- **Release-configuration test execution in CI**: in-process selftests are Debug-only by design; whether the standalone test exes are meaningful in Release needs investigation — deferred, noted in plan 011.
- **aws-sdk-cpp weight** (vcpkg.json, used only by FileSystemS3): a vcpkg feature-group split is possible but reshapes the default build for everyone; maintainer call.
- **BatchRenameEngine engine-level unit tests**: substantial UI-level selftest coverage already exists (`Commands.SelfTest.BatchRename.cpp`, recent case-only coverage commits); marginal value didn't clear the bar against the planned test work.
- **Metadata/details text recomputation batching** (FolderView.Layout.cpp:780-790): plausible but unmeasured; folded conceptually into plan 010's measurement scope.
