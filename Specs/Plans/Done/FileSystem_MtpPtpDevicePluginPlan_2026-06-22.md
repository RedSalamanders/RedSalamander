## 1. Goals / Non-goals

### Goals
- Read and write files on a connected MTP/PTP device through WPD (`IPortableDevice*`) with no third-party dependency (WPD ships in the Windows SDK / in-box runtime).
- Implement the mandatory `IFileSystem` surface plus the optional interfaces that map cleanly to WPD: `IFileSystemIO`, `IFileSystemDirectoryOperations`, `IInformations`, `IDriveInfo`, `INavigationMenu`, `IFileSystemInitialize`.
- Surface each connected device as a navigable drive/connection (`IDriveInfo` + `INavigationMenu` + `/@conn:` resolution), including device arrival/removal (hotplug).
- Honest capability gating: declare structurally unsupported features (random write, in-place overwrite, recycle bin, watch/search, timestamp-write) as unsupported; use probed device capabilities only to select native-vs-fallback paths for copy/move/delete recursion; advertise host-facing copy/move support when the writable-profile fallback can perform it safely, and use per-method `ERROR_NOT_SUPPORTED` for genuinely unsupported requests.
- Data-safety parity with existing FS plugins: no silent overwrite, byte-integrity verification before a destructive overwrite swap — **local** transmit-hash by default (proves we sent the source bytes and the device accepted the declared length; it does **not** prove the device stored them), with an opt-in full device re-read (`deviceReread`) for true device-storage integrity (§17) — never leave the device with a half-written object, duplicated final name, or silently-selected ambiguous duplicate.
- Deterministic, device-less testability via an internal `IMtpBackend` seam with a `FakeMtpBackend` (the sole required harness, gates M0–M3) plus an M4+ stretch `RecordedMtpBackend` (capture/replay; §21), registered as `SelfTest::RunCase` cases.
- Mandatory perf validation from M0: named scenarios, an `mtp.*` metric family, deterministic self-tests, archived runs under `Specs/TestRuns/`.

### Non-goals (v1)
- Real-time directory watch (`IFileSystemDirectoryWatch`): WPD object events are driver-discretionary and lossy. v1 omits the interface (QI fails) and relies on host poll + refresh-on-navigate.
- Content search and server-side search (`IFileSystemSearch`): would require downloading every candidate object (whole-object transfer). Omit the interface; host falls back to its own scan via `ReadDirectoryInfo`.
- Alternate data streams (`IFileSystemItemStreams`): MTP has no ADS concept. Omit the interface.
- Random/seek writes, append, in-place edit: structurally impossible on MTP (§6 item 4 + §17). Public `IFileWriter` is staged-to-temp then whole-object upload on `Commit`; direct WPD stream upload is an internal optimization only when the plugin itself already knows the final byte count.
- Multi-plugin DLL: single plugin (`builtin/file-system-mtp`), single mode.
- PTP-camera-specific capture/control commands (taking a photo, triggering capture). Read/write FS only.

## 2. Background & glossary

- **MTP** (Media Transfer Protocol) — Microsoft device-bus protocol for transferring media/files to/from portable devices. Successor/superset of **PTP** (Picture Transfer Protocol, the camera standard). Both are surfaced identically through WPD.
- **WPD** (Windows Portable Devices) — the in-box Win32 user-mode COM API (`PortableDeviceApi.dll`) that wraps the MTP/PTP initiator stack. This is the only API we use.
- **Object store, not a filesystem** — WPD exposes a tree of **objects** (storages, folders, files), each identified by a runtime string **Object ID** (`WPD_OBJECT_ID`). There is no native path, no `open(path)`, no `seek`, no partial write on most devices.
- **Object ID vs path** — Object IDs are unique on the device but **session-scoped**: they may change after a reconnect. Only `WPD_OBJECT_PERSISTENT_UNIQUE_ID` (PUID) survives a reconnect. We synthesize paths from `WPD_OBJECT_ORIGINAL_FILE_NAME` (preferred) / `WPD_OBJECT_NAME` joined up the `WPD_OBJECT_PARENT_ID` chain, and maintain our own path↔ObjectID map.
- **Whole-object transfer** — writes require the total size declared up front (`WPD_OBJECT_SIZE`) and finish with `IStream::Commit`; there is no random-access write or append.
- **Per-device serialization** — the MTP transport is request/response and effectively single-session; concurrent operations against one device degrade or fail. One dedicated MTA worker thread + serialized command queue per device.
- **Functional objects / storages** — direct children of the device object (`WPD_DEVICE_OBJECT_ID`) are typically storage functional objects (`WPD_CONTENT_TYPE_FUNCTIONAL_OBJECT`), one per volume (internal, SD card). Their children form the folder/file tree.
- **Plugin contract terms** — `IFileSystem` and friends are RedSalamander's COM-style plugin interfaces in `Common/PlugInterfaces/`. `shortId` = navigation scheme (`mtp`). `id` = stable identity (`builtin/file-system-mtp`). `cookie` = opaque host-supplied context passed back verbatim into callbacks.

## 4. Why this approach

### API / library reality
- WPD (`IPortableDevice`, `IPortableDeviceContent`, `IPortableDeviceResources`, `IPortableDeviceCapabilities`, `IPortableDeviceProperties[Bulk]`) is the native, in-box, supported stack for MTP/PTP on Windows 11 (x64 + ARM64, identical API surface).
- Headers: `PortableDeviceApi.h`, `PortableDevice.h`, `PortableDeviceTypes.h`. Link **`PortableDeviceGuids.lib` only** (load-bearing — supplies `CLSID_*`/`IID_*`/`PROPERTYKEY` symbols). `PortableDeviceApi.lib` is not linked — objects come from `CoCreateInstance`, no direct DLL imports (definitive rationale in §19.A.6). Runtime `PortableDeviceApi.dll` is in-box.
- Prefer `CLSID_PortableDeviceFTM` (free-threaded marshaler) over `CLSID_PortableDevice`. Note the `IPortableDevice::Open` Remarks frame the marshaling-overhead benefit specifically for **STA** callers (it eliminates interface-pointer marshaling when the interface crosses an apartment boundary). On our per-device **MTA** worker the same-apartment benefit is largely moot, but FTM remains the correct, harmless choice because returned interfaces/streams may still be handed to the STA (e.g. picker/UI marshaling); do not cite "eliminates marshaling overhead" as a flat MTA win.

### Performance reality
- Every WPD call is a per-object MTP round-trip over USB; latency, not CPU, dominates. The decision metric is **round-trip count**, not wall time alone.
- Enumeration is the slowest part. Mitigation: lazy per-directory enumeration + `IPortableDevicePropertiesBulk` (one batched async round-trip for a whole directory's property set) with a per-object `GetValues` fallback.
- Single-session transport → false parallelism *hurts*. Concurrency caps must be 1 (see §11), unlike the repo default of 4/8.
- Whole-object transfer means copy = double whole-object transfer; move/copy frequently unsupported on-device; dir-size = recursive per-object fetch (pathologically slow). These shape the capabilities JSON and the perf scenarios.

## 6. Product constraints from MTP/WPD (first-order design inputs)

1. **No paths** — synthesize `/<device>/<storage>/<dir>/<file>` from object names + parent chain; maintain a path↔ObjectID map.
2. **Object IDs are session-scoped** — persist PUIDs for anything remembered across reconnect; re-resolve via `GetObjectIDsFromPersistentUniqueIDs`; drop the path↔ID cache on reconnect/`WPD_EVENT_DEVICE_RESET`.
3. **Whole-object write; size up front** — `WPD_OBJECT_SIZE` must be known before transfer; unknown-size sources must be buffered to a temp file first.
4. **No random/seek write, no append** — edit = download→modify→delete→upload.
5. **Per-device serialized access** — one MTA thread + command queue per device; never concurrent on one device.
6. **Slow enumeration** — lazy + bulk property fetch + caching.
7. **Duplicate sibling names + case collisions allowed** — path map keyed on (parent, name) must disambiguate.
8. **Move/Copy/recursive-delete are optional device capabilities** — probe, then enable, else fall back.
9. **Timestamps often unwritable/missing** — tolerate missing dates; do not fail uploads when timestamps can't be set.
10. **Access-denied devices** — implement R/W→R/O `Open` fallback; surface a read-only mount cleanly.
11. **Events are lossy** — never promise real-time watch.
12. **Hot-plug** — device can vanish mid-operation; detect device-gone HRESULTs and fail cleanly (no hang); let host relocate the pane.

## 9. Device / profile model

- One connection profile = one **device identity** + policy + optional storage selection:
  - `ConnectionProfile.pluginId = L"builtin/file-system-mtp"`.
  - `ConnectionProfile.host = <current WPD PnP device id>` as an opaque required-field hint only. It may change across ports and is not the primary identity.
  - `ConnectionProfile.authMode = Anonymous`, `userName = L""`, `savePassword = false`, `requireWindowsHello = false`.
  - `ConnectionProfile.extra.devicePuid` = device-object `WPD_OBJECT_PERSISTENT_UNIQUE_ID` when available (primary reconnect key).
  - `ConnectionProfile.extra.friendlyName` and optional `extra.manufacturer` / `extra.description` for display and fallback matching.
  - `ConnectionProfile.extra.defaultStoragePuid` / `extra.defaultStorageName` for default storage selection.
  - `ConnectionProfile.extra.readOnly` for user-forced read-only mode.
- Reconnect identity: match by `extra.devicePuid` first, then by current `host`/PnP hint, then by friendly-name fallback only when it is unique among live devices. If no unambiguous live device exists, fail `Open` with a localized "device not connected" result and let the host relocate the pane.
- Non-secret config (timeouts, page size, chunk hints, `readOnly`, default storage) lives in `ConnectionProfile.extra` (JSON). No secret API used.
  - `extra.commandTimeoutMs` = per-command no-completion watchdog deadline. Default `120000`; min `5000`; max `600000`. Tests may use smaller values through the MTP self-test factory only, never by changing production defaults.
  - `extra.hardQuarantineTimeoutMs` = secondary deadline after best-effort `Cancel`/stream-release before the session is declared lost and the worker is quarantined. Default `15000`; min `1000`; max `60000`.
  - `extra.enumerationPageSize` = `IEnumPortableDeviceObjectIDs::Next` page size. Default `32`; min `1`; max `256`.
  - `extra.transferChunkBytes` = read/write hint when WPD returns no optimal buffer. Default `262144`; min `65536`; max `4194304`. If WPD returns an optimal size, honor the returned value unless it is zero.
- Default behaviors: open R/W, fall back to R/O on `E_ACCESSDENIED`; lazy per-directory enumeration; bulk property fetch when `IPortableDevicePropertiesBulk` is present.

## 10. IFileSystem contract mapping (every method accounted for)

The plugin class implements `IFileSystem, IFileSystemIO, IFileSystemDirectoryOperations, IInformations, INavigationMenu, IDriveInfo, IFileSystemInitialize`. Optional interfaces NOT implemented (QI fails): `IFileSystemDirectoryWatch`, `IFileSystemSearch`, `IFileSystemItemStreams`.

Factory entry point honored exactly:
```cpp
extern "C" PLUGFACTORY_API HRESULT __stdcall
RedSalamanderCreate(REFIID riid, const FactoryOptions* factoryOptions, IHost* host,
                    const wchar_t* pluginId, void** result);
```
`riid == __uuidof(IFileSystem)` ({12519afa-30e7-4e3a-9db2-7990c4be9a21}); `pluginId` selects the single mode; `new (std::nothrow) FileSystemMtp(host)`; `QueryInterface(riid, result)` + `Release()` to transfer the single ref.

**`pluginId` contract for a single-mode DLL (DO NOT copy S3 verbatim).** `Common/PlugInterfaces/Factory.h` documents (lines 41, 67): *"For single-plugin DLLs, `pluginId` may be `nullptr` or empty."* The S3 reference is a *multi-mode* DLL and therefore rejects `nullptr`/empty with `E_INVALIDARG` in `RedSalamanderCreate`/`RedSalamanderGetConfigurationSchema` (`Plugins/FileSystemS3/Factory.cpp`, the `if (! pluginId || pluginId[0] == L'\0') return E_INVALIDARG;` guards). That guard is **correct for S3 but WRONG for FileSystemMtp** — copying it verbatim would reject the documented single-plugin call form. Exact required behavior for `FileSystemMtp::RedSalamanderCreate` and `RedSalamanderGetConfigurationSchema`:
  - `pluginId == nullptr` **OR** `pluginId[0] == L'\0'` (empty) **OR** `pluginId == L"builtin/file-system-mtp"` → accept as the single mode.
  - Any other non-empty string → `HRESULT_FROM_WIN32(ERROR_NOT_FOUND)` (id mismatch, not `E_INVALIDARG`).
  - `result == nullptr` → `E_POINTER`; `riid != __uuidof(IFileSystem)` → `E_NOINTERFACE`.
This divergence from the S3 template is flagged again in §3 (implementation shape) and §14 (Factory.cpp responsibility) so the implementer does not inherit the bug.

Legend for "Verdict": S = straightforward, A = awkward, H = hostile. "Fallback" = exact HRESULT / capability-flag behavior when unsupported. `ERROR_NOT_SUPPORTED` below means `HRESULT_FROM_WIN32(ERROR_NOT_SUPPORTED)`. `GetCapabilities` itself may **never** return `E_NOTIMPL`/null/empty (contract violation; host fails-closed).

Signatures in the tables below are **abbreviated for readability** — some `const` qualifiers and `= nullptr` default arguments are elided. The implementation MUST match `Common/PlugInterfaces/FileSystem.h` exactly. The `IFilesInformation` / `IFileReader` / `IFileWriter` rows describe **returned-object** interfaces (created by `ReadDirectoryInfo` / `CreateFileReader` / `CreateFileWriter`), not interfaces QI-able from the `FileSystem` instance itself.

### 10.0 IUnknown / QueryInterface matrix

The class hand-rolls `IUnknown` (`AddRef` / `Release` / `QueryInterface`) across **7** inherited interfaces, so `QueryInterface` is the single most error-prone spot (the `IUnknown` base is ambiguous across the multiple-inheritance graph — disambiguate by casting through one chosen interface, e.g. `static_cast<IFileSystem*>(this)`). Exact contract:

| `riid` | Result |
|---|---|
| `IUnknown` | `S_OK` — return `static_cast<IUnknown*>(static_cast<IFileSystem*>(this))` (single canonical path; same pointer every call) |
| `IFileSystem`, `IFileSystemIO`, `IFileSystemDirectoryOperations`, `IInformations`, `IFileSystemInitialize`, `INavigationMenu`, `IDriveInfo` | `S_OK` — return the matching base sub-object pointer |
| `IFileSystemDirectoryWatch`, `IFileSystemSearch`, `IFileSystemItemStreams` | `E_NOINTERFACE` — advertised-unsupported (§10.9) |
| `IFilesInformation`, `IFileReader`, `IFileWriter` | `E_NOINTERFACE` — returned-object interfaces, never QI'd off the FS |
| anything else, or `result == nullptr` | `E_NOINTERFACE` (`E_POINTER` if `result == nullptr`) |

Every `S_OK` branch MUST `AddRef()` the returned pointer before returning (a hand-rolled QI is exactly where a missing AddRef hides). Self-test `mtp_queryinterface_matrix` (§21) asserts every must-succeed IID returns a non-null, AddRef'd pointer that round-trips back to `IUnknown` identically, and every must-fail IID returns `E_NOINTERFACE`. `IUnknown` (the 3 methods) is part of the "every method accounted for" surface even though it is not tabulated per-interface below.

**Copy/move advertised-vs-native (authoritative — resolves the §18 tension):** `operations.copy` / `operations.move` are **always advertised `true`** whenever the active profile is writable, because the download→upload(+delete) fallback guarantees them on every device. The capability probe (§18) only selects the *native-vs-fallback code path*; it never flips the advertised boolean to `false`. Implement and test against this one rule so §10.5 and §18 cannot be implemented divergently.

**Move fallback partial semantics (authoritative).** For fallback move (`download → upload → delete source`), once the destination upload/overwrite succeeds, the plugin must not roll it back merely because source delete fails. Return the source-delete HRESULT when it is specific, otherwise `HRESULT_FROM_WIN32(ERROR_PARTIAL_COPY)`; emit per-item completion/issue that the destination exists and the source was left behind; leave both objects visible. This is a partial move/duplicate-left terminal state, not silent success and not a destructive rollback. Self-test `mtp_move_fallback_delete_source_failure_leaves_duplicate_and_reports_partial` gates it.

**Manual recursive delete is not atomic:** native `Delete` is all-or-nothing on a hard error (only `S_FALSE` is partial), but the manual depth-first fallback issues many `Delete` calls, so a mid-sequence failure can leave a *partially* deleted tree. Report that as `ERROR_PARTIAL_COPY` with per-item completion callbacks — do not present the fallback path as atomic.

**`const char*` return storage contract (two slots per method — not retain-forever).** The in-repo contracts (`FileSystem.h`, `Informations.h`) say returned JSON pointers are valid until the **next call to that same method** or object release. Therefore all JSON-returning methods use the same bounded helper: `JsonReturnBuffers { std::array<std::string, 2> slots; uint8_t active; }`, one instance per method under `_jsonReturnMutex`.
- `GetConfiguration`, `GetCapabilities`, and `GetItemProperties` each write the next result into the inactive slot, flip `active`, and return `slots[active].c_str()`.

## 11. Async / threading / cancellation / plugin-unload quiet point

### Device-access architecture
- **One dedicated MTA worker thread per device**, owned by the per-device session object. The thread runs `wil::CoInitializeEx(COINIT_MULTITHREADED)` for its lifetime. All WPD calls for that device execute on this thread via a serialized command queue (each FS op posts a work item + waits on a `wil::unique_event`). The UI thread (STA) never calls a device interface synchronously.
- **`IPortableDeviceManager` is not a device-session interface, but the same STA rule applies.** It is created per-apartment, never shared: the **Connection Manager device picker enumeration runs on a worker** (not the STA) and marshals a plain `{pnpId, friendlyName}` list back to the STA picker UI via `PostMessagePayload`; the **hotplug watcher jthread (MTA)** owns its own separate manager instance for `RefreshDeviceList`/`GetDevices`. The two manager instances are distinct per-apartment objects and never alias (the manager is cheap, no `Open`). See §16 for the ownership rule.
- **No detached threads.** `std::thread(...).detach()` is forbidden in the DLL. Use a `std::jthread` member with `std::stop_token` for the device worker and the device-manager notification watcher, joined on session teardown / `RedSalamanderPluginShutdown`. Where threadpool callbacks are used (`IPortableDevicePropertiesBulkCallback`, `IPortableDeviceEventCallback`), prefer `TrySubmitThreadpoolCallback`; pin the module via an address-anchored `wil::unique_hmodule moduleKeepAlive` captured into the work context, touched in the callback, ownership transferred on submit success. If a worker cannot join because WPD never returns, it is not "detached"; it is a quarantined live worker reported through `RedSalamanderPluginCanUnloadNow() == FALSE`.
  **Concrete ownership (resolves the "jthread dtor joins → deadlock" problem without `detach`, without a permanent pin, and without self-unmapping):** the device worker is a `std::jthread` member of `MtpDeviceContext`; in the normal case its dtor stop-requests + joins a responsive thread. When the watchdog quarantines a wedged worker, the owning `MtpDeviceContext` is **moved into a manager-visible quarantine list and is NOT destroyed yet** (destroying it would join the wedged thread and block). The quarantine context owns a **reversible** module reference (`AcquireModuleReferenceFromAddress`, `Common/Helpers.h` — a `wil::unique_hmodule` that `FreeLibrary`s on destruction) so the DLL stays mapped while worker code may still run.
  The worker must **not** destroy the module keepalive itself as its final act: if that reference is the last live DLL ref, `FreeLibrary` from inside the worker can unmap code while the thread is still returning through it. Instead, the worker unwinds only its own COM/session/state, clears host callback pointers, sets atomic `workerExited = true` with release semantics, and returns. `RedSalamanderPluginCanUnloadNow()` is both the poll and the cleanup gate: it checks `workerExited` **non-blockingly** and returns FALSE immediately if any quarantined worker is still live. For contexts whose `workerExited` flag is already set, it joins only the already-finished `jthread`, erases the context from the quarantine list, and then destroys the quarantine context, which releases the module keepalive from the manager/sweeper thread. Only after that may the aggregate unload check return TRUE.
  This keeps deferred unload real for a worker that eventually returns. If a WPD call never unwinds, the quarantine context and module stay loaded until process exit; that leak is deliberate and bounded by the number of wedged workers, and it is safer than unloading executing DLL code. **Do NOT use `GET_MODULE_HANDLE_EX_FLAG_PIN`** — an irreversible pin can never be unloaded even after the worker exits, which would contradict the deferred-unload contract (§11 step 5, M3 acceptance). This reversible-ref + non-blocking-poll path is the one sanctioned exception to "always join immediately"; it is neither a dtor-join-while-running nor a `detach()`.
- **Single-session / serialized → concurrency caps = 1.** `GetCapabilities().concurrency = {copyMoveMax:1, deleteMax:1, deleteRecycleBinMax:0}`; `GetStorageCharacteristics().preferredCopyMoveConcurrency = 1`. A per-device global gate ensures two host tasks never hit the same device concurrently (key on the device identity). Setting host concurrency higher must NOT produce concurrent device I/O — an acceptance criterion.
- **Hung-device watchdog / per-command deadline (mandatory).** Cooperative `FileSystemShouldCancel` polling cannot interrupt a WPD `IStream::Read`/`Write`/`Commit` that never returns (wedged USB/driver). Every command dispatched to the device worker carries a deadline (a timed `wil::unique_event::wait(ms)` on the per-command completion event — the existing repo primitive; see `.github/skills/async-threading`). On a tripped deadline the watchdog makes a **best-effort** unblock attempt: `IPortableDeviceContent::Cancel` — which per WPD docs cancels **all** pending operations on that session (acceptable here because the queue runs one op at a time) and requires the watchdog to hold an **FTM-marshaled** content pointer to call it cross-thread — and/or releasing the in-flight stream. **`Cancel` is best-effort for `Read`/`Write` only and CANNOT interrupt a wedged `Commit`** (per the Cancellation section below: once `Commit` is entered it runs synchronously); a write cancelled mid-stream must `IStream::Revert()` on unwind. The real guarantee is therefore NOT `Cancel` but the quarantine path: if the worker is *still* blocked after a hard secondary deadline, the session is declared lost: mark the `MtpDeviceContext` dead, complete the host operation with a device-gone HRESULT, stop all future posts to that context, and **do not blindly `join()` the wedged worker**. The in-flight command state must be heap-owned (`shared_ptr`/equivalent) with no references to the caller's stack; before the host call returns, atomically clear its callback/cookie pointers and mark callbacks disabled, while the worker retains its own reference until it finally unwinds. The stuck worker may only unwind into code that releases its own COM/session state and sets `workerExited`; the module keepalive remains owned by the quarantine context until the manager/sweeper joins the finished thread. The worker must not retain host callbacks, navigation callbacks, or `IFileSystemCallback` pointers after the operation has completed. Runtime refresh then follows the unload-deferral contract: `RedSalamanderPluginCanUnloadNow()` returns FALSE, `FileSystemPluginManager` keeps the old module quarantined, does not call `FreeLibrary` for that entry, and skips fresh reload from the same path until a later refresh/shutdown sees TRUE. `FakeMtpBackend` MUST be able to inject a never-returning call so `mtp_hung_device_times_out` and `mtp_runtime_refresh_defers_when_worker_quarantined` (§21) exercise this path.
- **The per-device event callback bypasses the command queue.** `IPortableDevice::Advise` delivers `IPortableDeviceEventCallback::OnEvent` on a WPD-chosen thread, asynchronously, possibly while a serialized command is mid-flight on the worker. `OnEvent` is the one path *outside* the queue: it may only set atomics / post a cache-invalidation or teardown request — no WPD calls, no `_stateMutex` held across it, no reentrant command dispatch. `WPD_EVENT_DEVICE_REMOVED`/`WPD_EVENT_DEVICE_RESET` flip the context to dead so the in-flight and next commands fail fast.
- **The MTA-worker-per-device + serialized queue is net-new.** Neither `FileSystemS3` (no worker thread) nor `FileSystemMicrosoftDrive` (a single drain condition-variable, no worker thread) has this; only the *navigation-menu drain shape* is reused. Budget the threading core as original work with its own teardown/timeout stress test — not a copy.
- **No WIL exception macros in implementation snippets.** Pseudocode in this plan describes call order only. Production helpers return `HRESULT`, use explicit `if (FAILED(hr)) return hr;`, and keep ABI/thread callbacks `noexcept` without `THROW_IF_FAILED`/C++ exception control flow.

### Cancellation + progress + cookie pattern
- Per-call callbacks (`IFileSystemCallback`, `IFileSystemDirectorySizeCallback`) are **raw vtable, not COM** — never stored in `wil::com_ptr`, never AddRef'd. Forward the host-supplied `void* cookie` **verbatim** into every callback invocation.
- Poll `FileSystemShouldCancel(BOOL*, cookie)` / `DirectorySizeShouldCancel` frequently inside slow enumeration/transfer loops; on cancel return `HRESULT_FROM_WIN32(ERROR_CANCELLED)`. Cancellation is normal control-flow — **do not log it**.
- Progress: `FileSystemProgress(...)` with a distinct stable `progressStreamId` per worker (we have at most 1). Conflicts via `FileSystemIssue(...)` returning `FileSystemIssueAction`.
- Transfer cancel mechanics: **upload** — stop writing, call `IStream::Revert()` (abandons object creation, nothing created). **download** — stop reading, release the source `IStream`. `IPortableDeviceContent::Cancel` / `IPortableDeviceCapabilities::Cancel` cancel **all** pending operations on that session (whole-session, not per-op — acceptable here because the queue runs one op at a time). **No clean mid-`Commit` cancel** — once `Commit` is called it runs synchronously; cancellation must be checked before `Commit`.
- Callbacks may block (host Pause / inline conflict UI); never hold the device `_stateMutex` across a callback that may block.
- Plugins MUST NOT invoke a per-call callback after the operation returns, nor concurrently for one operation.

### Plugin-unload quiet point (sequence)
1. Host stops scheduling new work / stops producers.
2. Host requests cancel; plugin sets `_stopping`, signals device worker `stop_token`, drains the command queue (cancel pending items).
3. `SetCallback(nullptr, nullptr)` — hard synchronous barrier: snapshot under lock, release lock, wait for in-flight menu/navigate callbacks to drain (counter + CV), then guarantee the old callback is never called again. Do NOT block the drain on an in-flight 30-second transfer while holding the lock — signal cancel, release lock, then join.
4. Unadvise WPD events (`IPortableDevice::Unadvise(cookie)`); join the device worker `jthread` **bounded by the watchdog deadline** after `Cancel`/stream-release. If it still does not return, **move the owning `MtpDeviceContext` into the manager-visible quarantine list (§11 Device-access architecture) instead of destroying it** (a dtor-join would block on the wedged thread), clear all host callback pointers, and mark it dead. The quarantine context keeps the **reversible** module reference; the worker only releases its COM/session state and sets `workerExited` when it unwinds. The context is reclaimed, the already-finished thread is joined, and the module keepalive is released by `CanUnloadNow()`/the host sweeper after that. Do not release or mutate state the still-running thread may touch, and do not pin the module irreversibly.
5. Runtime refresh must not unload a quarantined module. `FileSystemPluginManager` must call optional `RedSalamanderPluginCanUnloadNow()` after `RedSalamanderPluginShutdown()` and before `Localization::UnregisterResourceOwner` / `entry.module.reset()`. If it returns FALSE, keep the entry's `HMODULE` and resource owner registered, mark the plugin path as unload-deferred, skip rediscovery/reload of that same path for this refresh, and surface a diagnostic/status that the plugin is busy. A later refresh or process shutdown retries the same sequence. Only when `CanUnloadNow()` returns TRUE may the manager unregister resources and call `FreeLibrary`. **This reorders the currently-unconditional `Localization::UnregisterResourceOwner` (`FileSystemPluginManager.cpp:1182`) to run only inside the `CanUnloadNow()==TRUE` branch** — a behavior change to the *shared* unload path that requires its own regression check against existing plugins. Blast radius is bounded: a plugin that does not export `CanUnloadNow()` is treated as TRUE (§10.1), preserving today's order exactly.
   Required host-manager state model: add an explicit deferred-unload collection keyed by canonical plugin DLL path and plugin id/shortId (for example `_deferredUnloadEntries`). A deferred entry owns the `PluginEntry`, its `wil::unique_hmodule`, and resource-owner registration until a later sweep succeeds. `Discover()` must sweep deferred entries first, skip loading a new plugin from any path still deferred, and preserve existing loaded entries whose id/shortId would conflict with a deferred one. Process shutdown performs the same sweep once, then allows process-exit retain/leak for entries still returning FALSE; it must not spin or block indefinitely. Update/extend the source-scraping regression test in `RedSalamander/SelfTest/Commands.SelfTest.PluginConfig.cpp` so it validates the new shared unload order rather than failing on the reorder.
6. Process shutdown is allowed to leak/retain the module until process exit via `RedSalamanderPluginRetainModuleUntilProcessExit()`, but only after producers/callbacks are stopped and host pointers are cleared. The retain vote is not a runtime-refresh mechanism.
- Cross-thread UI payloads (hotplug refresh) marshal to the UI thread via `PostMessagePayload`/`TakeMessagePayload<T>`; teardown stops producers first because `PostMessagePayload` does not guard against a destroyed `HWND`.

## 12. Error handling & logging conventions

- `Debug::ErrorWithLastError()` for Win32 failures; `Debug::Error()` for unexpected/never-should-happen; `Debug::Warning()` for recoverable. Do NOT log normal control-flow (cancellation, "device not connected", handled disconnect, `ERROR_NOT_SUPPORTED` advertised-unsupported paths).
- **`catch(...)` is FORBIDDEN.** At every `noexcept`/ABI/threadpool/WndProc boundary catch only named types: `std::bad_alloc` → `std::terminate()`; `std::exception` → log once with `Debug::Error` and return a failure HRESULT. Justify any catch inline.
- HRESULT translation from WPD (handle these explicitly):
  - `E_ACCESSDENIED` on `Open` → retry with `WPD_CLIENT_DESIRED_ACCESS=GENERIC_READ` (read-only mount).
  - `E_WPD_DEVICE_ALREADY_OPENED` → treat as already-open / contention; surface clean error.
  - device-gone / `WPD_EVENT_DEVICE_REMOVED` / transport-failed HRESULTs → invalidate caches, fail with a user-facing "device disconnected" (from `.rc`), let host relocate; do not log as an error.
  - `Delete` returns `S_FALSE` → at least one child failed; inspect `ppResults` per-object `VT_ERROR`.
  - `ERROR_DIR_NOT_EMPTY` / `ERROR_INVALID_OPERATION` from non-recursive delete on a non-empty folder → switch to manual depth-first or recursive option.
  - `ERROR_NOT_FOUND` → stale Object ID; re-resolve once via PUID/parent re-enum, then fail if still gone (no spin).
  - per-property `SetValues` `pResults` failure → property read-only on this device.
- ABI struct discipline: every `sizeBytes`/`version` struct — producer sets, consumer validates, `[out]` structs caller-initializes (`FileSystemOptions`, `FileSystemBasicInformation`, `FileSystemTransferHints`, `FileSystemStorageCharacteristics`, `FileSystemDirectorySizeResult`). Mismatch → `E_INVALIDARG`.

- Strings needed: plugin name (`IDS_FILESYSTEMMTP_NAME` — language-neutral, embedded), description (translated), the **"MTP" protocol-identity token** (`IDS_FILESYSTEMMTP_FSNAME` — language-neutral, embedded, used as `IDriveInfo` `fileSystem`; see below), "Disconnect" (translated), "Device disconnected" (translated), "Device is read-only" (translated), drive properties labels (translated), "Connect MTP device" (translated), storage-picker labels (translated), conflict prompts (translated), and the user-facing notices introduced in §11/§17 (each its own translated id; positional placeholders): "Plugin busy — unload deferred" (`IDS_FILESYSTEMMTP_UNLOAD_DEFERRED`), "Safe overwrite is not supported on this device" (`..._OVERWRITE_UNSUPPORTED`), "Temporary copy left as {0}" (`..._TEMP_COPY_LEFT`), "Recovered file as {0}" (`..._RECOVERED_AS_TEMP`), and the optional `deviceReread` "Verifying written data…" progress/notice (`..._EXTRA_VERIFICATION`).
- **Identity token vs user-facing word — explicit boundary.** The word "MTP" appears in two distinct roles and they use *different* string ids:
  - As a **protocol identity** (the `IDriveInfo` `fileSystem` field, the column value shown like "NTFS"/"exFAT"): this is `IDS_FILESYSTEMMTP_FSNAME`, **language-neutral, embedded-only, never translated** — a satellite must not localize "MTP" here, exactly as filesystem-type names are not localized. **This is a deliberate divergence from FileSystemS3/MicrosoftDrive**, which set `IDriveInfo.fileSystem = shortId`; we add a dedicated embedded token because `shortId` is the lowercase scheme `"mtp"` whereas the drive column should read uppercase `"MTP"` (like `"NTFS"`). If matching the other plugins' lowercase-`shortId` behavior is preferred instead, drop `IDS_FILESYSTEMMTP_FSNAME` + its §19.D allow-list entry and reuse `shortId` — but then the column reads `"mtp"`.
  - As **part of a translated sentence/label** (e.g. "Connect MTP device", "MTP device"): the surrounding label is a normal translated string in its own id; the embedded `_FSNAME` token is not reused inside those.
- Positional placeholders only: `{0}`, `{1}`, `{1:08X}`. No bare `{}`, no `%s`/`%d`. Source placeholders in argument order; `FormatStringResource(...)` args in matching order.
- Language-neutral tokens stay only in the embedded base `.rc`, loaded via `LoadEmbeddedStringResource(g_hInstance, ...)` (never `nullptr`), NOT duplicated into satellites. The complete embedded-only id set is: `IDS_FILESYSTEMMTP_NAME` (plugin display name used for `RegisterResourceOwner` matching) and `IDS_FILESYSTEMMTP_FSNAME` (the "MTP" protocol-identity token). Non-resource language-neutral literals (plugin id `builtin/file-system-mtp`, scheme `mtp`, WPD `PROPERTYKEY`/format GUIDs) are `constexpr` in code, not STRINGTABLE entries.
- Satellites: `Plugins/FileSystemMtp/Lang/<culture>/FileSystemMtp-<culture>.{rc,vcxproj}` for `cs-CZ, fr-FR, ja-JP, sk-SK`. Each satellite must be placeholder-equivalent to the source (may reorder for grammar; must not add/drop/duplicate/renumber/change format specs). DLL must be named `FileSystemMtp.dll` (owner name = DLL stem for `Localization::RegisterResourceOwner`).
- Run `Tools/Tests/ResourceLocalizationContracts.Tests.ps1` after any brace-bearing string change; add `'Plugins\FileSystemMtp' = @('IDS_FILESYSTEMMTP_NAME', 'IDS_FILESYSTEMMTP_FSNAME')` to its `Get-RSLanguageNeutralStringIdsByOwner` allow-list (every id loaded via `LoadEmbeddedStringResource`, not just the plugin name).

## 15. Virtual path & protocol-scheme design

- Scheme: `shortId = L"mtp"`; stable id `L"builtin/file-system-mtp"`. Drive display may show `mtp://<deviceKey>/<storageName>/...`, but the internal canonical plugin path is always slash-rooted.
- Accepted input forms normalize to one canonical path before resolution: `mtp:/<deviceKey>/...`, `mtp://<deviceKey>/...`, `/<deviceKey>/...`, and `/@conn:<profileName>/...`. `NormalizePluginPath` may preserve a leading `//authority` for generic protocols, but MTP resolution must collapse the scheme/authority form into `/<deviceKey>/...` and must not treat `//<deviceKey>` as a separate root.
- Canonical synthetic path: `/<deviceKey>/<storageName>/<dir>/.../<file>`.
  - `deviceKey` = the device segment (friendly-name-derived, disambiguated by device identity). Root path `/` = device list.
  - `storageName` = storage functional object name.
  - Remaining segments map to nested objects via `WPD_OBJECT_PARENT_ID` chain.
- Parsing reuses S3's helpers verbatim:
  1. `NormalizePluginPath`: backslash→`/`, ensure leading `/`, collapse duplicate slashes, preserve leading `//authority`; empty→`/`.
  2. `SplitPathSegments` → `[deviceKey, storageName, ...objectNames]`.
  3. Device resolution (replaces `ResolveAwsContext`): map `deviceKey` (or `/@conn:<name>/...` Connection-Manager prefix) → an `MtpDeviceContext` (open lazily); resolve segments → ObjectID by walking the parent chain via the path↔ID cache, fetching children on miss.
- Device-key grammar:
  - Base key = sanitized/percent-encoded friendly name, preserving display readability where possible.
  - If two live devices have the same base key, or the base key itself ends in a syntactically valid synthetic suffix token, append a device identity suffix: ` [devpuid:<percent-encoded-device-puid>]` when the device-object PUID exists; otherwise ` [devid:<percent-encoded-stable-hash-of-pnp-id>]` for the current machine/session only.
  - `devpuid` is durable and may be persisted in connection profiles; `devid` is a fallback navigation key only and must be revalidated on every open. Friendly name alone is never a durable identity when duplicates exist.
- Path↔ObjectID mapping strategy:
  - Cache `{ (parentObjectId, canonicalLeafToken) -> objectId }` and `{ objectId -> (parentObjectId, displayLeafName, PUID, volatileObjectId) }`, populated lazily per directory listing.
  - **Canonical display/path token**: `FileInfo.FileName` is the plugin path component the host will reuse. The suffix grammar below applies to **every** path component (device, storage, directory, file), not only to duplicate groups. For unique siblings, use the display/original file name as-is **unless that name would itself be misread as a synthetic suffix** — i.e. it already ends in a syntactically valid ` [puid:…]`/` [oid:…]`/` [devpuid:…]`/` [devid:…]` token per the grammar below — in which case percent-encode that literal trailing pseudo-suffix inside the stem before adding any real identity suffix. For duplicate siblings under the same parent according to the declared `pathIdentity.componentComparison`, return every colliding sibling with a synthetic suffix:
    - `name [puid:<url-escaped-puid>]` when `WPD_OBJECT_PERSISTENT_UNIQUE_ID` is available.
    - `name [oid:<url-escaped-objectId>]` only as a current-session fallback. `oid` tokens are invalidated on reconnect/device reset and MUST NOT be written into connection profiles, overwrite journals, or specs as durable identity.
  - **Suffix grammar is exact, reversible, and idempotent.** A synthetic suffix is recognized only at the end of the component and only in the form space + `[puid:<percent-encoded-utf8>]`, space + `[oid:<percent-encoded-utf8>]`, space + `[devpuid:<percent-encoded-utf8>]`, or space + `[devid:<percent-encoded-utf8>]`. Percent-encode every byte outside `A-Z a-z 0-9 - . _ ~`; decode only after validating the full suffix grammar. If a real device filename already ends with a syntactically valid suffix, **do not append another suffix to the already-encoded path text on re-enumeration**. Always encode from the raw WPD display name, percent-escape the literal suffix-looking tail in the stem, then append at most one real identity suffix when needed. The parser strips at most the rightmost recognized synthetic suffix and decodes the remaining stem as literal display text. Unit-test repeated enumerate→parse→enumerate stability for literal names containing `[puid:...]`, `%`, `]`, trailing spaces, and non-ASCII.
  - **No silent ambiguous resolution**: resolving an unsuffixed name that maps to multiple live children returns `HRESULT_FROM_WIN32(ERROR_OBJECT_NAME_COLLISION)` (or the nearest existing collision HRESULT) and raises a conflict where the caller supports one. Never pick "lowest ObjectID"; that mutates the wrong object under duplicate names.
  - `pathIdentity` for MTP is `ordinalCaseSensitive`, `normalization:"none"`, preferred/accepted separator `/`, `casePreserving:true`, and `caseOnlyRename:"supported"` only when the device accepts the rename; otherwise `"unsupported"`. The path text is stable for host planners because colliding siblings are encoded before the host sees them; if a directory cannot provide any stable/sessional disambiguator for a collision, list those entries as read-only/non-mutable and fail same-context mutation from that directory.
- Persistent identity across reconnect: persist `WPD_OBJECT_PERSISTENT_UNIQUE_ID` for the device object, storage roots, overwrite-journal entries, and any remembered targets. On reconnect/`WPD_EVENT_DEVICE_RESET`, drop the path↔ID cache and re-resolve PUIDs via `GetObjectIDsFromPersistentUniqueIDs` (empty string ⇒ object gone). Session-only `oid` suffixes fail after reconnect and force a refresh.

## 16. Device enumeration, connection, hotplug & UI surfacing

### Enumeration
- `IPortableDeviceManager` (CoCreate `CLSID_PortableDeviceManager`) — no `Open` needed. Two-pass `GetDevices(nullptr,&count)` then `GetDevices(ids,&count)`; each `PWSTR` is a CoTaskMem PnP device id (wrap `wil::unique_cotaskmem_string`). Metadata via `GetDeviceFriendlyName`/`GetDeviceManufacturer`/`GetDeviceDescription` (each two-pass; fall back to device-object `WPD_OBJECT_NAME` on failure). Treat the PnP id as opaque.

### `IPortableDeviceManager` apartment / instance ownership (no shared cross-apartment instance)
`CLSID_PortableDeviceManager` is created without the free-threaded marshaler, so a single instance shared across apartments would incur COM marshaling and cross-apartment calls. The manager is cheap (no `Open`, no device session), so we use **separate per-apartment instances** and never share one across threads:
- **(a) Connection Manager device picker** — owned by a **worker thread**, NOT the STA UI thread. Per the §11 rule "the UI thread (STA) never calls a device interface synchronously," the picker does not enumerate `IPortableDeviceManager` inline on the STA. Instead it posts an enumeration request to a worker (the DLL-global watcher's MTA apartment, or a short-lived `TrySubmitThreadpoolCallback` that `CoInitializeEx(COINIT_MULTITHREADED)`s for its duration), which CoCreates its own manager instance, enumerates `{pnpId, friendlyName}`, and **marshals the resulting plain-data list back to the STA picker UI** via `PostMessagePayload`/`TakeMessagePayload<T>`. The STA only ever touches the marshaled POD result, never a live WPD interface.
- **(b) Hotplug watcher** — the DLL-global watcher jthread (MTA, §16 Hotplug) owns its **own** `IPortableDeviceManager` instance for `RefreshDeviceList`/`GetDevices`. It is a distinct instance from (a); the two never alias.
- Both instances are created and released entirely within the apartment that owns them. Because the manager is stateless and cheap, holding two (or creating short-lived ones for the picker) costs nothing and avoids any apartment-crossing call on the device-manager object.

```cpp
wil::com_ptr<IPortableDeviceManager> mgr;
HRESULT hr = CoCreateInstance(CLSID_PortableDeviceManager, nullptr,
    CLSCTX_INPROC_SERVER, IID_PPV_ARGS(&mgr));
if (FAILED(hr)) return hr;
DWORD count = 0;
hr = mgr->GetDevices(nullptr, &count);                    // pass 1
if (FAILED(hr)) return hr;
std::vector<PWSTR> raw(count);
hr = mgr->GetDevices(raw.data(), &count);                 // pass 2 (caller owns strings)
if (FAILED(hr)) return hr;
for (DWORD i = 0; i < count; ++i) {
    wil::unique_cotaskmem_string id{ raw[i] };            // RAII free
    // friendly name (two-pass length/buffer), build {pnpId, friendlyName}
}
```

### Hotplug (device arrival/removal)
- v1 implementation choice: use `CM_Register_Notification` in the DLL-global watcher `std::jthread` so no plugin-owned hidden HWND/message pump is required. The callback only queues a refresh request to the watcher state, returns promptly, and never calls host UI directly. The watcher owns its MTA `IPortableDeviceManager`, calls `RefreshDeviceList()` + `GetDevices`, computes a plain-data device snapshot, and marshals UI refresh through the existing host/window payload path.
- If `RegisterDeviceNotification`/`WM_DEVICECHANGE` is chosen instead during implementation, the plan must be updated first with the message-only window owner, message loop, `wil::unique_any` notification handle, `InitPostedPayloadWindow`/`DrainPostedPayloadsForWindow`, and teardown sequence. Do not implement an implicit global HWND.
- Per-device WPD `IPortableDeviceEventCallback` (Advise) is used only as opportunistic object cache-invalidation + to catch `WPD_EVENT_DEVICE_REMOVED`/`WPD_EVENT_DEVICE_RESET` (tear down session). NOT used for device arrival/removal of the device itself.
- Mid-operation removal: device-gone HRESULT → invalidate caches, fail clean (user-facing `.rc` message), host relocates pane.

### UI surfacing
- Appears as a drive via `IDriveInfo::GetDriveInfo` (friendly name, "MTP", per-storage capacity).
- Navigated via the `mtp:/` scheme or a persisted `/@conn:<name>/...` Connection-Manager entry resolved in path parsing.
- `INavigationMenu::GetMenuItems` pushes device/storage roots; `NavigationMenuRequestNavigate(path, cookie)` drives pane navigation.
- Disconnect/Properties via `GetDriveMenuItems`/`ExecuteDriveMenuCommand`.

## 17. File operations design + data-safety

### Read (download)
- `content->Transfer(&resources)`; `resources->GetStream(objectId, WPD_RESOURCE_DEFAULT, STGM_READ, &optimal, &src)`; loop `IStream::Read` in `optimal`-size chunks (fallback 256 KB) until 0 bytes; poll cancel; release `src` to cancel.

### Write (upload) — the core constraint
```cpp
// Public CreateFileWriter always stages first; this helper runs only after size is known.
wil::com_ptr<IPortableDeviceValues> props;
HRESULT hr = CoCreateInstance(CLSID_PortableDeviceValues, nullptr, CLSCTX_INPROC_SERVER, IID_PPV_ARGS(&props));
if (FAILED(hr)) return hr;
hr = props->SetStringValue(WPD_OBJECT_PARENT_ID, parentObjectId);
if (FAILED(hr)) return hr;
hr = props->SetStringValue(WPD_OBJECT_NAME, leafName);                       // full leaf, including extension
if (FAILED(hr)) return hr;
hr = props->SetStringValue(WPD_OBJECT_ORIGINAL_FILE_NAME, leafName);          // same full leaf unless a device requires otherwise
if (FAILED(hr)) return hr;
hr = props->SetUnsignedLargeIntegerValue(WPD_OBJECT_SIZE, totalBytes);        // MUST be known
if (FAILED(hr)) return hr;
hr = props->SetGuidValue(WPD_OBJECT_CONTENT_TYPE, WPD_CONTENT_TYPE_GENERIC_FILE);
if (FAILED(hr)) return hr;
hr = props->SetGuidValue(WPD_OBJECT_FORMAT, WPD_OBJECT_FORMAT_UNSPECIFIED);
if (FAILED(hr)) return hr;

DWORD optimal = 0;
wil::com_ptr<IStream> dst;
hr = content->CreateObjectWithPropertiesAndData(props.get(), &dst, &optimal, nullptr);
if (FAILED(hr)) return hr;
// write EXACTLY totalBytes in optimal chunks; poll cancel BEFORE Commit
for (each chunk) { hr = dst->Write(p, n, &written); if (FAILED(hr)) return hr; }
if (cancelRequested) { static_cast<void>(dst->Revert()); return HRESULT_FROM_WIN32(ERROR_CANCELLED); }
hr = dst->Commit(STGC_DEFAULT);                                             // object created only now
if (FAILED(hr)) return hr;
wil::com_ptr<IPortableDeviceDataStream> ds;
hr = dst.query_to(&ds);
if (FAILED(hr)) return hr;
wil::unique_cotaskmem_string newId;
hr = ds->GetObjectID(&newId);
if (FAILED(hr)) return hr;
```
- Public writer: `IFileWriter::Write` appends to a `wil::unique_hfile` temp; `Commit` then knows size and performs the create-and-stream above; release-without-`Commit` discards the temp and never opens a WPD create stream.
- **`pdwOptimalWriteBufferSize` (and `GetStream`'s `pdwOptimalBufferSize`) are `[in,out]`, not pure `[out]`.** WPD may read an input hint and writes back the optimal chunk; initialize to 0 (or a sane hint), then use the returned value as the chunk size. Do not treat it as write-only.

### mkdir
- `CreateObjectWithPropertiesOnly(props, &newFolderId)` with `WPD_CONTENT_TYPE_FOLDER` and both name properties.

### delete (recursion)
- Build `IPortableDevicePropVariantCollection` of `VT_LPWSTR` ids; `Delete(option, col, &results)`. Recursion option iff `WPD_OPTION_OBJECT_MANAGEMENT_RECURSIVE_DELETE_SUPPORTED`; else manual depth-first (enumerate children, delete leaves first). `S_FALSE` ⇒ inspect `results`.

### rename / move / copy with capability fallback
- rename: `SetValues` both name props; check `pResults`.
- move: native `Move` iff `WPD_COMMAND_OBJECT_MANAGEMENT_MOVE_OBJECTS`; else download→upload→delete.
- copy: native `Copy` iff `WPD_COMMAND_OBJECT_MANAGEMENT_COPY_OBJECTS`; else download→upload.

### Data-safety (no silent overwrite / no data loss / whole-object constraint)
- **No silent overwrite**: if destination exists and `FILESYSTEM_FLAG_ALLOW_OVERWRITE` is not set, raise `FileSystemIssue` (one-shot grant) or return `ERROR_ALREADY_EXISTS` (file-vs-file). Never overwrite without a host decision.
- **Overwrite is destructive (delete-then-create, non-atomic)**: sequence — **(0)** write a durable journal *intent* entry (`phase: planned`, with `intendedFinalName` and a **random-GUID** temp-leaf token, e.g. `.rs-mtp-<GUID>.<ext>`, guaranteed unique at creation) *before* creating anything, so a crash at/after Commit can never orphan an untracked temp; **(1)** upload new bytes under that **collision-proof temp leaf name** in the destination folder; **(2)** `Commit`, then re-read the temp object's `WPD_OBJECT_PERSISTENT_UNIQUE_ID` and verify (level per `operations.byteVerifyOnOverwrite`, see below) — **a non-empty `tempPuid` is a hard precondition for step (3)**; **(3)** delete the old object; **(4)** rename temp → final name. If any step fails before (3), delete the temp and leave the original intact. This guarantees we never end with a half-written object or two same-named final siblings. The byte-integrity check in (2) is the MTP analogue of the *local* compare in `ee2786351 fix(fileops): verify bytes before suppressing overwrite` (that commit byte-compares two **local** file handles to suppress a redundant overwrite — it does **not** re-read a written remote object); see the byte-verification model below for the honest MTP definition.

- **Overwrite journal (closes every crash window, not just steps 3→4).** A crash/disconnect can strand a temp object at several points; the journal must cover all of them, including the one a naive design misses (crash *after* Commit but before the original is deleted → an orphan temp). The intent entry is written at **step (0)**, before anything is created, so no committed temp is ever untracked.
  - **What is recorded** (one entry per in-progress overwrite): `{ schemaVersion, devicePuid, parentPuid, tempLeafToken, intendedFinalName, originalPuid, tempPuid, declaredSizeBytes, sourceTransmitHashHex, journalTimestampFileTimeUtc, phase, diagnosticTempObjectId, diagnosticOriginalObjectId }` where `phase ∈ {planned, uploaded, committed, original-deleted}`. `declaredSizeBytes` and `journalTimestampFileTimeUtc` are required because the orphan sweep uses them; omitting either is a spec bug. Session-scoped object IDs are **diagnostic-only** and MUST NOT be relied on by recovery (they are invalid after reconnect).
  - **Where it lives**: **host-side**, NOT on the device (the device has no reliable scratch store and may be read-only for metadata). Persisted under `%LOCALAPPDATA%\RedSalamander\PluginState\FileSystemMtp\<hash(devicePuid)>\overwrite-journal.json` (multiple independent entries; one file per device) written with create-temp/write/flush/rename atomic-replace semantics via `wil::unique_hfile`. The entry advances `planned → uploaded → committed → original-deleted` and is deleted only after step (4) succeeds.
  - **Journal mutation is serialized (no lost-update race).** All read-modify-write of the per-device journal file — add/advance/clear entries, and recovery-on-`Open` — runs only on that device's worker (MTA) thread under a per-device journal `std::mutex`. Atomic-replace makes each individual write crash-safe, but only single-threaded RMW prevents the classic lost-update that would drop one of two concurrent overwrites (different folders, same device) and leave an untracked orphan temp — the exact window the journal exists to close.
  - **Journal write must be durable or the overwrite does not proceed.** If the step-(0) intent entry cannot be made durable (disk full, `%LOCALAPPDATA%` unwritable), **fail the overwrite** with the underlying error and do not touch the device — never reopen the crash window by proceeding journal-less.
  - **`tempPuid` precondition guards against data loss.** Before step (3) deletes the original, the committed temp MUST have a non-empty `tempPuid` (re-read after Commit). Track a per-device `createdObjectPuidPolicy = unknown | supported | unsupported`. If the policy is `unsupported`, overwrite preflight fails with `ERROR_NOT_SUPPORTED` / localized notice **before uploading anything**. If the policy is `unknown`, the first temp upload may act as the probe; if the committed temp has an empty PUID, delete that temp by the current-session object ID immediately, mark the policy `unsupported`, clear the journal, leave the original intact, and surface that safe overwrite is unsupported on this device. If the cleanup delete fails, surface a "temporary copy left as `<tempLeaf>`" notice **once and clear the entry** (the temp is left under its harmless random-GUID name; the original is intact — there is no destructive recovery to defer). Do not repeatedly upload temp copies on later overwrite attempts once the device is known PUID-less (`createdObjectPuidPolicy = unsupported`). This prevents the failure mode where the original is deleted but the new version cannot be re-found on recovery (silent data loss).
  - **Recovery on next `Open`** (per matched `devicePuid`), running on the device worker (MTA) thread before the first user-visible op, by **PUID only** (`GetObjectIDsFromPersistentUniqueIDs` + parent re-enum; never stale object IDs):
    - `phase == original-deleted` and `tempPuid` present: finish the rename `tempLeaf → intendedFinalName` (step 4). If the device **rejects** the rename (read-only name prop), retry up to a small bounded count across opens; on exhaustion, surface a localized "recovered as `<tempLeaf>`" notice, leave the data under the temp name, and clear the entry (terminal state — never infinite-retry).
    - `phase == original-deleted` and `tempPuid` missing: treat the journal as corrupt or the device as PUID-hostile after the destructive boundary. Do **not** blind-delete anything. Sweep only for manual diagnostics using `tempLeafToken` + size + timestamp, surface a localized manual-recovery notice, keep the entry until the user/plugin can resolve it, and log once with `Debug::Warning`. Step (3) is gated on non-empty `tempPuid`, so this branch should be unreachable in healthy code and must be self-tested as a corrupt-journal path.
    - `phase ∈ {planned, uploaded, committed}` and original present with `tempPuid` present: roll back — delete the temp if it exists, leave the original intact, clear the entry.
    - `phase ∈ {planned, uploaded, committed}` and original present with `tempPuid` missing: crash occurred before recording the committed temp PUID, or the device omitted it. Sweep the parent by **random-GUID `tempLeafToken` + streamable/plugin-created temp object type + `declaredSizeBytes` + timestamp at/after `journalTimestampFileTimeUtc`**. If exactly one candidate matches, delete it and clear the entry; if zero or more than one match, delete nothing, surface for manual resolution, and keep the entry. The original remains intact in all outcomes.
    - Both temp and original PUIDs missing (double failure / user intervention): perform the same typed orphan sweep, but **never blind-delete by name** — MTP sibling names are not unique (§6 item 7, §15). Delete only if **exactly one** candidate matches; if zero or more than one match, delete nothing, surface for manual resolution, and keep the entry. Log once with `Debug::Warning`.
  - Recovery and the orphan sweep are normal control-flow — not logged as errors.
- **Byte-verification model (honest definition — no false `ee2786351` parity).** `ee2786351` compares two **local** handles (source vs. an already-present local destination) to *suppress a redundant overwrite*; it never re-reads a written remote object. MTP has no cheap local destination to compare against, so we define three explicit levels in the `GetCapabilities` `"operations".byteVerifyOnOverwrite` key — `"sizeOnly"` | `"transmitHash"` | `"deviceReread"`:
  - `"transmitHash"` (**v1 default for overwrite**) — while streaming, hash the bytes we send and compare to a hash of the local source, then confirm the post-`Commit` `WPD_OBJECT_SIZE`. **Zero extra transfer.** Be precise about what this proves: it is **LOCAL integrity only** — that our read of the source was self-consistent, we transmitted exactly those bytes, and the device accepted the declared length. Because *we* set `WPD_OBJECT_SIZE` up front, the post-`Commit` size echo adds little device-side assurance: **for device-stored integrity, `transmitHash` is no stronger than `sizeOnly`** — neither can detect silent device-side truncation/transcoding. Only `deviceReread` proves the device actually persisted the bytes.
  - `"deviceReread"` (**opt-in**, `extra.verifyDeviceReread = true`) — additionally re-download the committed object end-to-end and hash-compare to the source before deleting the original. This is the only level that catches device-side persistence faults, justified by **untrusted device commit** (NOT by `ee2786351`). It costs a full extra whole-object MTP download (§4, §6 item 3, §10.3): advertise high metadata/latency through `GetTransferHints`, but do **not** claim the current host can show a special decline UI from that key. Until a host UI change exists, the plugin owns progress text, cancellation polling, and any localized "extra verification" notice via the normal `IFileSystemCallback` path. Bill the round-trips into `mtp.verify.*` / `mtp.transfer.*`.
  - `"sizeOnly"` — confirm only the post-`Commit` size. Weakest; permitted only for a *new* (non-overwrite) write where there is no original to lose.
  - **Verify input per write path (the hash needs a meaningful input):**
    - *Public staged-writer `Commit`* and *local-source upload*: the temp/local file IS the source, so `transmitHash` (local) is meaningful.
    - *Move/copy download→upload fallback*: the "source" is a just-downloaded temp, so hashing it is **circular** — it only proves the temp round-tripped, not that the original device bytes were read or re-stored correctly. On this path only `deviceReread` (or trusting the device `Commit`) is meaningful; `transmitHash` adds nothing over `sizeOnly`.
    - *Device-/remote-source overwrite*: there is no local source pass to hash — stage the source to a temp first (then it reduces to the staged-writer case) or use `deviceReread`.
  - **v1 decision (load-bearing):** ship `byteVerifyOnOverwrite: "transmitHash"` as the overwrite default — it adds local-read integrity over `sizeOnly` at zero extra transfer, **but it is not a device-storage guarantee and must not be described as one.** Delete-old (step 3) gated on `transmitHash` therefore guarantees only that we sent the correct bytes and the device accepted the declared length — not that the device stored them; treating a successful MTP `Commit` as authoritative is an accepted v1 trade for the common case. Users who require device-stored integrity opt into `"deviceReread"` (the only level that re-reads the device). Delete-old happens only after the active level's check passes **and** the `tempPuid` precondition holds. Do **not** make a full device re-read mandatory by default, and do **not** justify any level as `ee2786351` parity.
  - **Host/parser status:** current host capability parsing does not consume `operations.byteVerifyOnOverwrite`; v1 emits it as forward-compatible plugin-owned metadata and proves it with self-tests. Do not rely on host UI behavior from this key until a host parser/UI change is added.
- **The advertised level MUST match the code path actually executed** (acceptance gate in M2 + self-test `mtp_overwrite_byte_verify_level_matches_capability`, §18 / §21).
- **Read-only mode** honored end-to-end at **two gates** (defense in depth — not a single choke point, because the staged writer defers its device write to `Commit`): (a) the public `CreateFileWriter` rejects at **entry** with `ERROR_WRITE_PROTECT` before returning a writer (fail fast — so a R/O profile never lets the host stream gigabytes to temp then fail late); and (b) the device-worker command-queue **enqueue** rejects any *mutating* command, so no entry point can bypass it at the device boundary. The full gated surface: `CreateFileWriter`/`Commit`, `CreateDirectory`, `DeleteItem(s)`, `RenameItem(s)`, `MoveItem(s)`, `CopyItem(s)` (when this device is the destination), `SetFileBasicInformation`, and the overwrite swap. Each returns `ERROR_WRITE_PROTECT` (or `ERROR_ACCESS_DENIED`) before any WPD write call, and capabilities advertise those operations `false` for a read-only profile. (`Disconnect` is a session release, not a device mutation, and is allowed.)
- **Move/rename are metadata-only** when native support exists (no re-stream); the download→upload fallback is used only when the device lacks native move/copy, and that path still follows the temp-name-then-swap safety sequence.

## 18. Capabilities discovery & feature gating

- Probe at session open via `IPortableDeviceCapabilities`:
  - `GetSupportedCommands` → gate `Move`/`Copy`/`UpdateObject`.
  - `GetCommandOptions(WPD_COMMAND_OBJECT_MANAGEMENT_DELETE_OBJECTS, ...)` → `WPD_OPTION_OBJECT_MANAGEMENT_RECURSIVE_DELETE_SUPPORTED`.
  - `GetFunctionalObjects(WPD_FUNCTIONAL_CATEGORY_STORAGE)` → storages.
  - `GetSupportedContentTypes` → folder/generic-file support.
  - For each listed object, classify readable files by **streamability**, not by `WPD_CONTENT_TYPE_GENERIC_FILE` alone: non-folder/non-storage objects that expose `WPD_RESOURCE_DEFAULT` and a size are byte-readable through `CreateFileReader`; known media content types are therefore valid read-only/read-write files when streamable. Non-streamable functional/metadata objects are listed read-only (or skipped if useless) and `CreateFileReader` returns `ERROR_NOT_SUPPORTED`.
  - `GetSupportedEvents` → whether any change-notification is even plausible (informs the watch deferral).
  - QI `IPortableDeviceProperties` → `IPortableDevicePropertiesBulk` (bulk fetch availability).
- "Discover, then enable" applies to **native WPD command paths**, not to the host-facing operation booleans when a safe fallback exists. No native Move/Copy/recursive-delete call without confirmed support; every optional native path has a fallback or an advertised/method-level unsupported result.
- `GetCapabilities` is generated per `FileSystemMtp` instance from profile policy + stable plugin semantics and returned through the two-slot per-method JSON buffer (§10.7). It is not a single DLL-global static string, and it must not report `write=false`/`copy=false`/`move=false` merely because the lazy WPD session has not been opened yet. The pre-`Initialize` or invalid-profile document is conservative read-only (`read=true`, `write=false`, mutations false) so the mandatory ABI is still satisfied. After `Initialize`, a writable profile advertises the operations the plugin can attempt safely: `read=true`, `write=!readOnly`, `copy/move=true` when writable because fallback transfer exists, `delete/rename=true` when writable with per-method WPD failure mapping, `recycle=false`, `randomWrite=false`, `search=false`, `watch=false`, concurrency 1, and complete `crossFileSystem`/`pathIdentity`. The first real operation opens/probes the device and chooses native-vs-fallback; if the device opens read-only or rejects a mutation, the operation fails cleanly and capabilities are rebuilt to read-only for subsequent calls.
- `pathIdentity` is always present. For MTP v1 it declares `ordinalCaseSensitive`, `normalization:"none"`, `preferredSeparator:"/"`, `acceptedSeparators:["/"]`, `casePreserving:true`, and `pathTextStableIdentity:true` only if duplicate sibling display names are encoded in returned path components. If an implementation cannot guarantee encoded duplicate components, it must emit `pathTextStableIdentity:false`, which will fail-close same-context mutation; do not ship that as the final v1 behavior.
- **`operations.byteVerifyOnOverwrite` must equal the verify level the overwrite code actually performs** (§17): v1 ships `"transmitHash"`, so the overwrite path MUST hash the transmitted source bytes and confirm the post-`Commit` size before deleting the original, and MUST NOT perform a device re-read unless the profile opted into `"deviceReread"`. This pairing is enforced by acceptance and a self-test (§21 `mtp_overwrite_byte_verify_level_matches_capability`): the test parses the advertised value and asserts the corresponding code path ran via the `FakeMtpBackend` round-trip counter — `"deviceReread"` performs an extra full re-read download before delete-old; `"transmitHash"` performs **no** re-read; `"sizeOnly"` checks size only. A mismatch is a build-failing test, not a runtime warning.

## 21. Testing strategy

### Seam (single most important testability decision)
- Internal `IMtpBackend` interface behind which all `IPortableDevice*` calls sit. Production = `WpdMtpBackend`. Tests inject `FakeMtpBackend` (in-memory seeded object tree, configurable per-call latency + fault injection: device-busy, object-locked, disconnect-mid-enumeration/transfer; **counts WPD round-trips** for batching assertions).
- **`FakeMtpBackend` is the sole REQUIRED device-less harness for M0–M3 acceptance.** Every milestone gate in §23 and every non-gated self-test in this section binds to `FakeMtpBackend`. No milestone gate depends on `RecordedMtpBackend`.
- **`RecordedMtpBackend` is an explicit M4+ stretch item** (capture-and-replay of a real device), specified here so it is buildable but not load-bearing:
  - **Recording tap point**: a passthrough decorator `RecordingMtpBackend : IMtpBackend` that wraps the live `WpdMtpBackend`, forwards every call, and appends a record `{ seq, method, argsDigest, resultHresult, outPayloadDigest-or-bytes, latencyUs }` for each `IMtpBackend` call. Because the seam is `IMtpBackend` (not raw `IPortableDevice*`), the tap is one wrapper at exactly one boundary — it cannot drift from the production call surface.
  - **Trace format**: a checked-in JSON document (`Tests/.../mtp-traces/<device-class>.json`) — `{ "schemaVersion": 1, "imtpBackendAbiHash": "<hash>", "calls": [ ... ] }`. Object-content blobs are stored inline (small fixtures) or as sibling binary files referenced by digest; all traces are scrubbed of personal data (§22).
  - **Determinism / replay binding**: `RecordedMtpBackend` loads a trace and answers each `IMtpBackend` call by matching `(method, argsDigest)` in sequence, returning the recorded HRESULT + payload (and optionally replaying `latencyUs` for perf realism). A self-test binds it exactly like `FakeMtpBackend` through `RedSalamanderMtpCreateForSelfTest(...)` / `SelfTest::CreateMtpFileSystemForSelfTest(...)`.
  - **Sync-on-`IMtpBackend`-change**: the trace embeds `imtpBackendAbiHash` (a hash of the `IMtpBackend` method signatures). `RecordedMtpBackend` refuses to replay (and the test `Skip`s with a reason) when the hash mismatches, so an interface change can never produce a silently-stale green — it forces a re-capture rather than rotting unnoticed.

### Pure local / deterministic tests (no device, no network)
- path-segment ↔ ObjectID resolution; duplicate-name suffix format/parse round-trip for `puid:` and session-only `oid:`; unsuffixed ambiguous path fails closed; WPD-property → `FileInfo` mapping; capabilities/schema JSON validity (`version:1`, required blocks, non-empty, per-instance read-only/mutation toggles); non-file-object classification; ABI `sizeBytes` set/validate; public writer stages before WPD create; data-safety overwrite sequence (no half-write / no duplicate final sibling under injected mid-`Commit` failure).

## 22. Security & data-safety considerations

- No credentials/secrets: MTP has none; do not add a secret kind. If a device PIN/unlock is ever required, route through the existing `IHostConnections` prompt path; never persist device contents or PINs.
- Recorded test fixtures must be scrubbed of any personal data; treat them like the remote-credentials security model (no secrets checked in).
- Temp staging files (unknown-size uploads, emulated edit/move/copy, backward-seek buffering) created in the host temp area with `wil::unique_hfile`; deleted on `Commit`/abort/release. **Pre-flight a free-space check** (`GetDiskFreeSpaceEx`) against the staged size before staging, and note that the `"deviceReread"` verification opt-in can hold up to ~2× the object size locally (staged temp + re-read buffer) — **stream the re-read comparison** rather than materializing a second full copy. Surface a clean error if the temp write or space check fails.
- Read-only profiles enforced before any device mutation.
- Data-safety overwrite sequence (§17) is the load-bearing guarantee: no half-written objects, no duplicate same-named siblings, **local transmit-hash verification before deleting the original** (which proves we sent the correct bytes and the device accepted the declared size — NOT that the device stored them; device-storage integrity requires the opt-in `byteVerifyOnOverwrite:"deviceReread"`), a **non-empty `tempPuid` precondition** that prevents deleting the original when the new version cannot be re-found, and a host-side overwrite journal (intent recorded before `Commit`, serialized RMW, PUID-only bounded recovery, GUID-token typed orphan sweep) that recovers the temp→final rename or rolls back across **every** crash window.

## 24. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Single-session transport; false parallelism degrades/fails | Concurrency caps = 1; per-device global gate; `mtp_concurrency_is_serialized` test. |
| Object IDs invalid across reconnect | Persist PUIDs; re-resolve via `GetObjectIDsFromPersistentUniqueIDs`; drop path↔ID cache on reconnect/`WPD_EVENT_DEVICE_RESET`. |
| Whole-object write / size-up-front | Buffer unknown-size to temp; declare `randomWrite:false`; "replace whole file" semantics. |
| Overwrite is destructive (delete+create, non-atomic) | Temp-name → transmit-hash verify (optional device re-read) → delete-old (gated on non-empty `tempPuid`) → rename swap; host-side overwrite journal (intent before `Commit`, PUID-only bounded recovery) recovers the rename or rolls back across every crash window; never half-write, duplicate, or delete the original when the new version can't be re-found. |
| Mandatory full re-read makes overwrites unusably slow | Default `transmitHash` verification is zero-extra-transfer; full device re-read is opt-in only. The false `ee2786351` "parity" justification (which would have forced a re-read) is dropped. |
| Move/Copy unsupported on many devices | Capability-gate; download/upload(+delete) fallback; cross-storage move = full re-upload. |
| Fallback move upload succeeds but source delete fails | Return partial/specific failure, leave both source and destination, and surface the duplicate-left state; never claim success and never roll back the destination destructively. |
| Enumeration slow (per-object round-trips) | Lazy per-dir; `IPortableDevicePropertiesBulk` with fallback; round-trip-count metric to prove batching. |
| Duplicate sibling names / case collisions | All colliding siblings get `puid:`/session `oid:` suffixes before the host sees paths; suffix escaping is raw-name-based and idempotent; unsuffixed ambiguous paths fail closed. Never choose an arbitrary ObjectID. |
| Duplicate/suffix-like device names | Device keys append `devpuid:` or session `devid:` identity suffixes; accepted `mtp:/`, `mtp://`, slash-rooted, and connection paths normalize to one canonical form. |
| WPD events lossy/coarse | No real-time watch in v1; events used only as cache-invalidation hints; poll/refresh model. |
| Device hot-plug mid-operation | `CM_Register_Notification` + `RefreshDeviceList`; device-gone HRESULT → clean fail + host relocate; quiet-point teardown. |
| Device wedges — WPD call never returns (no timeout) | Per-command watchdog/deadline → `IPortableDeviceContent::Cancel`/stream-release; secondary deadline → session declared dead, op fails device-gone, worker **never blindly joined** (avoids host-thread deadlock); if still live, worker enters quarantined state and `CanUnloadNow()==FALSE`. `mtp_hung_device_times_out` test. |
| Unload-during-callback/runtime refresh | Runtime refresh calls `RedSalamanderPluginShutdown()` then optional `RedSalamanderPluginCanUnloadNow()`. If FALSE, manager keeps the module/resource owner registered, marks unload-deferred, skips same-path reload, and retries later. Process-exit retain vote is separate and not used for refresh. |
| Timestamps unwritable/missing | Tolerate missing dates; `SetFileBasicInformation` returns `ERROR_NOT_SUPPORTED`/mapped failure when rejected; never fail upload on timestamp set. |
| Access-denied / read-only devices | R/W→R/O `Open` fallback; read-only mount surfaced cleanly. |
| Driver quirks across vendors | Probe-then-use-else-fallback for every optional capability; recorded fixtures from multiple devices. |
| Testing without a device | `IMtpBackend` seam + `FakeMtpBackend` (required, gates M0–M3) injected only via `RedSalamanderMtpCreateForSelfTest(...)`; M4+ `RecordedMtpBackend` capture/replay; gated live smoke. |
| Fake-backend timing gives false confidence | Fake backend gates byte/chunk/progress/call counts and serialization only; live or recorded latency is required for throughput claims. |
| JSON return storage grows with browsed items | Two-slot per-method `JsonReturnBuffers`; no LRU ring and no retained `std::list` per item. |
| `catch(...)` / detached threads creeping in | Code review + standards; named exceptions only; `jthread`/`TrySubmitThreadpoolCallback` + explicit quarantine state for unjoinable workers. |

## 25. Decisions locked for v1

1. **Watch (`IFileSystemDirectoryWatch`)**: omitted; QI fails. Host refresh/poll is the v1 freshness model. Synthetic post-mutation notifications are a later-version feature, not v1 scope.
2. **Non-file objects**: list read-only when they have useful metadata; skip write/overwrite and return `ERROR_NOT_SUPPORTED` for byte-stream operations.
3. **Multi-storage**: expose each storage as a navigable root under the device. A profile may store a default storage, but it does not hide other storages.
4. **`SetFileBasicInformation`**: best-effort write, but no success-no-op. Return `S_OK` only when requested writable fields were actually accepted.
5. **`GetDirectorySize`**: implement with cancellation/progress and `HIGH_METADATA_COST`; keep a focused perf/test gate. Revisit only if evidence shows it is user-hostile on common devices.
6. **Host C++ requirement**: required for v1 because the Connection Manager protocol list and visibility rules are code-defined today.
7. **Device identity key**: `extra.devicePuid` is primary; `ConnectionProfile.host` stores the current PnP id as a required schema hint; friendly name is display/fallback only.
8. **Path identity**: MTP declares `ordinalCaseSensitive`; duplicate sibling path components are disambiguated before exposure. Ambiguous unsuffixed mutation fails closed.
9. **Public writer**: always staged-to-temp; no direct WPD create stream before `Commit`.
10. **Overwrite verification**: default `byteVerifyOnOverwrite:"transmitHash"` (hash transmitted bytes + post-`Commit` size; zero extra transfer) — this is **LOCAL integrity only**, no stronger than `sizeOnly` for device-stored bytes, and must not be presented as a device-storage guarantee. `"deviceReread"` (full re-download compare) is the only device-storage guarantee and is a per-profile opt-in for untrusted devices. For the download→upload move/copy fallback, `transmitHash` over the temp is circular → only `deviceReread` is meaningful there. No mandatory device re-read; the `ee2786351` "parity" framing is dropped (that commit compares local handles only).
11. **Hung-device handling**: every device command carries a watchdog deadline; on timeout the session is declared dead and the op fails device-gone. A wedged worker is never blindly joined; it is quarantined, host pointers are cleared, and `CanUnloadNow()==FALSE` prevents unsafe runtime unload/reload.
12. **Runtime-refresh teardown**: the module retain-vote protects process exit only. Runtime refresh uses `RedSalamanderPluginCanUnloadNow()` plus `FileSystemPluginManager` unload deferral; `FreeLibrary` and same-path reload happen only after the plugin reports no live work. The reversible module keepalive is owned and released by the quarantine context/sweeper, not by the worker thread returning through DLL code.
13. **Overwrite journal**: intent recorded *before* `Commit`; recovery is PUID-only and bounded; delete-old is gated on a non-empty `tempPuid`; a step-0 journal-write failure aborts the overwrite without touching the device.
14. **Fake-backend injection**: injected self-tests use `RedSalamanderMtpCreateForSelfTest(...)` / `SelfTest::CreateMtpFileSystemForSelfTest(...)`, never the production manager-owned `SelfTest::GetFileSystem(...)`.
15. **JSON return buffers**: all JSON-returning methods use two-slot per-method `JsonReturnBuffers`; no LRU ring and no retained list.
16. **Path normalization**: accepted `mtp:/`, `mtp://`, slash-rooted, and connection-manager paths normalize to one canonical slash-rooted path; duplicate/suffix-like device names use `devpuid:` / `devid:` suffixes.
17. **Fake perf scope**: fake-backend timing is not throughput evidence. Device-less perf gates use round-trip/call/byte/progress counters; production throughput/latency claims require live or recorded latency before citation.
18. **Live smoke safety**: live-device writes run only in an explicit scratch folder and never delete a pre-existing non-empty user folder.
