## 3. Verified current behavior that constrains the design

These statements were re-derived from code by at least two independent readers and are the premises of every requirement below.

- **Severity model.** `DiagnosticSeverity {Debug, Info, Warning, Error}` (`FolderWindow.FileOperationsInternal.h:850-856`). `EnqueueTaskDiagnostic` counts only Warning/Error, installs the entry as `_taskLastProblem`, and admits only Warning/Error/decision/result entries to the per-task Issues reservoir (`State.Diagnostics.cpp:1524-1555`). `QualifyIssueFacts.originalProblem` requires Warning/Error (`:45-46`); `ProjectsRow() = originalProblem || acceptedDecision || conflictResult` (`FileOperationsInternal.h:1006-1009`). `TrimIssueReservoir` evicts non-row Info/Debug first, then orphan decision/result rows, then the oldest original problems (`:286-335`); per-task cap 128, global 256 (`State.Private.h:175-176`). The Issues pane labels every original row Warning or Error and has no Info caption for an original row (`IssuesPane.cpp:697`). Accepted-decision/result records are Info, bypass the Info gate, never count and never replace the Last note (`:1481-1485`, spec `UI_FileOperationsPopup.md:2146-2160`).
- **Completion summary.** `RecordCompletedTask` copies the counts, synthesizes `warningCount=1` for `ERROR_PARTIAL_COPY`, for a consumed clipboard cut list with retained sources, and for a cancel with indeterminate items; `errorCount=1` for other failures (`State.Diagnostics.cpp:1896-1998`). `cleanCompletion` requires `S_OK` and zero counts (`:2067`). A canceled task with only known axes is designed to end with zero synthesized warnings (`:1942-1966`); only the prompt-shown Warning defeats it.
- **Auto-dismiss.** `IsAutoDismissableFileOperationCompletion` returns false for any count, true for a cancellation, else `SUCCEEDED` (`State.Runtime.cpp:405-419`); applied at `FolderWindow.FileOperations.cpp:5167-5172`. `autoDismissSuccess` defaults false (`Common/SettingsStore.h:351`) and the single toggle covers success and canceled (rc:1957-1958, 2548-2549). Completed history is capped at 24 (`State.Private.h:174`). `SetAutoDismissSuccessInSettings` hard-codes the false default (`State.cpp:2842-2855`); flipping the default requires fixing that setter.
- **Discovery.** Host closes a root only on a `traversalClosed` report not under `deferDiscoveryClosure`, or through the per-item terminal guard when the root's executor returns (`State.cpp:8291-8294`, `21063`), and unconditionally after `ExecuteOperation` (`:10638-10639`). `FileSystemGetDiscoveryMode` returns AHEAD until closed or skipped (`:8193-8202`). `SkipDiscovery` never closes (`:8113-8138`). `FileOps.Discovery.GrowthAfterClose` must stay 0 (spec `FileSystem_FileOperations.md:681-683`). Exact Local permanent Delete must contribute the root's bytes and one mutation **before** closure (spec `:648-654`; test `Tests.Phases05_06.cpp:4656-4659`) and is out of scope for section 6.
- **Routes.** `destinationFileSystem` is null when both panes share plugin + instance context (`FolderWindow.FileOperations.cpp:3364-3366`); `useCrossFileSystemBridge = destination fs != null || hasManagedMovePlans || hasVerificationPlans` (`State.cpp:19723-19724`). Admission qualifies pairs by endpoint tuple while execution keys on pane object identity (XP-09). Only `Plugins/FileSystem` implements `IFileSystemBoundMetadata` and `IFileSystemObjectBinding`; no provider-to-host metadata outcome channel exists in the ABI (`Common/PlugInterfaces/FileSystem.h:102-108`, `700-707`).
- **Artifact guard.** Name-shape classification is deliberately non-authoritative; a Possible item that cannot supply an exact identity cannot mint a Continue receipt (spec `FileSystem_FileOperations.md:2130-2136`, `UI_FileOperationsPopup.md:1238-1241`). Any change in section 7 is therefore a **spec change with a data-safety rationale**, not a bug fix.
- **Prompts.** The arbiter is generation-keyed; `ConflictBroker::TryAcceptLocked` refuses stale generations, unpublished layouts, actions not offered at the submitted placement, and a second decision (`FileOperationsConflictBroker.cpp:18-70`), so a second renderer submitting through `Task::SubmitConflictDecision` is already idempotent. Automatic presentation is non-activating by design (`UI_FileOperationsPopup.md:357-373`, `1888-1889`); hide is not consent (I18 §5.3).
- **Cancel all.** Requests cancel on every unfinished, not-yet-cancelled task present in the snapshot; completed records and informational tasks are never dismissed (spec `UI_FileOperationsPopup.md:201-205`); a cancel without an accepted choice records no decision (spec `:2153-2157`, by design, CA-5 refuted as a defect).
- **Rate display.** Hold 600 ms, decay τ 900 ms, floor 1 B/s (`Popup.cpp:3450-3464`); only `displayedBytesPerSec` decays, `smoothedBytesPerSec` does not (`:5326`, `:5285-5293`); the graph samples the decayed value (`:5393-5398`); tests pin hold at 250 ms, decay at 2.5 s, zero at 40 s (`Tests.Phases05_06.cpp:15313-15324`, `Commands.Tests.FileOps.cpp:6564`).

## 4. User-facing policy (normative text to merge into the authoritative specs)

Add a "User-facing policy" section to `Specs/UI/UI_FileOperationsPopup.md` (referenced from `Specs/FileSystem/FileSystem_FileOperations.md` "Results and consumers"). Items marked **D-x** are owner decisions accepted on 2026-10-11 (section 14); they are settled, not open.

- **P1 Severity taxonomy.** *Error* = the requested result was not achieved for an item or the task. *Warning* = the result was achieved with a loss or deviation the user may need to act on: skipped or failed items, lost MOTW/ADS/EA, failed attribute or timestamp writes, verification Failed/Unavailable, retained owned stages or cleanup debt, a prompt raised after a failed attempt. *Information* = the result was achieved exactly as the product contract says: destination ACL, owner and group inheritance; a Move that used the Copy route disclosed at admission; a destination that cannot store timestamps or permissions at all; a question the user was asked; a decision the user took or that was applied from the user's earlier choice; discovery skipped; a destination the user chose to keep; items or links the user chose to skip; a Recycle the user escalated. Compression inheritance is never a note, and no new timestamp-precision comparison is introduced (FAT rounding is not detected today and stays undetected). Only Warning and Error increment the card counters, retain a card against auto-dismiss, block clean completion, or project an Issues row by default. Information is always recorded in the bounded task reservoir and export, independently of the Advanced log-verbosity toggle, and is shown on cards and in Issues only when `fileOperations.showInformationalNotes` is on (section 5).
- **P2 Noise budget.** An ordinary cross-volume Move or Copy of a folder whose destination inherits a different ACL or compression state, truncates timestamps, or runs beside an unrelated queued task in a disjoint folder MUST end as "Copied"/"Moved" with zero counted problems and MUST ask nothing. The only prompts permitted in that scenario are a typed collision on an existing item or an overlap the paths prove.
- **P3 Never-started rule.** A task that ends Canceled before any root crossed the mutation gate (no builder in `MutationPossible`, no owned stage created, no clipboard cut list consumed, no indeterminate item) renders a plain Canceled card: no counters line, no HRESULT line, a single fact "Not started; nothing was changed", eligible for auto-dismiss and for the completed group's one-time collapse after Cancel all. A task that crossed the gate keeps today's typed facts.
- **P4 Decision surface.** Every actionable prompt published before a task's first mutation, plus any per-item prompt whose relevant folder is shown in a pane, is rendered on the task card **and** mirrored as a modeless, pane-anchored overlay in the Folder window whose pane currently shows that folder. One engine decision, two renderers; the first answer wins and the other renderer disappears. Enter and Escape on the mirror bind only to the mirrored prompt's own default and escape actions; the mirror never steals focus and is never a nested message loop. Hiding the popup while a decision is pending leaves the mirror and a main-window "Decision pending" indicator in place. (D-8.1, accepted: the status-bar indicator is always shown while a decision is pending; the popup's taskbar button flashes only when the owner window is foreground and the popup is not, once per publication.)
- **P5 Plain language.** Card body text never contains a raw HRESULT, a zero-valued counter, or the engine words *publish*, *artifact*, *identity*, *discovery*, *known work*; those stay in Technical details, the log and the export. The blocked artifact message must still state the fail-closed reason in plain words and name the item.
- **P6 Escape hatches.** (a) A root's discovery scope closes when its enumeration completes, never when its last child finishes (section 6). (b) The headline speed is a windowed average and a stall longer than the window is named, never rendered as ~0 B/s; the graph never draws a trough for callback silence that is followed by a burst (section 10). (c) An interrupted-operation leftover, or any file, on a location that exposes no file identity gets a plain-language reason, an "Open location in File Explorer" action, and a corroborated by-name delete behind one explicit consent (D-7.3, which supersedes D-7.1; section 7); an item that cannot even be opened gets Retry, never a by-name delete.
- **P7 Completion.** The counters line is drawn only when a counter is nonzero. `autoDismissSuccess` keeps its default (off) and its combined success/canceled meaning (D-5.3, accepted); a separate canceled toggle is an optional follow-up after I18 §7.5, outside this plan.

### 5.2 Requirements

- R5.1 The prompt observation `item.conflict.prompt` is recorded at **Info** when the prompt is a deferred-consent prompt (`consentFacts != nullptr`) or a first-attempt typed collision; it stays **Warning** when `attemptCount != 0` (prompt after a failed attempt) or the bucket is `Unknown`. The row keeps its `conflictPrompt` facts, its Issues row, and its join with later decision/result records.
- R5.2 An Info entry that carries typed user-facing facts (`conflictPrompt`, `acceptedDecision`, `conflictResult`, or a `LocalizedDiagnosticText` user note) is a **user note**: it bypasses the `diagnosticsInfoEnabled` ingress gate, enters the task reservoir and the export, never increments the counters, never blocks auto-dismiss, and never becomes `_taskLastProblem` while a Warning/Error exists. `QualifyIssueFacts` separates **retention** from **visibility**: `originalProblem` becomes `(Warning || Error || (Info && conflictPrompt)) && !acceptedDecision && !conflictResult`, so trimming, joining and Problem text are unchanged for prompt rows, and a new `visibleWithoutNotes` facet is true only for Warning/Error original rows and for the decision/result rows joined to one. Recording never depends on the setting; only display does (R5.3).
- R5.3 New setting `fileOperations.showInformationalNotes` (bool, default **false**), Preferences > File Operations, toggle card next to Auto-dismiss, label "Show informational notes from file operations", description "Show notes about expected outcomes (inherited permissions, questions you answered, skipped links) on task cards and in the Issues pane. They are always kept in the task log." One rule everywhere: questions, decisions and notes are **always recorded** (reservoir, log, export); the card, the Last note, the Issues pane and the direct `Issues` action **all follow the setting**. When **off**: cards show no note and no "Notes:" line, "Last note" shows only Warning/Error problems, Issues projects only rows with `visibleWithoutNotes` (Warning/Error originals and the decision/result rows joined to them; a question answered without any Warning is hidden), and the direct `Issues` action appears only when a visible row exists. When **on**: cards show "Notes: N" after the counters (only when N > 0), "Last note" falls back to the last user note when no Warning/Error exists, Issues projects Info question and note rows with the existing "Information" caption and neutral tone, and the direct `Issues` action is offered for note-only tasks. The export always contains everything.
- R5.4 Metadata classification. Security: every difference explained by destination inheritance — inherited ACEs, explicit ACEs absent from an inheriting destination, owner, primary group — is **one Information note per task** ("Permissions were inherited from the destination" with a count), deduplicated by (task, feature); dedupe is mandatory. Normal inter-callback gaps (≤ 50 ms plugin, ≤ 200 ms bridge) never trigger decay, so every dip the user sees is a **real** stall ≥ 0.6 s at the bytes-handed-to-OS level: end-of-file flush, server-side extension, or redirector write-behind throttling.
- Existing hooks for attribution: `FileOps.Popup.Rate.MaxCallbackSilenceMs` (`Popup.cpp:5420`), `FileOps.Bridge.Copy` detail with `writeUs/writerWaitUs/readerWaitUs/progressCalls` (`State.cpp:14175-14189`), `throttleMaxGapMs` (`FileOps.cpp:1507-1530`, bandwidth-limit path only).
- Not a cause: DISC-3's half-rate reservation lowers the plateau but cannot oscillate; the per-directory drain convoy (all workers idle at every directory boundary) is a structural ramp-to-zero for nested trees and is fixed by section 6.
- Hypotheses (not verifiable from code): NAS write-cache flush on `FlushFileBuffers`, SMB credit stalls, `FILE_ATTRIBUTE_TEMPORARY` turning server writes into one large flush at commit, antivirus on close, multichannel/RSS/jumbo frames.

### 10.2 Requirements

- R10.1 Measurement first. The engine reports a per-item phase (`Transferring`, `Finalizing`, `Publishing`, `Verifying`) at phase boundaries: either a new `FileSystemItemPhase` on the progress ABI (`FileSystemProgress`/`IFileSystemOperationControl`, sizeBytes-guarded) or, without an ABI change, a forced zero-delta progress report at each boundary so `lastProgressCallbackTick` advances and the host derives the phase from its own bridge state. The Local plugin emits it around `Commit`/flush/metadata/`PublishAs`; the bridge around its phases.
- R10.2 Display: the headline "Speed" and the ETA use a sliding 5 s average of bytes over wall-clock time (resampled 100 ms buckets already exist), so a real stall lowers the number honestly instead of snapping to 0 and back; the display never holds or invents a rate. A named phase, or a stall longer than 600 ms, is shown as text next to the last honest average ("Finalizing file…", "Waiting for the destination…"), and the graph draws that interval as a distinct stall band (hatched, zero height) rather than a held rate; the no-trough rule of `UI_FileOperationsPopup.md:1382-1383` is reworded to "silence followed by a burst within the window is averaged, never drawn as a trough; a stall longer than the window is drawn as a stall band". After a stall the EMA baseline resets to the stall end (as `resumeTick` does for pause, `Popup.cpp:5260-5263`) so the headline neither undershoots nor snaps.
