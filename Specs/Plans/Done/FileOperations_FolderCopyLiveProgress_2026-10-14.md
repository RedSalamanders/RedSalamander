## Required behavior

- **R1 — precise units:** show discovered descendant **files** separately from folders and selected roots. Keep the child-file count and total logical byte size visible after discovery closes, including before the first byte moves. During open discovery label totals as found so far; after closure show the final total. Represent byte-total availability explicitly: a producer-certified empty tree or all-empty-file tree shows `0 B`, while unavailable size stays unavailable, not zero. Include the native known-zero and sizeless-provider controls; do not infer size availability from `totalBytes > 0`.
- **R2 — copied children:** live copied-file counts advance at successful per-file publication, including zero-byte files. Skipped, canceled and failed unpublished files do not count as copied; retries do not count twice. A published file still counts when subsequent verification or cleanup fails; those outcomes remain independently visible. Keep selected-root result accounting separate. A provider without authoritative child completion reports must show known found-file totals and bytes, without inventing a copied-file count.
- **R3 — file lifetime:** a file row remains visible while opening, transferring, finalizing, publishing or verifying. Known size and written bytes survive zero-delta phase changes. A fully written but uncommitted file may show a filled byte meter with a localized finalizing state; it must not vanish or be described as copied. Retire a row on explicit file-terminal state or task teardown, with only a bounded completion-display grace.
- **R4 — actual bytes:** render an individual determinate meter for each known-size live file; its fill must advance with real callback bytes. An unknown-size file remains indeterminate. A zero-byte file has no fake byte percentage but still contributes to found/copied counts. Preserve distinct streams and filenames under parallel copy.
- **R5 — task truth:** no growing-denominator overall percentage during open traversal; keep discovery and transfer independent. A known closed total switches to determinate before the last file finishes. Keep copied byte counts and child counts coherent, monotonic and bounded, without changing verification weighting or cancellation/partial-result semantics.
- **R6 — lifecycle:** cancellation, errors, task completion and popup destruction drain live rows and callback storage. No unbounded per-file path ledger, callback allocation storm or worker access to UI controls.
