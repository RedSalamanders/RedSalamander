## Why this plan exists

**Verdict: broadly well-engineered, but NOT yet "rock solid."** The viewers get the hard parts mostly right — most plugins snapshot inputs by value before going off-thread, AddRef `this` for the worker's lifetime, drop stale work by `requestId`, drain posted payloads on teardown, use WIL RAII consistently, and bounds-check the untrusted decoders (libraw/turbojpeg/TIFF/EXIF/PE). The audit confirmed and **refuted 23** plausible-but-wrong findings (see "Verified correct"). But it also found real defects that block a business-critical "rock solid" sign-off, concentrated in five classes:

1. **One data-corrupting use-after-free on the most dangerous surface (export).** ViewerImgRaw holds a reference into the cached pixel buffer across the modal save dialog's message pump; an in-flight decode completing during the dialog frees/moves it → UAF or a silently corrupt/blank image written to the user's file. This is the single ship-blocker.
2. **A whole capability is silently dead.** ViewerImgRaw's decode workers never initialize COM, so every WIC-backed format (PNG/GIF/BMP/non-RAW TIFF/HEIC/WebP) fails to open — masked because JPEG and RAW don't touch COM.
3. **A security hole on intentionally-untrusted input.** ViewerWeb embeds untrusted JSON/JSONL/Markdown into inline `<script>` with an escaper that misses `</script>`, and ships no CSP → script injection in the viewer origin.
4. **Concurrency/lifetime gaps.** A COM-refcount data race in ViewerWeb's async load (UAF/double-free of the IFileSystem plugin); object/COM-self-ref leaks + an OOM null-deref across four async dispatchers; a UI-thread freeze in ViewerPE; two VLC teardown/loader races.
5. **Pervasive text-rendering geometry errors.** ViewerText's text mode assumes one code unit == one fixed column, so tabs, CJK/proportional glyphs, and surrogate pairs desync selection/caret/search/hit-test — the wrong text gets selected and copied on very common files.

**Standing rule for every Farsight slice:** a slice is not done because a self-test is green. For each P0/P1 slice the proof must make the *dangerous, dead, or wrong condition observable* and **FAIL (RED) on the current tree** before the fix, then pass after. Where a deterministic UI repro is impractical (a refcount race, a threadpool-submit failure), the proof is a line-by-line review of the AddRef/Release/ownership balance plus a structural assertion (e.g. "the worker dereferences no mutable `self->_member`").

**Cross-cutting first (fix the class, not the instance):**
- The **async-dispatch leak + OOM null-deref (F-S0-4)** is *one* mistake replicated at 5 sites; fix all 5 to the one correct shape (ViewerWeb's `StartAsyncLoad` is the in-tree exemplar), and later hoist it into a shared `Common` helper (F-S3-3 / `plans/030` Stage 3).
- The **WIC-CoInit (F-S0-3)** is one chokepoint (`DecodeImageToBgraWic`), not three call-site edits.
- The **text geometry (F-S1-4)** is one model (fixed `charW`), not three symptoms; the layout-based fix subsumes tabs, CJK, and surrogates.

### F-S0-8. `[HIGH / security + resource bounds]` ViewerWeb raw-HTML isolation and complete navigation mediation

**New evidence that retires the old refutation:** `builtin/viewer-web` currently turns local or staged paths into `file://` URLs and navigates them directly while `IsScriptEnabled` is globally true. Its only policy hook is top-level `NavigationStarting`; frame and new-window routes are not mediated, non-HTTP schemes are accepted for Web content, and `allowExternalNavigation` defaults to true. Virtual-filesystem Web documents are copied to a temp file without either an advertised-size guard or a running byte ceiling. JSON/Markdown have a raw-byte cap, but UTF-16 normalization can retain the raw bytes, a full wide copy, and the UTF-8 copy concurrently at the schema's 512 MiB maximum.

**Required architecture:**
- Serve raw HTML bytes from the private `https://viewer.redsalamander.invalid` origin. The response must carry a raw-document CSP that disables document script and denies network, connection, frame, object, base, and form capabilities by default. Generated JSON/JSONL/Markdown retain their separate internal CSP and required bundled scripts.
- Keep PDF as a separately classified route, but stage every PDF from the provider reader. A drive/UNC-shaped logical path supplied by a custom provider is not proof of host-local identity and must never authorize WebView2 to read the corresponding host path directly. The staged path remains tracked until deletion succeeds or a later retry/quiet point handles it.
- Route top-level navigation, frame navigation, and new-window requests through one allow-list policy. Internal viewer URLs and the exact active PDF document are allowed in-view; frame/new-window escape is canceled; an explicit user-initiated `http`/`https` open may be sent to the system browser only when the setting permits it. External navigation defaults to false in runtime defaults, schema, serialized-default detection, and the authoritative spec.
- Apply both `GetSize`/advertised-size validation and a running-byte cap to virtual reads. Bound UTF-16 expansion before allocation (or convert incrementally) so configured input cannot produce an unbounded multi-copy peak. Emit scenario metrics for accepted bytes, rejected bytes, and conversion/output size.

**Required proof:** deterministic helper tests cover URL classification/policy, the raw CSP, false-by-default configuration, advertised and running size rejection, and UTF expansion bounds. A real `ViewerWeb.dll` harness case opens hostile raw HTML through a virtual filesystem and proves the viewer completes without navigating the original/staged `file://` path where the installed WebView2 runtime permits observation. Build `ViewerWeb` + `ViewerPETests`, run the focused cases, archive the run, and update `Specs/Plugins/Plugins_ViewerWeb.md` with the lasting security/size contract.

### F-S0-9. `[CRITICAL/HIGH / data safety]` ViewerText Save-As source/destination integrity

**New evidence:** Both Save-As paths open the selected destination with `CREATE_ALWAYS` before the operation has proved it can finish. Keep-original opens/truncates the destination before acquiring the source reader; choosing the source path as the destination can therefore erase the source before it is read. Re-encode opens/truncates first, writes only `_textBuffer`, and merely shows an informational truncation alert afterward when `_textStreamActive`; a streamed file is silently saved as one chunk. Any later read/encode/write failure leaves a pre-existing destination partially overwritten.

**Required architecture:** Reject save while the viewer is loading. Reject streamed re-encode with a localized actionable error before creating any destination artifact unless a full incremental transcoder is implemented and proven. For keep-original, acquire and seek the source reader before creating output. For both modes, create a unique sibling temp on the destination volume, write all bytes to it, flush and close it, then commit with `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`. Delete only the temp on every failure. The production dialog path and a non-dialog Debug test seam must call the same save primitive; injected encode/write/commit failures must not mutate source or destination bytes.

**Required proof:** On-disk tests cover same-path keep-original, a pre-existing destination under source-open/read/encode/write/flush/commit failure, successful keep-original and re-encode, streamed-conversion refusal, and loading refusal. Each failure leaves source and pre-existing destination byte-identical and no sibling temp behind. Build `ViewerText` + `ViewerPETests`, run the focused case plus localization/source contracts, and merge the lasting atomic/refusal rules into `Specs/Plugins/Plugins_ViewerText.md`.

**Implemented (2026-07-11):** `SaveAsToPath` is the sole production/test save primitive. It validates loading/stream state and target encoding before output; keep-original opens, sizes, and seeks a fresh source reader before temp creation; both branches write only a collision-safe `CREATE_NEW` sibling temp, flush and close it, then commit with the required same-volume `MoveFileExW` flags. ### F-S1-9. `[HIGH / module lifetime]` Threadpool callbacks must release plugin pins after the callback return boundary

**New evidence:** The focused ViewerPE close regression reproducibly crashed with `0xC0000005` after the blocked worker was released. Both preserved dumps placed the exception at the same unloaded `ViewerPE.dll` RVA; symbolization resolved it to WIL's `unique_hmodule` `FreeLibrary` close helper. The worker correctly acquired a module reference, but its work-context destructor released the last reference from inside the callback. Windows unmapped the DLL while the callback still had to return through it. The same retain-until-body-end pattern existed in ViewerWeb, ViewerText, ViewerImgRaw, ViewerVLC, and ViewerSqlite threadpool callbacks.

**Required architecture:** Every plugin work item still acquires an owning module reference before submission and destroys it normally on submission failure. Once a threadpool callback starts, it must immediately transfer that reference with `FreeLibraryWhenCallbackReturns(instance, pin.release())`; merely keeping a `wil::unique_hmodule` local until the callback body's end is unsafe. This rule applies to success, cancellation, stale-result, allocation-failure, and payload-post-failure exits. Non-threadpool callback systems retain their own documented quiet-point ownership and must not be mechanically converted to this API.

**ViewerWeb reconciliation:** WebView2 owns ordinary COM callback objects outside the plugin's submitted work callbacks. A callback-captured module reference could become the last reference while `ComCallback::Release()` was still returning, so those callback-owned pins are removed. Callback construction records the WebView2 owner STA; every callback contributes to a DLL-global live count, invocation/final release must occur on that STA, and any affinity violation permanently quarantines that DLL image. The final delete publishes a release epoch before the live count reaches zero; `CanUnloadNow()` requires the same owner STA, and its first zero-live poll records that epoch and still returns false, so only a later same-STA deferred-unload poll can vote true after the releasing call stack is gone. Load/Save threadpool contexts contribute to a separate active-worker gate, retain the normal `FreeLibraryWhenCallbackReturns` rule, and release the gate only in the callback epilogue. `CanUnloadNow()` also requires explicit shared-environment, window-class/WIL-brush, and staged-file cleanup at `PluginShutdown`; `DllMain` remains empty on detach.

**Required proof:** Preserve and symbolize the PE crash dumps, then rerun the exact blocked-read close/unload case to prove the DLL remains mapped while work is blocked and unloads cleanly after callback return. Source contracts enumerate every module-pinned viewer threadpool callback and reject the unsafe destructor-at-body-end shape. Focused unload/close tests cover ViewerText, ViewerImgRaw, ViewerVLC, ViewerWeb, and ViewerSqlite where their existing harness exposes deterministic blocked or delayed work. Update `AGENTS.md`, `Common/Helpers.h`, and `Specs/Plugins/Plugins_ViewerPlugins.md`; build every touched viewer and run the full viewer suite.

**Implementation and focused proof (2026-07-12):** ViewerPE, ViewerWeb load/save, ViewerText, ViewerImgRaw main-open/prefetch/export, ViewerVLC load/cleanup-dispatcher, and ViewerSqlite threadpool callbacks transfer their owning pins at callback entry. ## Phase P2 — Reliability & performance mediums (each independent)

### F-S2-1. `[MEDIUM / reliability]` ViewerSpace live scan-model memory is unbounded (plan 025)

**Symptom:** Scanning a drive root grows `_nodes`/`_childrenArena`/`_fileRecords` to millions of entries (hundreds of MB–GBs), pushing the process toward `bad_alloc`/termination; the user never sees most of those nodes (the treemap already does level-of-detail).

**Root cause and reconciled evidence:** The only byte guard gates the persisted cache snapshot, not the live model. Every non-reparse directory allocates a model id, pending record, frontier job, completion-map entry, child-name/path copy, and ultimately a `Node`; every retained file allocates a `FileRecord`; `_childrenArena` growth appends a replacement block and strands the old capacity until the entire scan is reset. Provider `FileInfo` buffers are walked without validating the advertised count, entry alignment/minimum stride, duplicate/non-monotonic offsets, internal id exhaustion, separator/NUL-bearing names, or path cycles. Byte/count additions and `nextId` can wrap. A hostile or simply enormous provider can therefore exhaust memory, corrupt identity bands, fabricate totals, or recurse indefinitely even though reparse points are skipped.

**Required architecture:** Introduce one ViewerSpace-owned scan resource policy that caps retained directory nodes, child references, file records, retained names/bytes, per-directory children, traversal depth, and outstanding traversal state. When a valid scan exceeds an itemization cap, continue enumerating and aggregating under the nearest retained ancestor so root/folder byte and file/folder counts remain exact; expose a deterministic aggregate bucket/state rather than dropping totals. Use checked/saturating arithmetic for bytes and counts, never wrap packed item ids, and emit accepted/rejected/capped/resource metrics. Parse provider buffers through one bounded validator: reconcile `GetCount` with the traversed record count; require aligned, forward, in-range entry strides and bounded aligned names; reject separator/NUL/dot path components, invalid ids/counts, duplicate logical child names/ids where meaningful, and ancestor/path cycles. Reparse-point directories remain visible/non-descending. Replace append-and-abandon child growth with storage that reclaims/reuses prior blocks without invalidating stable item ids.

**Required proof:** Deterministic tiny-cap helper and real ViewerSpace runtime cases cover an accepted tree, very wide and very deep valid trees, cycles/path injection, misaligned/truncated/count-mismatched buffers, duplicate/exhausted ids, and byte/count overflow. Valid capped scans retain bounded node/child/file/itemization storage, reach a stable responsive UI, and report exact saturating rolled-up totals/counts; hostile buffers terminate safely without model corruption; reparse points never descend. Prove child-storage growth does not strand the prior block, expose accepted/rejected/capped/resource metrics in the Debug snapshot/JSONL archive, build `ViewerSpace` + `ViewerPETests` with zero warnings, run focused/existing ViewerSpace regressions, archive under `Specs/TestRuns/<machine>/Viewers/<timestamp>/`, and merge the lasting contract into `Specs/Plugins/Plugins_ViewerSpace.md`.
