# ViewerSpace Plugin Specification

## Overview

**ViewerSpace** (`builtin/viewer-space`) is a built-in **viewer plugin** that visualizes **disk usage** for a folder as a **Direct2D/DirectWrite treemap**.

Goals:
- compute folder and file sizes asynchronously (non-blocking UI)
- render progressively as results arrive (real-time expansion)
- allow interactive drill-down (into subfolders) and drill-up (back to parent)
- respect the host theme (colors, dark/high-contrast, rainbow, DPI)

## Invocation (Host Integration)

ViewerSpace is invoked from a **FolderView pane**:
- **Shortcut**: `Alt+F10`
- **FolderView context menu**: `View Space`

Target path selection:
1. If exactly **one directory** is selected in the active pane, open ViewerSpace for that directory.
2. Otherwise open ViewerSpace for the pane’s **current folder**.

The host opens the plugin directly by id (not via file-extension association).

## ViewerOpenContext Contract

The host passes:
- `ViewerOpenContext.fileSystem` (active filesystem instance)
- `ViewerOpenContext.fileSystemName` (localized filesystem name for display)
- `ViewerOpenContext.focusedPath` (filesystem-internal UTF-16 folder path)

`selectionPaths` and `otherFiles` are unused by ViewerSpace and SHOULD be null/empty.

Path semantics:
- `focusedPath` is treated as an **opaque filesystem-internal path string** (it may not be a valid Win32 path).
- ViewerSpace MUST pass the same path string (and child paths derived from it) back to `IFileSystem` APIs; it MUST NOT enumerate with Win32 file APIs.

## Configuration

ViewerSpace exposes a JSON configuration schema (`GetConfigurationSchema`) and accepts configuration via `SetConfiguration`.

Supported keys (defaults):
- `topFilesPerDirectory` (96): compatibility floor for largest-file retention per directory. The scanner may retain more file candidates when pixel/detail budgets allow it; remaining files are grouped into exact “Other” totals (`0` groups all files only when the effective adaptive floor is also disabled by implementation policy). The current adaptive budget is derived from the visible treemap area, then capped at the 20k file-candidate ceiling.
- `scanThreads` (1 in persisted config): number of background threads used to scan sibling subtrees in parallel within a single ViewerSpace scan. For the Win32 filesystem, the runtime default is at least `min(hardware_concurrency, 8)`; non-Win32 providers stay at `1` unless explicitly configured.
- Scan workers use `THREAD_PRIORITY_BELOW_NORMAL` CPU scheduling while preserving ordinary I/O and memory priority. Each worker, including the coordinator, captures and restores its previous CPU priority on every exit; the UI thread is unchanged. A recoverable priority API failure leaves scanning available and is logged. The terminal `viewer.space.scan.cpu_priority` row reports successful apply/restore counts in `value0`/`value1` and the priority-operation HRESULT, independently of the scan HRESULT. Its detail is `below-normal-cpu-normal-io-restored`; it follows worker joins. This policy does not change worker-count, volume-admission or cancellation limits.
- `maxConcurrentScansPerVolume` (1): throttles how many ViewerSpace instances scan the same volume at once.
- `cacheEnabled` (`true`): enables the in-memory scan cache.
- `cacheTtlSeconds` (60): how long an unused cached scan remains reusable, measured from its last use; `0` keeps it until it is replaced or evicted.
- `cacheMaxEntries` (1): maximum cached roots kept in memory.
- `viewMode` (`"explorer"`): `explorer` or `analyst`; both use the same retained scan, layout, selection and analysis projection.
- `analysisPanelVisible` (`true`): show the linked table and inspector when the viewport permits it.
- `analysisPanelRatio` (`0.33`, clamped to `0.20`–`0.65`): preferred width of the Explorer side panel, retained across collapse and reopening.
- `analysisBottomRatio` (`0.62`, clamped to `0.20`–`0.80`): preferred height of the bottom analysis panel, retained separately from side-panel width.
- `inspectorVisible` (`true`) and `inspectorRatio` (`0.38`, clamped to `0.20`–`0.70`): independently collapse or resize the selection inspector within the analysis workspace. Legacy configurations acquire these defaults.
- `compactRows` (`false`): use compact or comfortable table density. Legacy configurations remain valid and acquire these defaults.
- `fileCountWeight` (`false`): normal logical Size is the default map weight; `true` weights known retained/aggregate file counts. Zero-byte files may have count area without acquiring fabricated byte area.
- `colorMode` (`"folder"`): stable folder colors, `"type"`, `"age"` (own Modified), or `"newest"` (newest contained file, only when complete retained metadata establishes it).

Settings belong to global **Preferences → Plugins → Space**. Basic presentation fields precede the schema's **Advanced** technical scan/cache/retention fields. Grouping does not change stored values, defaults, worker count or draft/apply/cancel semantics. There is no separate viewer settings dialog.

A deliberately hidden panel with an empty filter releases its derived row/index arrays and does not build projections. Reopening the panel or choosing a view mode rebuilds the projection, preserving the independent selected item. A retained nonempty filter continues to build its index while the panel is hidden because linked treemap highlighting still consumes it. Viewport-driven temporary hiding does not change this preference or discard the projection.

## UI / UX

### Layout

The selection inspector and treemap tooltip MUST show the selected/hovered real file or directory's
last-write date and time as **Modified**, formatted in local time by the canonical
`Common/FileMetadataFormatting.h` CompactDetails profile (`YYYY-MM-DD HH:mm`). Retain the provider's
`FileInfo::LastWriteTime` in file summaries, directory nodes and cache snapshots, including refresh
replacement. A directory's timestamp describes that directory, not the newest descendant. Missing,
invalid and synthetic Other timestamps use the localized **Unavailable** value. An optional scan-root
`IFileSystemIO::GetFileBasicInformation` read runs on the scan worker; a provider without this capability
leaves the root date unavailable. Selection, hover and painting MUST NOT perform metadata I/O. The
inspector's narrow and paired layouts retain the Modified field and its complete UIA Name/HelpText.

- **Header**: viewer name, scan status and live progress, with **Cancel** while scanning. The navigation row is the single path display; the header has no duplicate Up button.
- **Breadcrumb**: compact path links followed by folder chevrons, with Back/Forward history. Clicking a segment navigates to that retained ancestor. Its chevron lists retained real child directories in Windows natural name order (`StrCmpLogicalW`, ignoring case and comparing digit runs numerically), so an ancestor can choose a sibling of the next segment. Equivalent natural names use a deterministic ordinal tie-breaker; literal names and generation-qualified targets remain unchanged. Files and synthetic Other entries are excluded. Folder menus snapshot at most 512 generation-qualified targets and reject stale generations; they never perform provider I/O on the UI thread. This private retained-model menu follows the same natural display-order policy as NavigationView sibling menus; canonical path identity is separate. Ancestors hidden by narrow layouts remain reachable from the ellipsis. Up remains in Navigate and via Backspace/Alt+Up.
- **Panels**: the analysis panel has a draggable separator in both side and bottom layouts. The selection inspector has its own separator and disclosure. Collapsing either panel preserves its preferred size; Show panel in the breadcrumb row restores the entire workspace, and the inspector retains a disclosure strip when collapsed. Both separators use the canonical DxUi Splitter for pointer, keyboard, Escape/capture-loss cancellation and UIA RangeValue. Pointer previews change geometry without publishing configuration; release/keyboard/UIA commits persist it. Pane minimums protect the treemap and table when the window becomes small. Resizing does not restart scanning or rebuild the analysis row model.

- **Treemap**: squarified treemap representing the current node’s children.

The analysis table Name column MUST use Windows natural display ordering in both
directions, independently of provider case sensitivity. Equal metadata keys retain
ascending natural name order with ordinal spelling ties and item IDs as the final
tie-breaker. Equal-byte top-file projections use the same natural display policy;
candidate retention caps and byte ranking remain unchanged. Shared owner:
`Common/NaturalSort.h`. Provider listing duplicate-name validation MUST remain under
its ordinal provider identity relation; natural equality never merges retained items.
The analysis-host fixture exercises numeric, leading-zero, case, dot and Unicode names,
both Name directions, size ties and no provider I/O. Listing-validation tests preserve
distinct `file2`, `file02` and `file10` under both provider case policies.

Breadcrumb links and folder chevrons participate in forward and reverse keyboard traversal. Reverse Tab from the analysis filter visits the panel separator before returning to navigation.
Folder-menu labels preserve literal ampersands in retained directory names rather than interpreting them as shortcut markers.

Protected scenarios: side/bottom panel resizing, inspector resizing and collapse/restore, retained-folder sibling navigation, mode popup selection/dismissal, no-activation narrow/wide layout transitions and stale menu rejection. `viewer.space.workspace.layout_us` measures inspector arrangement, `viewer.space.navigation.folder_menu_us` measures retained-folder choice projection, and `viewer.space.navigation.choice_menu_us` measures bounded token-map and popup-label construction before the modal popup is shown; existing render/layout/input-presentation metrics remain the treemap witnesses. Deterministic ViewerPETests checks UIA operations and lifecycle captures with exact fixture/binary provenance.

`TestViewerSpaceAnalysisHostVirtualGridAndLifetime` also checks the real breadcrumb-folder query with twelve
retained mixed-case, numeric, leading-zero, multiple-digit-run, dot and Unicode directory names. It preserves
distinct names/tokens, excludes files, rejects stale generations and proves that querying does not read the
provider. It records 32 `ViewerSpace.SiblingSort` query samples for same-fixture comparison; those samples are
query timings, not menu-presentation or whole-viewer performance qualification. The ambient-desktop variant
reuses this fixture under the existing no-activation guard.

Nonactivating analysis UIA coverage keeps the shared activation blocker and observes
process-owned foreground events through `ScopedNonActivatingDesktopObserver`.
Ambient cursor movement or another application's foreground change is diagnostic
evidence, not a ViewerSpace activation failure. Owned foreground, including a
transient event, and unavailable observation/drain coverage remain failures. This
path never injects physical input, moves/restores the cursor, or restores another
application's focus. Native contract controls and simulated observation changes
exercise these distinctions without changing the physical desktop. This test
witness does not alter normal viewer opening, keyboard focus or assistive-technology
behavior; interactive qualification remains separate.

Lifecycle capture provenance declares `foreground_witness_scope` as
`guarded-process-owned-events`. Its compatibility `foreground_preserved` field
means no owned foreground transition through that frame's event-drain barrier;
it does not claim that unrelated applications remained in the same foreground.
The case also drains after teardown. Invalid captures and failed case results
remain diagnostic evidence and cannot qualify documentation screenshots.
The held-refresh frame waits for the UI's `Scanning` state and an empty progress
queue while the provider remains gated; observing retained rows or an entered
provider callback alone cannot qualify a stable capture. The unchanged before/after
state and model assertions must still pass.

Auto-expansion:
- Once the current scan producer has completed and a projection is already published, new map and analysis builders defer until all queued update bytes drain, including a terminal tail below 4 MiB. Producer completion is acquired before sampling the queue; the UI's Scanning state alone does not establish producer activity. In-flight builders still finish coherently, initial previews remain eligible, and final projections retain their existing limits.
- For **large-enough directory rectangles**, ViewerSpace renders the **next level inside the rectangle** (recursively), reserving a label header for the folder name and using the remaining area for children.
- Auto-expansion uses the available child content area: at least 16 DIP on each side and 512 square DIP after the folder header and inset. The largest eligible areas expand first, up to depth 8 while scanning or 10 when settled, within 20,000/50,000 draw-item ceilings. Small retained children remain visible where they fit; no relative 8%/3.5% threshold stops a large folder from showing its children.
- Scoring, ordering, row placement, animation preparation and spatial indexing are resumable timer work. A yielded build keeps the previous complete geometry; it resumes to complete publication, qualified by displayed model generation, revision, view, DPI and bounds. The target is 1.8 ms between time checks, not a hard callback-duration guarantee: allocation and release can add latency and must be measured.
- While scanning, new map and analysis builds are limited to four publications per second, with one initial positive-map preview attempt per displayed view and generation when the current real view already has committed retained-file, observed-child, or Other bytes and no positive-byte, positive-area, non-culled geometry has been published. Zero-byte metadata tiles do not consume that useful-geometry state. Root progress alone and staged summary bytes do not qualify. This initial attempt remains sliced and may bypass cadence and the existing-map backlog deferral once; it does not bypass resource limits. Otherwise, when a map already exists, a pending transport above 4 MiB defers new builds so bounded update drains can recover throughput; an empty map remains eligible for bounded preview work. In-flight builders finish against their borrowed revision before model mutation resumes; completed scans always build their final projection. Retained refresh candidates preserve the visible display generation's preview latches until adoption; cancellation does not grant that generation another initial attempt. Deferral never changes the 8-MiB transport cap or discards accepted files.
- Test-only publication phase diagnostics may be enabled with a positive `REDSALAMANDER_VIEWERSPACE_PUBLICATION_PHASES` value. They emit extra timing rows for cache reset, retirement, row notification and inspector update; those observer writes contribute to the existing end-to-end turn metrics. The flag is unset by default and phase-instrumented captures are diagnostic, not default candidate-qualification measurements.
- Directory byte totals are monotonic lower bounds while scanning: the greatest accepted provider progress/completion total is combined with committed retained direct-file bytes, committed Other bytes, and the derived totals of represented child directories using saturating addition. Summary file bytes remain staged until the entire summary transaction commits. A positive child-total delta propagates once through its real-directory ancestors (bounded by the 512-level traversal policy), so a parent can acquire useful geometry before all sibling subtrees finish. Cache restore preserves these accounting bounds.
- For the deterministic 1200 × 800 DIP map with A/B each containing four S folders and sixteen F files, and each S containing four Q files (all files 1 MiB), settled layout exposes 10 folders and 64 files without an Other tile. Captures are generated by the test harness, with provenance, and are distinct from proposal mockups.

### Explorer and Analyst

Explorer keeps the map dominant. At widths of at least 1100 DIP the linked panel starts at 33% on the right; narrower windows put it below the map. Bottom panels start at 62% of available height. These sizes are resizable and persisted independently. Showing the panel requires a viewer width of at least 504 DIP and 462 DIP of body height; bottom panels receive at least 320 DIP while preserving a 120-DIP drawable map plus its insets and separator. Below those limits the canvas remains usable and View commands retain the preference.

Inspector paths use a visual middle ellipsis and names a trailing ellipsis when the value cell is too narrow. Resizing derives that display from the retained full value, not a previously shortened label. Cut positions preserve UTF-16 surrogate pairs. All Inspector values keep the unabridged value in UIA Name and HelpText; kind, bytes, share and state retain their full visible text. This presentation policy belongs to the analysis host because the pinned DxUi Label has no public trimming API; measurement uses the public DxUi Typography surface.

The virtual table lists retained direct children of the current folder plus its exact scan-time Other. Columns are Name (file/folder icon and exceptional status), Size, Parent share and an independent cleanup checkbox. Kind is conveyed by an accessible icon; ordinary Done has no dedicated column. It formats visible cells on demand and stores compact item IDs plus a lookup index, with no copied whole-model tree. Sorting is resumable, with stable name/identity ties. Folder/file glyphs supplement the map's folder header and folded file corner. Rainbow never replaces those shape cues.

Filtering is debounced and explicitly limited to retained names in the current folder. It changes the table projection and highlights its matching map items without changing map areas or logical totals. Scan-time Other retains unknown names and cannot claim to match a hidden leaf. Parent share uses the unfiltered included parent denominator for the selected area mode; exclusion changes that denominator, while filtering does not. Search of all discarded names requires a separate provider/storage feature.

Selection persists independently of hover and is qualified by displayed generation. A file click selects the linked inspector; folder click preserves drill-down. The compact inspector shows one icon/name identity, one parent location, Size, parent share and Modified. It shows exceptional scan/detail/exclusion state only. Empty selection shows a proper prompt. Exact full paths and raw bytes remain available through UIA/help text and Copy path; visual elision does not discard them. Selection in the table and map links through stable item tokens; nested map selection remains readable in the inspector even when absent from the direct-child table.

The navigation row uses shared DxUi controls: Back/Forward, at most six visible breadcrumb links with folder chevrons, an earlier-ancestors selector and one icon-only **Layout** button. Its tooltip and accessible name identify the current preferred placement. The owned menu offers **Panel right**, **Panel bottom** and **Map only**; Ctrl+1/Ctrl+2 retain right/bottom aliases. Live theme updates use the owned window DPI for map/header geometry, matching its hosted controls; theme metadata cannot rescale a live viewer. Table columns fit the current grid viewport while preserving stable column IDs. Right placement automatically uses the bottom arrangement in narrow windows without changing its saved preference. Independent splitter ratios and selection survive layout changes. The Layout control remains reachable in Map only. Escape dismisses the popup before reaching viewer commands. Popup tokens are snapshotted across modal message pumping and generation-qualified before dispatch. Ancestors and history remain capped at 512 and 64 respectively.

Workspace and inspector splitters use the theme's subtle grid-line tone at rest, preserving the canonical grip, accent on hover/drag and keyboard focus ring. High Contrast uses the original palette without softening. Pointer drag, arrow keys and UIA RangeValue resize the same ratios; Escape or capture loss cancels an in-progress preview before capture is released. Collapsing preserves each orientation's size and the linked selection, and mode changes never start a scan.

Accessibility uses the shared virtual Grid, GridPattern counts and offscreen GetItem, selected-row pattern, filter Value pattern, inspector labels and navigation controls as the accessible retained-data representation. The pinned DxUi version has no public custom treemap-fragment API; individual canvas tiles do not claim UIA providers. The snapshot contains visible rows, up to 256 selected offscreen rows and at most 16 most recently materialized offscreen rows. Embedded snapshot hits are read-only from any thread; uncached embedded requests require the owner thread. Detachment clears callbacks before destroying the host; retained providers become unavailable and cannot call into a retired viewer.

### Current workspace accounting and actions

**Discovered** remains visible above the navigation row and reports scan-wide logical bytes and counts. **This folder / Shown** separately reports the explored folder's included bytes. Navigation, filters and exclusions never rewrite discovered/original totals. Partial, cancelled, unreadable and summarized states remain explicit. Scan rate may appear after a meaningful sampling interval; no unreliable remaining-time estimate is invented.

**Exclude from view** is available from the main/context menus and the list's file/folder icon. Excluded real rows retain their original Size with dimming and an exclusion overlay so they can be restored. When exclusions adjust only part of a folder, its Size tooltip and exceptional inspector state identify its Shown total separately. Unreadable/unmeasured item sizes say Unavailable. Exclusion removes that item and its descendants from map area, shown totals and shares. It does not modify provider data or mark cleanup targets. Restore item and Restore all reverse it. Intents belong only to the current viewer session, survive navigation and refresh, and clear on Close. Provider path equivalence must come from a reliable typed path-identity profile; unsupported providers fail closed. Refresh rebinds retained real paths without silently changing their targets. Unresolved intents are reported; original scan totals remain available.

Exclusion intent is bounded to 128 paths, 131072 UTF-16 path units, 32768 units per path, 512 ancestry levels and 8192 sparse ancestor links. Rebinding publishes a coherent replacement sparse projection, in timer slices targeting 1.2 ms, while preserving the preceding coherent projection. Published/candidate maps, retained metadata, cleanup marks and export reservations are charged to viewer-owned admission accounting. These are conservative application-owned estimates, not a process/GPU memory cap.

Optional file-type and age colors have an explicit legend. Current-folder filtering combines retained name, file type and optional 30/365-day age conditions. The date basis is stated; own folder Modified is the default, newest-contained-file mode reports unknown if discarded/unreadable content prevents a trustworthy result. The expandable type breakdown summarizes retained direct entries; mixed/unknown folders cannot be assigned a fabricated file type. Filtering affects the list and linked highlighting, without changing map areas or totals. Whole-scan search and continuous zoom are not offered.

Derived type/newest-file/count facts are built after scanning using bounded retained metadata, at most 65536 node slots, with 1.2-ms preparation turns. Above that cap or when admission fails, affected derived facts are unavailable. Logical Size remains usable. **Size on disk** currently explains its unavailability: neither logical size nor hard-link aliases may be substituted for reliable allocation/identity data. Implementation of real allocation/hard-link collection remains separately gated.

**Problems** is reachable from the status count and View menu. It lists up to the first 256 retained unreadable/unmeasured entries as bounded metadata preparation completes, and supports locate, focus and real-path copy. It cannot claim to enumerate discarded names or all failures from an incomplete provider. Administrator rescanning remains outside ViewerSpace.

Cleanup uses separate checkboxes or explicit Mark matching items; icon exclusion never marks. Bulk marking snapshots the included real items in the settled current-folder filter, capped at 128 targets. Synthetic Other, stale generations and excluded entries cannot become targets. Parent/descendant marks are deduplicated. **Review cleanup** shows the frozen real target paths, bytes and whole-folder consequences, permits removal, and offers Recycle/Delete through the host's ordinary confirmed File Operations workflow. A handoff is not operation completion: refresh is explicit after the operation finishes. Refresh adoption clears obsolete generation-bound marks rather than silently retargeting them. No automatic cleanup suggestions are made.

Both pane actions use optional `IHostViewerActions`: **Focus in pane** opens the containing folder in the active host pane and reveals the item; **Open folder in other pane** opens a real selected directory in the opposite currently active pane, without a new shortcut. The host must bind the exact filesystem instance to a current pane and preserve provider/instance context; missing, stale or ambiguous bindings fail closed. Legacy focus is permitted only for verified local filesystem paths on hosts without the new service. Cloned legacy host leaf commands are likewise limited to the local provider.

**Export** explicitly chooses CSV or JSON and a local output path for a settled current analysis projection. It includes original/shown logical bytes, excluded/partial/unreadable/unmeasured/synthetic flags and null/blank unavailable allocation/count/date facts. Synthetic aggregates have no path. JSON preserves literal Unicode names; CSV includes a UTF-8 BOM, quotes and escapes fields and protects spreadsheet formula prefixes, recording the escape flags. Exported `fileCount` describes included known file count. Scan-root/current-view-path/discovered/shown/area/scope metadata distinguishes the view from the scan total.

Export freezes generation, model and view-projection revisions; concurrent changes cancel preparation rather than mix snapshots. Preparation targets 1.2 ms per turn and at most 20000 rows. One module-wide export reserves 8 MiB against admission, including bounded snapshot/formatting space; output is capped at 8 MiB. A module-pinned worker writes through the canonical atomic local-file transaction, preserving an existing destination on failure. Completion uses the registered posted-payload mechanism and a viewer-lifetime token. Closing does not join the writer or let late completion call a closed/reopened viewer. Save cancellation leaves existing files untouched.

Preparation borrows real retained names synchronously and transfers the strict UTF-8 conversion results into owned rows. Numeric modified times use the canonical nonallocating `Common::FileMetadata::TryGetLocalWriteTime` validity/conversion policy, rather than constructing display text and attributes. JSON retains the exact original valid UTC FILETIME ticks and explicit null for missing/invalid times; CSV retains its corresponding numeric/empty fields. The original preparation, admission, output and lifetime limits remain unchanged.

### Refresh ownership

F5 bypasses the cache. During queued cache validation, the accepted scan-root path remains available before root-node publication, so F5 and Rebuild can cancel the cached generation and start a full uncached scan. Unpublished child identities remain unresolved. For a settled view F5 retains the displayed model, geometry, selection and table while a replacement is built privately; the header identifies refreshing data. Candidate packets are never visible through control callbacks. Adoption waits for authoritative final progress, all directory-summary transactions, and a coherent queue drain. Selection rebinds by an unambiguous retained relative path or clears when absent. Navigating cancels the candidate before applying the user's navigation, so late completion cannot change the new location.

Retained refresh admits both owners, queue, scan reservations and derived storage against a conservative 192 MiB admission envelope. If replacement cannot fit, it keeps the previous view and offers the explicit File → Rebuild command, which discards it and rescans. Cancel/failure keeps previous data and identifies the outcome. A public `Close` detaches the retained model and model-derived state from the active viewer before returning. Submitted deferred-disposal callbacks may retain retired storage until completion; `Close` does not wait for them. A subsequent public `Open` on the same `IViewer` instance establishes an empty model before synchronous window-creation callbacks can inspect viewer state; model-derived records from the previous Open cannot be observed by the new window. It clears the previous path before creation and identifies the admitted current root in the title and header during queued cache restoration, before any restored geometry is published. Breadcrumbs may remain empty until their real nodes exist; retained F5 continues to identify its displayed model until replacement adoption. The ungated same-instance regression opens two distinct roots and returns to the first through the cache, checking the queued title/generation/no-geometry witness before pumping and then exact settled totals/current presentation. This envelope is not a hard process limit or an ordinary-scan cap: opaque provider buffers, DxUi/native controls, allocator metadata, and driver/GPU allocations are independently owned. Explicit Rebuild can transiently overlap storage awaiting background disposal; it charges and measures that storage until release. The compact cache remains independently capped.

The 192 MiB value is an admission-accounting basis. Retained refresh subtracts 16 MiB of derived headroom and the full 32 MiB ceilings for each of validation scratch, active paths and copied worker staging before admitting measured storage plus the candidate. Cache admission instead subtracts its own 16 MiB reserve and observes the independent 64 MiB serialized-residency limit. The 16 MiB reserve is not a standalone derived-allocation cap. Serialized cache records own separate storage; shared live/cache pages and shared-page deduplication are not implemented.

Retired model and derived storage is released by governed thread-pool callbacks. Model replacement, completed layout scratch/previous geometry, and canceled layout candidates share at most two disposal owners during normal operation. If both slots are occupied, ViewerSpace keeps the published layout, defers publication and one latest-wins replacement request, and retries from the timer when capacity returns. A canceled layout candidate may retain one charged pending owner; no new layout builder starts until that owner is handed off. This bounds resize/cancel storms without destroying large containers on the UI thread. Close may use one additional final slot, includes any pending canceled builder, and never joins submitted disposal callbacks. A failed thread-pool submission remains charged and is retried while the window is alive; at final teardown only an owner whose callback could not be submitted may be released inline. Submitted callbacks retain storage, a WIL-owned COM reference and the plugin-module pin until completion.

### Progressive Rendering
While scanning:
- treemap begins rendering immediately
- rectangles expand/settle as sizes are discovered
- an indeterminate progress indicator runs in the header (theme accent color; rainbow-aware)
- the header also shows:
  - line 1: path (left) and `Scanning…` / `Queued…` (right)
  - line 2: `N items (X folders, Y files)` (left) and `Processing: <folderName>` (right, no full path)
  - line 3: human-readable total size and raw bytes
- All numeric values (counts, percentages, bytes) follow Windows regional settings (digit grouping + decimal separator); the formatting locale is cached and invalidated on `WM_SETTINGCHANGE`.
- directories that are not yet complete show a small “incomplete” spinner
- large-enough incomplete tiles show a diagonal watermark:
  - while a scan is active: `In Progress`
  - if a scan ends before completion: `Scan Incomplete`
  - completed tiles show no watermark
- For very large incomplete tiles, the scan state is also shown as a second line under the folder name in the tile header (and the diagonal watermark is suppressed to avoid clutter).
- tiles in `Queued` / `NotStarted` / `Scanning` state are dimmed; tiles in `Scanning` state also show centered spinner overlays (current view root children; up to one spinner per scan worker actually running (the effective worker count, which for the Win32 provider can exceed the configured `scanThreads`), one per concurrently scanned subtree); if no eligible tile is visible/large enough, show a single fallback spinner centered in the treemap area (rainbow-aware, slower animation)
- When a scan completes (state transitions to `Done`), show a brief “Scan completed” toast/overlay in the treemap area.
- A folder that could not be read (for a reason other than access denied) keeps its own tile in the `Error` state, tinted with the theme's error colour, and the header status of a completed scan reads “Done (N folders could not be read)”.
- Tile colours derive from the item's and its parent's names, not from ids assigned in scan-completion order, so rescanning an unchanged tree produces the same colours.

### Interaction
- Tooltips appear after 120 ms of stable hover, including when the pointer stops moving. The existing animation timer completes that bounded wait against current hit geometry and the actual pointer over the viewer. On each timer tick, tooltip promotion and the idle-timer decision use the same captured timestamp so crossing the hover deadline between two clock reads cannot stop the timer before promotion. Mouse leave and ordinary model replacement cancel the candidate. An expired candidate under another window does not keep the idle timer running.
- Mouse: click a directory rectangle to drill down; click header Up to drill up. When the first click of a double click already drilled into a folder, the double click does nothing more (it never drills again into whatever tile the new layout places under the pointer).
- Right-click a treemap tile to open a context menu:
  - `Focus in pane`: navigate the active FolderView pane to the tile’s parent folder and focus the file/folder (when resolvable).
  - `Zoom in` / `Zoom out`
  - Standard FolderView file/folder commands (Open/Open With/Delete/Move/Rename/Copy/Paste/Properties), excluding `View Space` and debug-only items.
  - The popup surface MUST use the shared DxUI context-menu renderer so the menu matches the viewer theme/backdrop contract instead of falling back to a native `TrackPopupMenu` surface.
  - The shared host suffix is cloned from the FolderView **item** context
    resource. ViewerSpace never clones the background resource for a tile, and
    composition trims separators so no doubled or trailing separator appears.
  - Host resource and command IDs come from `Common/FolderViewMenuIds.h`; ViewerSpace MUST NOT duplicate numeric `138` / `3328x` literals. A new host context command therefore becomes an explicit shared-contract update instead of silently remaining enabled in the clone.
  - Cloned leaf commands follow ViewerSpace capability state. In particular, host Cut (`IDM_FOLDERVIEW_CONTEXT_CUT`) is gated with Copy and the other file-leaf actions and remains disabled while ViewerSpace disallows leaf dispatch.
- Up always goes to the structural parent of the folder in view, even when a click jumped several levels; it never returns to the previously viewed folder (that history is kept for Back/Forward). Up stays available during scanning; if the current scan root has no parent in the current model, Up restarts a scan at the parent path. Up is disabled when the scan root is already at a volume/share root.

## Memory and publication contracts

Provider validation decodes each structurally valid record into a compact offset. Nonowning name ordering and nonzero-ID ordering check duplicates with ordinal provider semantics and preserve error precedence for a valid prefix followed by malformed input. No accepted children are published before the whole listing validates. File names are copied only when a candidate enters or replaces an entry in the retention heap.

Validation scratch reservations total at most 32 MiB across workers and retired generations of one viewer. Active path reservations have a separate 32 MiB aggregate ceiling. Root paths charge their allocated `wstring` capacity plus the terminator; child paths are admitted using a conservative MSVC `wstring` capacity bound including reserve-rounding slack and the terminator, then constructed with one reserved buffer. These are path-storage reservations, not logical UTF-16 length totals. Rejected admission fails truthfully rather than wrapping or silently dropping counted data. These replace a promised combined 32 MiB proposal with two explicit envelopes. Each provider listing still has the existing 64 MiB used/allocated limit; aggregate provider occupancy is measured, not admission-limited.

Copied worker listing storage has a third, separate 32 MiB aggregate reservation across current and retired generations. Admission happens after whole-listing validation and before owning name copies. The allocation-free structural decode records directory/file counts, terminated directory-name bytes, and the largest terminated file-name byte length; the staging preflight then computes its reservation in constant time. With `D` directory records, `B` directory-name bytes including terminators, `K` the smaller of the file count and the per-directory candidate limit (zero for an aggregate-only directory), and `N` the largest file-name byte length including a terminator, the reservation is `64 KiB + 2*(B + (K+2)*N) + 512*(D+K+2)`. Validated provider extent and record/name ceilings bound this arithmetic. Discarded files are not charged as retained records, so a valid 100,000-file flat directory with a low configured top-K floor and bounded adaptive retention remains supported. The reservation conservatively covers name-capacity slack, simultaneous heap replacement, vector growth, child-job metadata and unposted summary-chunk descriptors. A worker retains the lease until all its staging and unposted arrays are destroyed or transferred. Available capacity is waited for with cancellation; a listing that individually exceeds the limit fails before partial candidate publication. These are conservative reservations, not measured allocations; queue transfers may overlap a reservation while their new owner is charged. Retained-refresh admission reserves headroom for all three envelopes. Provider allocations remain independently measured. `viewer.space.scan.worker_staging_preflight_us` is a per-scan aggregate: `DurationUs` is the maximum constant-time reservation-estimate preparation duration after validation, `Value0` is the completed-preflight count, and `Value1` is their summed duration. The record-shape walk is included in whole-listing validation and is not a separate preflight timer. Companion `viewer.space.scan.worker_staging_preflight_reservation_peak_bytes` and `viewer.space.scan.worker_staging_preflight_record_total` values report the maximum reservation and total validated records. These aggregates do not form a per-listing latency distribution.

Scanner frontier blocks and completion-map nodes/buckets use a separate counting PMR resource. Its instance-owned atomic current/peak counters include simultaneous retired generations until their containers are destroyed, are included in `viewerOwnedBytes`, and emit `viewer.space.scan.bookkeeping_peak_bytes`. This is actual requested allocation capacity, excluding allocator metadata. The existing outstanding-directory limit bounds record count; this counter is observation/admission input rather than a separate hard byte cap.

Zero-byte files and empty folders remain selectable in the analysis table, but receive no fabricated byte area in the treemap.

Directory file-summary publication is a generation/node/revision/sequence-qualified Begin → Chunk → End transaction. Ordinary chunks use at most 64 KiB; a single valid maximum-name item may use the explicit 128 KiB exception. Staging owns unreferenced records and a replacement child span, and copies predecessor references in resumable turns. End commits exactly once after all chunks and copying complete. Missing, duplicate, reordered or stale packets cannot expose a partial candidate set or allow root Done. Cancel discards uncommitted storage. Queue backpressure remains byte-based (8 MiB high-water / 4 MiB resume). Draining pauses while the displayed model is borrowed by layout or analysis preparation; bounded queue admission remains active. Cache restore exposes neither new geometry nor analytical rows until validation and coherent restoration complete.

Cache restore validates parent identity, referenced-child ownership, duplicate references and completeness in resumable turns. Active directory parents precede their children in the scanner's monotonic ID order, preventing cycles. Every active node except the root and every active file has exactly one incoming child reference; inactive records are all-zero tombstones. The sentinel and root have no incoming references. Its policy-bounded seen bitmap is charged by capacity and released on cancel/adoption. Invalid topology discards the source snapshot and returns to a real scan.

Scan-cache snapshots use fixed records and one UTF-16 blob with validated offsets/extents. Cache preflight, source copy and adoption preparation remain cooperative UI-timer work with their existing phase-local checkpoints and validation/adoption rules. Specifically, `ContinueScanCacheRestore` has a 1.2 ms per-invocation time budget: after a bounded restore phase completes, the same invocation may enter the next finite restore phase only while that original budget remains, then yields to the timer. This is not an end-to-end 1.2 ms bound on preflight, source copying or commit. The finite phase set has a bounded transition count, including a fail-closed path for `None` or an out-of-range phase. `ENABLE_TESTS` builds may set the strictly parsed positive decimal `REDSALAMANDER_VIEWERSPACE_TEST_CACHE_RESTORE_PHASES_PER_TURN`; zero, invalid or unset values use ordinary budgeted batching, and positive values cap completed phases per turn. This test-only cap does not change production behavior. Generation/state validation, source pins, reservation/source-fit checks, cancellation and corruption handling remain in force; no geometry or analysis is published until the complete snapshot has been validated, coherently restored and committed. When performance capture is enabled, `viewer.space.model.cache_restore_turn_us` reports per-invocation elapsed microseconds (`durationUs`), completed restore phases including terminal `Files` when committed (`value0`), and resulting phase (`value1`); bounded detail identifies the outcome. `S_OK` denotes yield or completion, `E_ABORT` stale-generation/state rejection, and `E_FAIL` invalid-snapshot/phase fallback. `viewer.space.model.cache_restore_batched_turn` is emitted only when one invocation completes multiple phases. No added timer read or per-turn emission occurs when capture is disabled. The process-wide cache has a 64 MiB aggregate byte cap plus configured entry count and TTL. Pinned restore sources cannot be evicted; admission declines a new entry when pins prevent fitting. Snapshot bytes include allocated capacities and keys. Live model PMR accounting measures upstream allocations, including arena spare capacity; derived arrays/indexes, queue, scan reservations and deferred disposal are charged separately without counting one owner twice. This ledger supports admission and diagnostics, not a claim about all process allocations.

Builds with `ENABLE_TESTS` (Debug and test-enabled Release) expose `WndMsg::kViewerSpaceDebugGetPerfSnapshot` for deterministic command selftests. The snapshot reports renderer mode, scan state, retained directory/file/synthetic counts, root/file-candidate/synthetic byte totals, exact aggregated bytes/folder/file counts, scan counts, child references and arena/free slots, active production/test limits, provider validation status, accepted/rejected/capped entries, retained-name bytes, traversed directories, the effective adaptive file-candidate budget used for the live scan and scan-cache key, pending queue count/bytes, inner-lock generation rejections, draw/visible/cull counts, last tile/text draw counts, renderer create/resize/brush/text-format counters, swap-chain pixel dimensions, last renderer failure stage/HRESULT, layout generation, static render-cache counters/bytes, scan-cache snapshot bytes, layout candidate-cache counters, hit-grid cell/candidate counts, recent paint/layout/drain/hit-test timings, and a working-set sample. Model aggregation is stored on retained parent nodes and materialized as deterministic layout-only “Other” tiles; it is not counted as an additional retained node. `WndMsg::kViewerSpaceDebugCompareHitTesting` samples visible tile centers and compares spatial-grid results with the reverse-linear fallback. `WndMsg::kViewerSpaceDebugForceRendererFault` is a test-only fault-injection hook for forcing the next render through the device-loss recovery path. `WndMsg::kViewerSpaceDebugPauseNextPostUpdate` pauses one producer after its fast generation check so a test can invalidate/clear before the inner queue-lock check and prove the stale update is rejected. The snapshot's `lastLButtonDownHitNodeId` names the tile the last `WM_LBUTTONDOWN` hit (0 for the header strip or no tile), and `WndMsg::kViewerSpaceDebugGetDrawItem` returns one draw item by layout-order index (node, depth, directory/synthetic flags, header-strip height, painted and target rectangles, viewer DPI and header bottom) so pointer tests can report the geometry their probes met.

## Threading and Cancellation

The separate opt-in `cmd_viewer_space_memory_heavy_four_root_retained_reference_optin` is a controlled same-IViewer comparison. Both revisions create and configure one public COM owner once, then call Open/Close for the same four 100,000-file/501-directory roots with top-K 512, eight scan workers, four cache entries, the original deadlines and candidate admission allowance. Six rows per root distinguish loaded, cached, in-flight F5, completed F5, and the two closed-HWND/retained-object states; a twenty-fifth row records final owner release. Completed rows require equal corpus digests, totals, detail and four cache hits. The baseline's in-flight model may be empty; that row records its actual state and cannot stand in for a completed-detail witness. This fixture does not modify either algorithm or replace the original fresh-instance opt-in. Reports must label the controlled lifecycle explicitly and retain failed historical evidence; they must not claim qualification of historical fresh-instance S0 from this cohort.

A cached generation may use exactly one existing budgeted restoration turn during its first paint, before renderer preparation. A per-restore latch prevents subsequent paints from adding work. After that paint, it may queue one additional generation-qualified restore continuation using the canonical posted-payload registry. The HWND has at most one pending continuation, including a canceled generation until dispatch or teardown drain. A successful post registers a payload containing the `uint32_t` generation and carries an opaque registry token in `LPARAM`. The admission ledger charges the four payload bytes while pending or executing, including while the generation is canceled but its token remains queued; registry and allocator overhead are outside this logical payload estimate. Once adopted, a valid helper-owned payload releases its own charge at handler exit even when its generation is stale; stale work performs no restore. A null result from `TakeMessagePayload` (null, drained, or type-mismatched token) returns before changing pending state or the admission ledger. Posting refusal/failure retains ordinary timer progress. The continuation never self-posts; later work keeps the existing 16-ms timer and 1.2-ms invocation budget. Root HWND creation initializes the payload registry, and NCDESTROY drains it before releasing window ownership. Cancellation, invalid-source fallback, and a new generation reset the per-restore attempt latch. Publication remains blocked until complete validation and coherent restore. The sliced-restore selftest forces two consecutive paints before pumping, verifies one paint turn and one queued message without partial projection, then cancels with F5 and dispatches the stale message; the stale handler performs no restore or turn-state change while releasing its valid old payload charge. A close-before-dispatch case delivers the drained opaque token to a newly owned HWND after that HWND has queued its own continuation, then verifies its ledger, restore phase and turn count remain unchanged. Both replacement scans retain exact corpus counts and the original settlement guards.

Generation-owned contiguous node, file-record, and child-reference vectors allocate directly from the counted upstream memory resource. Replaced vector buffers return to that resource immediately; a default pool must not retain their large geometric-growth size classes until generation teardown. Name arenas retain their existing generation lifetime. The retained-refresh admission allowance remains 80 MiB. Cancellation and mid-refresh refusal preserve the displayed model, draw items, and current presented layout generation; the regression observes refusal after the candidate was initially admitted.

- Folder scanning runs on background threads with cooperative cancellation (`std::stop_token`); `scanThreads` controls the in-process parallelism for a single ViewerSpace scan.
- Concurrency model: workers pull directories from a bounded shared frontier. Each enumerated directory appends validated child directories back to the frontier and completion state propagates saturating child byte/folder/file totals to parents so accepted scans remain exact. Completed traversal records are erased immediately; admission counts the complete live completion map (including ancestors and siblings), and both outstanding directory count and path bytes are capped. Directory/file/name/child-reference reservations and `AddChild` publication occur only after depth, path, traversal, and outstanding admission succeeds. Admission and bookkeeping run under the frontier lock, but a directory's model records are posted only after that lock is released (queue backpressure may sleep, and a throttled worker MUST NOT stall the others on the frontier lock); its child jobs become visible in the frontier only after those records, including every `AddChild`, are queued. Same-generation directory-size publication is monotonic: a delayed sibling packet MUST NOT reduce a newer parent total or a completed node. Root completion MUST enqueue one authoritative final progress record containing the complete byte/folder/file counters before publishing root `Done`; once `Done` is observable, the debug/performance snapshot totals and scan counts are final for that generation.
- Before a positive scan-byte total is observed, one first child from a newly published directory may be inserted at the front of the existing frontier. At most 16 such insertions are admitted per scan generation under the frontier lock; the remaining siblings keep FIFO insertion order. Once the sampled atomic byte total is positive or the cap is consumed, all subsequent insertions use FIFO. A concurrently running worker may publish bytes just after the sample; this is an observation-time admission policy, not a cross-worker barrier. Child admission, memory/path accounting, completion, and posting every AddChild before frontier visibility are unchanged. There is no second queue or unbounded depth-first path.
- UI updates are queued and periodically drained to avoid message storms. Repeated size/progress records are coalesced before drain when a newer record supersedes an older pending one; size application preserves the greatest same-generation total rather than trusting producer arrival order. The UI thread swaps a bounded batch out of the producer queue under one short lock, processes outside the lock, and applies measured backpressure from pending bytes rather than raw queue count. `PostUpdate` MUST validate the scan generation both before taking the queue lock and again while holding it; generation invalidation plus queue clearing therefore cannot race with a stale producer enqueue. Future queue representation changes must preserve the same generation checks, cancellation behavior, and `viewer.space.queue.*` metrics.
- Window close and `WM_DESTROY` MUST NOT wait for a scan worker or provider call. Teardown first invalidates the scan generation, marks scanning inactive, requests cooperative stop on every current/retired worker, then joins only workers whose completion flag is already published. A worker blocked in the untrusted `ReadDirectoryInfo` boundary is detached as the narrow documented exception to the plugin detached-thread ban. Each outer scan worker owns exactly one exception-safe `ViewerSpace` COM self-reference until all scan work and captured provider state have retired; `WM_DESTROY` releases UI-owned Direct2D/DirectWrite, filesystem, and host COM state before the window reference can disappear.
- Every created scan owns one module-global unload gate. A completion-signaled worker releases that gate only after the UI has joined it, so `RedSalamanderPluginCanUnloadNow` cannot report a return-in-progress worker as safe. If an uncooperative provider forces detach, the gate is intentionally retained for the rest of the process: runtime same-path reload is quarantined and the host leaves the DLL/resource owner mapped. `RedSalamanderPluginRetainModuleUntilProcessExit` separately covers orderly process teardown. A detached worker must never rely on that process-shutdown-only export for runtime refresh safety.
- The scan scheduler is shared-owned across acquisition and scan lifetime. Plugin module-state shutdown permanently closes both the global scheduler factory and the scheduler instance before waking waiters; delayed workers cannot recreate module-global scheduler state or acquire a new permit after the quiet point. Storage already owned by an abandoned worker remains valid until that worker releases it.
- Update draining and layout rebuild run on the viewer timer with a small time budget to keep `WM_PAINT` mostly render-only (responsive move/resize while scanning).
- When multiple ViewerSpace windows scan the same volume on the Win32 filesystem (`shortId == "file"`), scans are throttled via a per-volume concurrency limit (`maxConcurrentScansPerVolume`) regardless of `scanThreads`. For non-Win32 filesystems, throttling is per-filesystem-instance to avoid unrelated viewers blocking each other.
- A short-lived in-memory scan cache may be used to reuse recent results for the same root (configurable). To avoid collisions across mounts, ViewerSpace currently only uses the cache for the Win32 filesystem (`shortId == "file"`). Large snapshots are skipped when the estimated snapshot exceeds the scan-cache byte cap and must emit `viewer.space.model.cache_skipped_large`. The cache keeps one entry per root. An entry retained with at least the currently requested file-candidate budget is reusable (the budget follows the window area, so a resize does not miss). A hit restores the scan's byte, folder, file and unreadable-folder counts for the header.
- Scans are canceled when:
  - viewer closes
  - user refreshes
  - a new scan starts
  - user presses **Cancel** during scanning
  - user presses `Esc` while scanning

## Traversal Rules

- Uses `IFileSystem::ReadDirectoryInfo()` to enumerate entries and compute sizes (works for any active filesystem plugin, not only Win32 paths).
- Reparse-point directories remain visible as zero-sized directory nodes but are never descended, including when the provider maps the reparse path back to an ancestor.
- Access-denied paths contribute zero accepted logical bytes and do not abort the scan. They and their ancestors carry Contents not measured, so zero is never presented as proof of an empty/readable folder. This state survives cache storage/restoration and is shown in analysis, inspector and tooltip.
- Publish a retained folder's Scanning state before calling its provider's `ReadDirectoryInfo`, so a delayed read is visibly active rather than left Queued. The deterministic partial-scan capture holds that read, verifies its Scanning row, exact observed counters/bytes, and a successfully presented current partial map before taking the frame.
- A folder whose listing fails for any other reason is an `Error` in its own subtree only: its ancestors and the root still complete as `Done`, the scanner counts such folders on its progress records, and a completed root with such folders is cacheable. A scan root that cannot be read still ends the scan in `Error`. Malformed provider buffers and the scan-wide ceilings below remain whole-scan errors. When a capped (aggregated) subtree fails, its partial totals still go to its owner's “Other” bucket, so a parent's total always equals its tiles plus “Other”.
- Child path construction is string-based: `childPath = parentPath + separator + entryName` (no `std::filesystem` normalization). Separator selection prefers the style already present in the root path; otherwise it defaults to `\` for Win32 paths and `/` for non-Win32 paths.
- Provider buffers are untrusted ABI input. ViewerSpace validates both used and advertised allocated bytes, reconciles `GetCount()` with the exact terminal record extent, requires aligned/forward/in-range record strides, and bounds names and per-folder counts before model/resource mutation. It rejects dot/separator/NUL/control path components, duplicate nonzero provider ids within one listing, and duplicate logical names (ordinal case-insensitive for the Win32 provider). `FileInfo::FileIndex` is not a tree-wide identity. The plugin ABI defines it only as a file-system-specific index: MTP and Google Drive report each entry's position in its listing, and the Win32 provider reports a directory byte offset on FAT volumes. A nested folder may therefore repeat an ancestor's value, and ViewerSpace never compares ids across folders. Zero `FileIndex` means no id. Cycles are bounded without ids. Strict leaf-name construction rejects `..`-style self references, and reparse directories are never descended. A provider alias loop that is not marked as a reparse point stops at the traversal-depth ceiling or at the traversed- or outstanding-directory cap. Content reached through such an alias counts once per path until a ceiling stops the walk; the scan then ends in Error with that limit recorded. `ValidationError::AncestorCycle` is retired and never reported; it keeps its value so later validation errors keep their numbers. Access-denied directories are normal visible zero-sized leaves and do not count as provider-validation failures.
- Production resource limits are: 100,000 retained directories, 200,000 retained file records, 300,000 child references, 1,200,000 child-arena slots, 64 MiB retained names, 64 MiB used or advertised allocated provider buffer per folder, 500,000 entries per folder, 32 KiB per provider name, depth 512, 5,000,000 admitted/traversed directories, 100,000 outstanding directories, 64 MiB outstanding path text, and 32,767 path characters. These are safety ceilings, not configuration knobs. The arena ceiling is four times the child-reference ceiling so geometric live blocks and all predecessor blocks remain representable for every allowed child shape; tail blocks grow in place when possible. Reaching a provider/traversal/depth/outstanding cap terminates with a deterministic error; counters and bytes saturate instead of wrapping.
- To control itemization memory, ViewerSpace stores retained directories as real nodes and retained files in a compact file-record arena with packed item ids. `topFilesPerDirectory` remains a compatibility floor while the adaptive policy derives a larger per-directory candidate budget, but the global resource policy is authoritative. Once a valid subtree cannot be retained, scanning continues below it without allocating model nodes; its complete saturating byte/folder/file totals roll into the nearest retained ancestor and render as one exact “Other” bucket. The active model therefore stays bounded without falsifying accepted-scan totals.
- Child lists use reusable arena blocks. Growth copies live child ids to a larger block, immediately returns the prior block to a coalescing best-fit free list, reuses holes for later nodes, and trims free tail blocks; stable node/file ids remain unchanged and old growth capacity is not stranded until scan teardown.
- Treemap item ids distinguish real directory nodes, compact file records, and synthetic “Other” buckets. Tooltip, path building, context menu dispatch, drill-down, and hit testing MUST resolve through that item identity instead of assuming every tile is a `Node`.
- Layout-only “Other” buckets use deterministic synthetic ids derived from the parent and combine exact scan-time aggregation with any additional layout-only culling. Double-clicking an “Other” bucket increases that parent’s layout detail budget and, if needed, navigates to the parent so the user can explore the dense group.
