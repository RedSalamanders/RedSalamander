# Themes

RedSalamander applies one theme across the main window, folder panes, navigation bars, menus, file operations, dialogs, viewers, and RedSalamanderMonitor.

![Themes in Preferences](res/preferences-themes.png)

## Theme choices

Use **View → Theme** for quick switching or **Preferences → Themes** to select, preview, duplicate, import, and export themes.

Built-in choices are System, Light, Dark, Rainbow, and High Contrast App. Rainbow follows the current Windows light/dark preference and uses stable item identities for repeatable multicolor selections; it does not change randomly between paints. Windows Contrast Themes always take precedence over the selected application theme.

The distribution also includes these editable version 2 theme files:

- Forest Mist
- Neon Tokyo
- Paper & Ink
- Retro Terminal
- Solar Flare
- Ugly
- Dracula
- Catppuccin Latte
- Catppuccin Frappé
- Catppuccin Mocha

Dracula and Catppuccin are distributed with their exact upstream license texts and pinned source information in the [third-party theme notices](../Specs/Themes/THIRD-PARTY-NOTICES.md). Catppuccin uses Lavender for active/focus accents, Blue for links/actions, and Overlay2 blended over Base for selection fills; Mauve remains available in the palette but is not forced as the global accent.

## Preferences and RedConfigure

**Preferences → Themes** supports normal runtime management:

- Select built-in, file-based, or user themes.
- Duplicate a theme before editing a read-only built-in or shipped theme.
- Edit authored palette entries and semantic color sources without flattening references or functions.
- Preview changes with **Apply Temporarily**; **Cancel** restores the previously applied theme.
- Load and save `*.theme.json5` files in the same version 2 format used at runtime.

Use `RedConfigure.exe` for advanced authoring. Its Themes workbench exposes palette creation/rename/delete, import/duplicate/reset, reference rewriting, dependency and affected-token inspection, source/use/contrast metadata, scene filters, recent/copied colors, alpha and group recipes, fixed runtime preview seeds, two-step before/after batch review, and focused previews for dynamic and perceptual functions. Review & Export blocks invalid graphs/paths, preserves grouped authored JSON5, writes atomically, and reparses the result before reporting success.

## Version 2 theme files

Theme files live in `Themes\*.theme.json5` next to `RedSalamander.exe`. Shipped source themes live in `Specs/Themes/`. Every standalone, imported, exported, shipped, or inline user theme must use `formatVersion: 2`; version 1 and missing-version files are rejected.

```json5
{
  "formatVersion": 2,
  "id": "user/example",
  "name": "Example",
  "baseThemeId": "builtin/dark",
  "palette": {
    "background": "#1E1E1E",
    "foreground": "#D4D4D4",
    "accent": "systemAccent()",
    "selection": "blend(palette.background,palette.accent,25%)",
  },
  "colors": {
    "app.accent": "ref(palette.accent)",
    "window.background": "ref(palette.background)",
    "menu.text": "ref(palette.foreground)",
    "folderView.itemBackgroundSelected": "ref(palette.selection)",
  },
}
```

`palette` gives reusable names to literals and derived colors. `colors` maps those authored sources to application semantic keys. Expressions are intentionally non-nested: name an intermediate palette value instead of building a difficult-to-edit expression tree.

Supported functions are:

- Reuse and simple transforms: `ref`, `lighten`, `darken`, `alpha`, `blend`, and `contrast`.
- Perceptual/accessibility transforms: `perceptualTone`, `ensureContrast`, and `harmonize`.
- System and light/dark sources: `systemAccent`, `systemColor`, and `tone`.
- Stable runtime variation: `seededRainbow` and `seededChoice` on explicitly supported semantic keys.

Amounts accept decimals from `0.0` to `1.0` or percentages. Runtime functions use stable seeds, are compiled when the theme is resolved, and do not parse or allocate while painting. High Contrast overrides all authored and Rainbow output.

Theme files are formatted with the camelCase spellings shown above; input parsing remains case-insensitive for
compatibility. `ensureContrast(foreground,background,ratio)` measures the rendered foreground composite. Its
background must be opaque, and the foreground's authored alpha is retained only when that alpha can attain the
requested ratio. Otherwise the expression is invalid instead of reporting contrast that users will not actually
see.

## Loading and recovery

- Themes in the settings file are user themes and take precedence over a disk theme with the same ID.
- Inline theme IDs are case-sensitive. The first exact ID is active; later exact duplicates and structurally invalid
  array entries are retained in their authored positions as opaque repair data so a canonical save does not destroy
  them.
- Standalone theme files are strict: malformed expressions, missing references, cycles, unsupported dynamic targets, and invalid versions reject that file.
- A failed settings hot reload keeps the last valid live theme rather than partially applying a broken graph.
- `builtin/rainbow` can be used as a base. A static override replaces Rainbow only for that semantic token; the rest of the inherited Rainbow behavior remains active.

The complete format, limits, semantic-key catalog, and evaluation rules are defined in `Specs/Core/Core_SettingsStore.md`.
